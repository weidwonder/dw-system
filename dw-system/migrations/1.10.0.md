# 升级到 1.10.0（自 1.9.0）

## 结论

**安装器现在把 skill 自带的 `ctx` CLI 链接成全局 `ctx` 命令。** 此前 `ctx` 只随 skill 复制进项目，从不进 PATH，而 skill 文档（`mode-team.md`、`SKILL.md`、注入到 `CLAUDE.md` 的团队版片段）通篇写 `ctx <命令>`——`which ctx` 为空时，使用者（尤其是 AI agent）很容易误判成"Engineering Context 不可用"，退化成裸 grep 旧代码，正是团队版明令禁止的行为。

本版起每次安装：

- 在 `<项目>/.claude/skills/ai-dev-workflow/scripts/ctx` 下执行 `npm link`，随后**实跑 `ctx --help` 验证**才报成功（link 退出码为 0 不代表命令真的在 PATH 上）。
- PATH 上已存在**别人的**同名 `ctx` 命令时**不做链接**，不顶掉用户自己的工具。
- 链接失败、命令仍不在 PATH、被同名命令抢占——三种情况都只降级为警告，并打印兜底调用方式 `node <skill>/scripts/ctx/src/cli.js <命令>`（功能完全相同）。skill 安装不受影响。
- 新增 `--no-ctx-link` 整段跳过。

团队版注入片段（`CLAUDE.md` / `AGENTS.md` 的 `ai-dev-workflow` 标记块）同步补了一句：`ctx` 命令找不到时改用 `node .claude/skills/ai-dev-workflow/scripts/ctx/src/cli.js <命令>`，**不是**退回 grep。重跑安装器会幂等刷新该标记块。

流程、模板、文档目录约定均无变化。

## 需要的动作

- **一般情况**：无。重跑安装器即可，装完终端里直接 `ctx list-services` 就能用（新开的终端才会带上 PATH 变更时请重开一次）。
- **看到"npm link 跑通了，但 PATH 上仍找不到 ctx"**：把 `npm prefix -g` 目录下的 `bin` 加进 PATH 后重开终端，再重跑安装器；在此之前用打印出来的 `node <skill>/scripts/ctx/src/cli.js <命令>` 调用，功能相同。
- **本机已有别的 `ctx` 命令**：安装器不会覆盖它，按提示用兜底调用方式，或自行给本体系的 ctx 起个别名。
- **不想要全局命令**：加 `--no-ctx-link` 重跑；已链接的用 `npm rm -g ctx` 自行移除（安装器不代劳卸载）。
- **注意来源目录**：全局 `ctx` 指向的是**最后一次安装的那个项目**里的副本。删掉该项目后全局命令会失效，重跑一次安装器即可恢复。ctx 按当前工作目录找 `engineering-context/`，所以一份全局命令服务所有项目。
