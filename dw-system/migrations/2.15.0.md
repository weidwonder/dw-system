# 2.15.0 迁移指南：评审轴改为按开发对象面推导

## 需要的动作

1. **重跑一次安装器**（`npx --yes github:weidwonder/ai-dev-system <你的项目>`）。它会装上新增的伴生 skill `skill-principle`，并把两个 skill 的判据文件更新到本版本。
2. **如果你的脚本或 CI 里用了 `--agentic-repo=<url>`**：改成 `--companion-repo=agentic-principle=<url>`。**旧参数已删除，不留别名**——继续传会以"未知选项"非零退出。
3. 其余无需动作：标记块字段没变，存量 spec / plan / 文档都不用回填。

## 变了什么

**代码评审门的轴集合不再是固定的四条。** 改为先判本次改动触碰的**对象面**，再由面推出轴集合：

| 对象面 | 怎么判（看改动范围的文件名） | 带来哪些轴 |
|---|---|---|
| **P** 程序代码面 | 范围里有可执行代码文件（skill 自带的 CLI 也算） | 规范 / 忠实 / 残留 / 文档 |
| **K** skill 文档面 | 范围里有 markdown，且其所在目录或祖先目录含 `SKILL.md` | **skill 原则轴**（新增，加载 `skill-principle`）|
| **G** agent 架构面 | 触碰 Agent 系统设计面（判据沿用 AI-LLM-overlay）| agent 架构轴（加载 `agentic-principle`）|

多个面同时命中时取并集。三处随之而来的变化：

- **纯 skill 改动（范围里没有代码文件）只跑 skill 原则轴一个子代理**，忠实轴与残留轴不再跑——它们对照的是 spec 的需求编号与替换清单，而这类改动已不写 spec（见下条）。
- **纯 skill 改动跳过 spec 与 coding plan**：PRD 即 spec。跳过的是产物不是门，兼容取舍确认门与 spec 过稿门照旧，结论落在 PRD 或改动清单里。
- **评审子代理的模型档位默认降到普通档**，仅在该轴上一轮报过 P0、命中大架构确认门、或你显式要求时才升高档（**改动规模不再是升档依据**——跨几个边界、多少条需求都是数量信号不是难度信号）。**harness 有多档时不得派最低档**（评审是判断题，最低档只会复述改动）。

## 会不会影响正在进行的工作

不会。轴的职责、返回格式、P0/P1 口径、五道门的位置与顺序都没变。变的只是"这次派哪几条轴、派什么档位的模型"。
