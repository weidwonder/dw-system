# 升级到 2.1.0（自 2.0.0）

## 结论

**"这个项目要不要建代码事实资产"这道选择题取消了。** 装了本体系的项目一律维护 `engineering-context/` 卡片层（能力登记表 + 每个仓库一张事实卡），不分项目大小、不分人数、没有开关。

2.0.0 是按项目现有资产分档的：登记表里没有真实数据，就判定"这个项目还没有资产"，于是允许直接读旧代码、默认走最短流程，卡片靠"攒够返工信号才建议你补"。问题是**分档的判据永远慢一步**——一个人维护的十万行遗留系统恰恰一张卡片都没有，于是被判成"没有资产，直接 grep 吧"，而那正是这套体系最初要消灭的事故来源。

新规矩只有一句：**要用某个模块的事实，先查卡片；没有卡片就读源码，读完当场把卡片补上。**

## 需要的动作

**什么都不用做。** 重跑一次安装器升级 skill 即可，不需要手工建任何目录、不需要回答任何新问题。

- **下次唤起 skill 时**，如果项目里还没有 `engineering-context/`，会自动建好骨架（跟随本次任务分支提交，可评审、可回退）。骨架里只有模板占位、没有真实内容，**这是正常起步状态**，不会有人为此告警。
- **卡片在干活过程中边用边补**：碰到还没有卡片的模块，AI 会读源码把事实核实清楚，再把这张卡片写上（职责 / 对外接口带文件行号 / 相似但不该用的旧实现 / 确认日期），随本次改动一起提交。
- **本来就在用 `engineering-context/` 的项目**：无任何变化，只是"要不要用"不再是个问题。

## 代价（说在明处）

在既有代码库上，**前几次任务会慢一点**：碰到没有卡片的模块要多花时间读代码、写卡片。之后越来越快——同一块代码不会被反复重读，改错非权威实现的事故也随之减少。

## 其它变化

- **分流不再看资产**：一次改动走一页 Lean 还是升级到完整流程，只看**影响面说不说得清**，与项目有没有卡片、有几个人开发都无关。"卡片里查不到"本身不算说不清——读完源码补上卡片就有出处了。
- **项目里若有 `docs/report/资产补建信号.md`**：本体系不再读它、也不再写它，可以自行删除；留着也不影响任何流程。
- 流程十步、四道门、文档目录约定（`docs/spec|plan|report`）、模板、`ctx` 命令与参数均无变化，存量文档不需要回改。
