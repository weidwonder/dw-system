# 3.0.0 迁移指南：体系更名为 dw-system，单体 skill 拆成八个

## 结论

重跑一次安装器即可，旧版留下的东西由它自动清理；标记块里你配过的三个字段原样保留。

## 需要的动作

1. **在项目根重跑安装命令**：`npx --yes git+https://github.com/weidwonder/dw-system.git .`（仓库已更名；旧地址由 GitHub 跳转，建议改用新地址）。安装器会：删除 `.claude/skills/` 与 `.agents/skills/` 下的 `ai-dev-workflow`、`ai-prd` 与旧版本戳；把 `CLAUDE.md` / `AGENTS.md` 里的 `<!-- ai-dev-workflow:… -->` 块改写成 `<!-- dw-workflow:… -->`，`collaboration` / `merge-gate` / `worktree-dir` 逐字带入；同样改写 Codex 约束块与 `.gitignore` 块，`docs/` 是否入库的决定沿用、不再询问；把全局 `ctx` 重链到 `dw-code-facts`。先加 `--dry-run` 可只看计划。多人协作的项目，skill 目录默认不入库，**每个人都要在自己的检出里重跑一次**。用本地检出里的安装器安装的，先 `git pull` 更新检出再跑，或改用上面的安装命令：2.x 的安装器装不了 3.0 的源。
2. **脚本、CI 或文档里写死了旧 skill 名或旧路径的**，改成新名字：`ai-dev-workflow` → `dw-workflow`，`ai-prd` → `dw-prd`；`ctx` 的兜底路径改为 `<skills 目录>/dw-code-facts/scripts/ctx/src/cli.js`。
3. **标记块只有旧 `mode`、没有 `collaboration` 的项目**：安装器据 `mode` 推断协作面与合并方式并打印推断结果，不对就改标记块里的字段后再跑一次。
4. **存量卡片**：在项目根跑一次 `ctx lint-cards --init-baseline`，把现有违规记为基线（基线文件入库）。之后新违规判红，存量只许减不许增；碰到哪个业务域，就把哪个域从单文件卡搬成域卡。

## 行为变化知会

- **skill 从两个变成八个**：`dw-workflow` 只留总纲、分流、步骤顺序与确认门；评审门、文档治理、代码事实层、bug 诊断、worktree 两道门、文字写法各自成 skill，流程走到那一步才加载。五道门与七条不裁剪护栏的判据没变，只换了住处。
- **两条总纲**：一个事实只有一个家，别处只放链接；规范文本有体积上限，超限先搬走、再压缩、最后才抬上限。评审门的文档轴与 skill 原则轴会把"同一事实两处展开"报为问题。
- **Lean 路径不再有自足册**：改读一页步骤顺序，每一步的判据在对应 skill 里。
- **注入进 `CLAUDE.md` / `AGENTS.md` 的标记块缩到原来的三分之一**：只留常驻规则与指针。标记块不再写 `mode`。
- **卡片按业务域分**：每仓一张地图卡 `cards/<repo>.md`，每个业务域一张域卡 `cards/<repo>/<域>.md`，小节名固定、只写现状；cite 以 `路径#符号` 为主。`ctx get-card <repo> <域>` 用法不变，没有域卡文件时照旧读单文件里的同名小节。
- **`ctx` 新增**：`lint-cards`（卡片体检）、probe 题型 `authority-unique`（两份现行文档不得声明同一权威面）。其余命令用法不变，输出只增字段：`discover` / `search-semantic` 的结果多 `domain`，`list-services` 多 `domains`。
- **新 skill `dw-prose`**：写或精简规范文本、注释、卡片、提示词时用——删改前保住每条命题，只写现状，来历进 `docs/decisions/`。
