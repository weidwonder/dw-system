# 升级到 2.4.0（自 2.3.0）

## 结论

**安装器的默认安装版本从 `main` 分支改成"安装器自带 VERSION 对应的 tag"。** 你手里这份 install.mjs 是哪个版本，默认就装哪个版本的 skill——包版本与技能源版本从此绑定，不再各走各的。

此前默认拉 `main`：用一份很旧的 npx 缓存包，也会装到 main 最新的技能内容；反过来，刚合入 main 但还没发版的改动，也会被当成正式版装进项目。装到的东西与写进目标项目的版本 stamp 对不上，出问题时无从复现是哪一份。

为此 `ai-dev-system/VERSION` 现在会**随 npm 包一起分发**（`package.json` 的 `files` 多了这一条），安装器据此读出自己的版本号。

## 需要的动作

**什么都不用做。** 重跑一次安装器即可，没有新配置、没有新问题要回答。

要装某个特定版本仍然是 `--ref=<tag>`；要跟随开发分支就显式传 `--ref=main`。

## 其它变化

- **显式传了 `--ref` 就绝不回退**：指定的分支或 tag 取不到时直接报错退出（非零退出码），不会悄悄换成别的版本装进项目。
- **默认 tag 尚未发布时会告警并回退到 `main`**：VERSION 已 bump、tag 还没推的窗口期里，安装器打印一行明确告警再回退，不静默。
- **`README` 推荐的 npx 命令换成 `git+https://…#<tag>` 形式**：`npx github:owner/repo` 这种 shorthand 走 GitHub 的 codeload tarball，部分环境（已知 Windows + npm 12）会拿到 404；`git+https://` 形式走 git clone，绕开该路径。
- 十步流程、四道门、Triage 判据、文档目录约定、模板与 `ctx` 命令均无变化，skill 内容本身这一版没有改动。
