# 升级到 1.7.1（自 1.7.0）

## 结论

**`CLAUDE.md` / `AGENTS.md` 是软链接时，写入落到链接目标，链接本身保留。** 很多项目把 `AGENTS.md` 软链接到 `CLAUDE.md`（或让两者都链到仓库外的共用文件），让 Claude Code 与 Codex 共用一份指导文件。本版起：

- 安装器把 mode 标记块与 Codex 约束块写进链接**指向的实体文件**，按标记块判断更新还是追加，不动链接本身；两个入口指向同一文件时只写一次，不再注入两遍。
- 链接断开（目标所在目录不存在）时，安装器在**复制任何 skill 之前**就报错退出，目标项目零改动；旧版本会写到一半才抛 `ENOENT`。
- 全局卸载 Codex 冲突插件时，不再删除作为入口的软链接，也不删它指向的共用文件。
- skill 首次初始化写入这两个文件时遵循同一套规则（见 `references/init-初始化.md` §入口是软链接时）；断链时会停下来问你，不会新建实体文件把链接顶掉。

流程、模板、目录约定均无变化。

## 需要的动作

- **无需任何动作**：重跑安装器即可。既有的普通文件安装行为完全不变。
- 若你此前因为这个问题被写坏过入口（软链接变成了普通文件），可自行恢复软链接后重跑安装器验证——两个入口指向同一文件时，输出会明确写成 `AGENTS.md → CLAUDE.md（软链接目标）`。
