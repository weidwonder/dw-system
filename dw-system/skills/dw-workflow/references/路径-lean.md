# Lean 路径（一页步骤顺序）

> Triage 的判定问题全否、且 `00-流程总纲.md` §默认倾向 未把本次上调到完整流程时读。本页只定**顺序**与 Lean 特有的几条；每一步的判据住在它自己的家，到那一步才去读，MUST NOT 提前预读，也 MUST NOT 凭本页的一句话推断判据。
> Lean 的轻量体现在"文档只有一页、跳过 Step 1–10"，**不体现在跳过门**——`00-流程总纲.md` 门全景表里的门一道也不豁免，§"不裁剪"护栏 一条也不豁免。按 RFC 2119 解释规范词。

## 顺序

| # | 动作 | 产出 / 完成标志 | 判据在哪 |
|---|---|---|---|
| 1 | **工作区隔离门** | 独立 worktree；初始化挂账在门内结清 | skill `dw-worktree` |
| 2 | 【bug 类才做】过红回路门 | 先检索 bug 修复历史，再造出能变红的复现命令；回路不存在 MUST NOT 提假设、MUST NOT 改代码 | skill `dw-bug-diagnosis` |
| 3 | 取代码事实：`ctx find-scenes` → `ctx discover` → `ctx get-card`；查不到就读源码并**当场补卡** | 每条事实带 cite | skill `dw-code-facts` |
| 4 | 写一页 Lean Change Spec，**含〈既有系统清单〉**；写清单时逐条复核 `00-流程总纲.md` §默认倾向 的判据 3/4 | `docs/spec/YYYY-MM-DD-<change-name>-lean-change-spec.md`，骨架 `assets/templates/lean-change-spec.md` | `spec写作纪律.md`；本次不含可执行代码文件时先读 `纯skill改动.md` |
| 5 | 填**兼容取舍**一行 + **替换清单**表 + `FR-###` / `AC-###` 编号 | 保留例外带理由 + 到期日 + 到期动作 | `替换清单.md`（skill `dw-review-gate`）|
| 6 | **兼容取舍确认门 + spec 过稿门**；命中大架构判据或 Triage 第 3 问时附业务语言摘要——**同一批抛出，不分轮问** | 兼容逐条选定、这一页 spec 经拍板人定稿（或他显式说本次跳过）后才动手；结论写进过稿记录行 | `确认门.md`；摘要格式 `用户沟通纪律.md` §1 |
| 7 | 实现 + 边写边删 + 写 CHANGELOG 条目 | 被取代的旧逻辑当场删除；`## 未发布` 下至少一条 | `实现纪律.md` |
| 8 | 跑 spec「如何验证」里的命令 | 每条都真跑过 | `实现纪律.md` |
| 9 | 【命中判定才做】补端到端用例 / 固化测试样本：跨 ≥3 组件、异步多阶段、有中间产物，或手里有真实输入与凭证 | 用例断言每个环节的中间产物；样本进测试目录 | `测试资产纪律.md` |
| 10 | **代码评审门**：每个参照物分组收敛到 **1 个子代理**跑精简版，报告仍逐轴分节 | P0/P1 修完，或按规则登记积压 | skill `dw-review-gate` |
| 11 | 文档结算落盘；【bug 类才做】追加 bug 修复历史 | 文档轴的结论当场落盘 | skill `dw-doc-governance` |
| 12 | **完成与自动合并门** | 按 `merge-gate` 合并 + 合并后验证 + 清理 worktree | skill `dw-worktree` |

输入里有 UI 原型时，第 4 步 MUST 连元素批注一起读：界面内容用 `node <skills 根>/dw-prd/scripts/preview.mjs extract <原型文件>` 取，批注用 `node <skills 根>/dw-prd/scripts/preview.mjs annotations <原型文件>` 取（一次给出用户逐元素批注、文件末尾 `ANNOTATIONS:BEGIN … ANNOTATIONS:END` 的全局反馈、AI 侧 `data-anno` 说明三类），两条都跑完才算读过原型，MUST NOT 通读整份 HTML。`data-anno-kind="question"` 的每一条 MUST 在写这一页 spec 前向用户拍板，MUST NOT 自行替产品定。`<skills 根>` 的取法与两条命令跑不起来时的降级见 `00-流程总纲.md` §完整流程步骤索引 末段。

## 升级路径

走到一半命中任一升级条件时，**本页当场失效，MUST 改走完整流程**：读 `00-流程总纲.md` §完整流程步骤索引 与 `步骤-1-7-设计与实现.md`，从 Step 1 重新起步。MUST NOT 把已经写了一半的一页 spec 将错就错写完，MUST NOT 用"都写到这儿了"当继续的理由。

升级条件两组：Triage 的判定问题里有一问实际为"是"；`00-流程总纲.md` §默认倾向 的"说不清"判据任一命中（判据 3/4 在第 4 步回溯触发）。中途发现影响面变大——跨服务、要迁数据、动了对外承诺——同样立即升级。

## 实现中途发现这一页 spec 写错或写漏

MUST NOT 带着疑问硬做，也 MUST NOT 事后靠改 spec 去追认已经写出来的代码。

| 缺口 | 处置 |
|---|---|
| 措辞含糊、验证命令写漏 | 当场改这一页再往下做 |
| 改到「做什么」或「怎么算完成」 | MUST 依次重过 `确认门.md` 的两道门再回来 |
| 影响面其实说不清 | MUST 当场升级到完整流程 |

## Lean 特有的三个提醒

- **拿不准就升级，别硬塞进一页**：Triage 有任何一问是 borderline，在 spec 的「Triage 复核」里写清哪一问、为什么倾向"否"；实在拿不准就升级。
- **验收标准别只写 happy path**：小改动最常翻车在异常路径。
- **Lean 不等于不写测试、不补卡**：第 9 步的判定命中就照做，协作面为 solo 时也不压缩；本次为写〈既有系统清单〉或为动手实现而读过源码的每个模块，MUST 在本次任务内补卡并随分支提交。压缩的是文档篇幅，不是验证强度。

## 走一遍：一个真实小改动长什么样

需求："订单导出的 CSV 里加一列『下单来源』。"**这是示例不是判据**，每一步的规则以各自的家为准。

| # | 这次实际做了什么 |
|---|---|
| 1 | 主工作树干净 → `git worktree add ./.worktrees/csv-source -b feat/csv-source main`。之后所有文件都落在这里 |
| 2 | 不是 bug 类，跳过红回路门 |
| 3 | 未限定单仓 → 先 `ctx find-scenes 订单 导出`（无命中，起步态属正常）→ `ctx discover "订单导出 CSV"` → 命中订单服务的导出域卡，取到"导出列定义在 `export/columns.py#EXPORT_COLUMNS`"（带 cite）。`source` 字段没有卡片覆盖 → 读源码确认它是 `orders.source` 枚举，**当场补进该域卡**，随本分支提交 |
| 4 | 写 `docs/spec/2026-08-28-csv加下单来源列-lean-change-spec.md`；〈既有系统清单〉两条各带 cite |
| 5 | 兼容取舍：列加在**末尾**，既有列序不变 → "不改变既有可观察行为"。替换清单为空。需求编 `FR-001`，验收编 `AC-001`（含一条空值场景） |
| 6 | 范围（只动导出，不改下单）、`FR-001`、`AC-001`、兼容结论，一批抛给拍板人。他回"可以" → 过稿记录行写"2026-08-28 定稿" |
| 7 | 改 `export/columns.py` 加列；没有旧逻辑被取代；CHANGELOG `新增` 写一条 |
| 8 | 真跑 spec 里那条导出命令，核对新列取值（空值行只看了一眼，没写成可重跑的断言——第 10 步被翻出来） |
| 9 | 只碰一个组件、无异步阶段 → 不触发端到端用例 |
| 10 | 范围里有 `.py` 源码、无 skill 目录树内的 md → 对象面 = P，轴集合 = 规范/忠实/残留/文档，派 1 个子代理跑精简版，首行写明判定。忠实轴报一条 P1：`AC-001` 的空值场景没被真跑覆盖 → 补跑并回填 |
| 11 | 文档轴扫出 `docs/REQUIREMENTS.md` 的导出功能描述仍写"共 8 列" → 当场改成 9 列并落盘 |
| 12 | `merge-gate="direct"` → `git merge --no-ff` 回 main，跑一次导出确认没坏，删 worktree |

第 3 步和第 11 步：**补卡与改真相源都不是"额外工作"**，它们和改代码在同一次任务里结清。
