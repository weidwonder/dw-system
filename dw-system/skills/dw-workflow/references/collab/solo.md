# 协作面 = solo

> 加载条件：无其他人类协作方时加载。
> 本文按 RFC 2119 解释 MUST / MUST NOT / SHOULD / MAY。
> 本文只管**因为没有别人**才变化的约定，MUST NOT 被读成"流程可以放松"（§4）。

## 1. 可跳步：Step 2 / Step 3 通常省略

- **Step 3（PRD 细澄清）与 Step 2（Overview）MAY 省略**——没有协作方要对齐。
  - **这条 MAY 以"分流未被默认倾向上调"为前提**：跨仓 / 影响面说不清的改动 **MUST 升级**到 Step 2 出 Overview（`00-流程总纲.md` §默认倾向，无条件适用），此时本条 MAY **不适用**，MUST NOT 用它抵掉升级（冲突时以默认倾向为准，§5）。
- 但以下情况 SHOULD 照写 Overview：
  - 复杂到"两周后自己都看不懂当初为什么这么写"；
  - 改动跨多个模块 / 限界上下文，影响面自己都说不清；
  - 打算把执行拆给多个 agent 会话做。

> **省略的是"对齐用的文档"，不是"决策记录"。** 已定决策照样 MUST 落盘（写进 Lean Change Spec 或 spec 的决策表）。

## 2. 不需要 owner 对齐、不需要评审会

- **MUST NOT 向不存在的 owner 求证**，也 MUST NOT 因"等待 owner / 业务方 / 评审人确认"而挂起任务。跨仓改动按依赖顺序自排合并次序（规则在 `00-流程总纲.md` §多边界的合并顺序）。
- **例外是门，不是对齐开销**：用户本人的兼容取舍拍板（§3）、**用户本人在 spec 过稿门的表态**（`确认门.md` §spec 过稿门）、标记块 `merge-gate="pr"` 时的平台审批与 CI，都 MUST 照等。前两者是**仅有的两个**允许因等用户而挂起的流程内点——**MUST NOT 因为"只有我一个人用"就把它们读成对齐开销跳过**。协作面是 `solo` **不代表** `merge-gate` 就是 `direct`，合并方式只读标记块字段（`dw-worktree` 的 `worktree开发纪律.md` §完成与自动合并门）。
- **`merge-gate="pr"` 时 PR 的审批人就是用户本人。** 开出 PR 后 MUST 把 PR 链接与各轴评审结论摆给用户，请他过目并放行；MUST NOT 静默等待不存在的外部审批，也 MUST NOT 用代码评审门的自查结论替代这次放行（`dw-review-gate` 的 `评审处置.md` §处置）。CI 失败按常规修复后重推，MUST NOT 因为"等不到人审"就改用本地直合（`dw-worktree` 的 `worktree开发纪律.md` §完成与自动合并门）。
- **MUST NOT 开评审会**这类等待人类到场的动作。需要第二意见时走子代理（§4）。

## 3. 用户既是产品又是技术

本协作面的"用户"就是开发者本人：

- **MUST NOT 对用户隐藏技术细节。** 团队场景那条"不得要求业务用户理解技术方案后拍板"在这里不适用。
- 仍然 MUST NOT 用技术细节淹没业务判断：先说业务影响，再给技术理由（`用户沟通纪律.md`）。
- **兼容取舍每次由你拍板。** AI **MUST NOT 默认兼容**：每次把被改变的既有行为逐条列出，自己明确拍板一次。被新逻辑取代的旧函数/文件/配置/开关当场删除，不留"以后可能用"；保留项 MUST 带理由与到期日。

## 4. 代码评审门 MUST NOT 省略

- 每次编码后 MUST 过代码评审门（skill `dw-review-gate`），**或**按它的 `积压通路.md` §第零步 登记积压延到下一次门。Lean 改动按参照物分组各派 1 个子代理跑它的 `评审轴.md` §评审轴 的精简版即可，但**不能跳过**。
- 这道门 **MUST NOT 因"改动很小""就我一个人用"而免掉**。**积压是推后不是取消**：轴一条不裁，MUST 带 `Review-Deferred:` trailer、MUST 一句话告知你本人、MUST NOT 移动 `reviewed-through` tag。**solo 尤其 MUST NOT 把积压读成豁免**——子代理是你唯一的第二双眼睛。
- P0/P1 修完才收工。Agentic 项目增派一个加载 `agentic-principle` 的 agent 架构轴。

## 5. 分流默认倾向不由本文决定

分流走 Lean 还是升级到完整流程，由 `00-流程总纲.md` §默认倾向 **无条件**定义，**MUST NOT** 从"只有我一个人"推出"默认走最短流程"。

同理，**代码事实层不因"只有我一个人"而省**（`dw-code-facts` 的 `代码事实纪律.md` §1）：查不到卡片就读源码、读完当场补卡，MUST NOT 因为没人看而跳过。

## 6. 与其它分册的边界

| 想找的东西 | 在哪 |
|---|---|
| §"不裁剪"护栏（目录 / 沟通 / worktree / 评审门 / 兼容 / 测试 / 补卡） | `00-流程总纲.md` |
| spec 定稿后要不要请用户过目、怎么算定稿、什么情况才算跳过 | `确认门.md` §spec 过稿门 |
| 合并走本地非快进合并还是 PR | `dw-worktree` 的 `worktree开发纪律.md`（按 `merge-gate`） |
| 决策沉淀进 memory 的写法 | `上下文卫生.md` |
| 什么时候必须升级到完整流程 | `00-流程总纲.md` §Step 0 Triage 的判定问题 |
| 哪个是权威实现、怎么查代码事实、卡片怎么补 | skill `dw-code-facts`（`代码事实纪律.md`）；结构检索在探测到代码图谱时走它的 `graph.md` |

## 一句话

砍掉的是**对齐开销**，砍不掉的是**复核**：评审门、兼容拍板、测试资产一条不减。
