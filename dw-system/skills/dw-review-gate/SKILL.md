# dw-review-gate：代码评审门

本 skill 管**编码完成之后、合并之前的那道评审门**，以及残留轴的判据来源**替换清单**。适用于任何写过代码、改过 skill 判据文档、或改过 `docs/` 下现行文档的任务；完整流程在 Step 7 之后、Step 8 之前，Lean 在实现完成之后、完成与自动合并门之前，**两条路径都不豁免**。流程顺序归 `dw-workflow`；文档去留的判据归 `dw-doc-governance`；合并归 `dw-worktree`。按 RFC 2119 解释规范词。

## 为什么必须交给子代理

写完代码的会话已经被实现细节浸透：它记得"我当初为什么这么写"，于是 review 时最容易替自己辩护，也最容易看不见自己刚加的多余行为和刚绕开的边界。子代理不带这段记忆，只带 spec 和 diff，判断更接近真实的第三方读者。附带收益是省主上下文（见 `dw-workflow` 的 `上下文卫生.md` 规则 4）。

## 五步

| # | 步骤 | 产出 | 判据 |
|---|---|---|---|
| 0 | 定评审范围，定走哪条通路：当场跑，还是登记积压延到下一次门 | 基点、范围、通路 | `references/积压通路.md` |
| 1 | 判本次改动触碰了哪几个**对象面**（P 程序代码面 / K skill 文档面 / G agent 架构面，闭集三类、可多命中）| 面的组合 | `references/评审门禁.md` §第一步 |
| 2 | 由面推轴取并集，按参照物分组派发 | 轴集合与分组 | 同篇 §第二步、§其余门禁规则 |
| 3 | 为每条轴定模型档位 | 档位 | 同篇 §第三步 |
| 4 | 主会话汇总，判定结论写进报告首行 | 首行 + 逐轴报告 | 同篇 §第四步 |
| — | 处置：P0 与 P1 修完、文档轴结论当场落盘、重跑受影响的轴 | 过门 | `references/评审处置.md` |

**面 → 轴**（细则与最易判错的几行在 `评审门禁.md`）：P → 规范 / 忠实 / 残留 / 文档；K → skill 原则轴（加载 `skill-principle`）；G → agent 架构轴（加载 `agentic-principle`）；三面皆不命中 → 文档轴。**算出来是几条就派几条，轴集合 MUST NOT 被裁剪**；积压改的是"什么时候跑"，不改"跑哪几条"。

未过门、也未登记积压时 MUST NOT 进入测试阶段，MUST NOT 进入完成与自动合并门。

## 读取条件（到点才读、只读那一节；MUST NOT 预读，MUST NOT 凭记忆代替）

| 什么时候 | 读什么 |
|---|---|
| 每次过门，第一件事 | `references/积压通路.md` |
| 要判面、推轴、定档、写首行 | `references/评审门禁.md` |
| 要知道每条轴只看什么、不看什么 | `references/评审轴.md` |
| 要派子代理 | `references/子代理模板.md`——派发前 MUST 把每个占位符换成真实值 |
| 各轴报告回来、要处置；走 PR 合并的项目开 PR 前 | `references/评审处置.md` |
| 写 spec 时登记被取代物；残留轴核销 | `references/替换清单.md` |
| 第一次过门，或拿不准一次评审门长什么样 | `references/评审走查例子.md` |

**你是被派出来的评审子代理时**：只读 `references/评审轴.md` 与 `references/子代理模板.md` 里属于你那一轴的职责与返回格式；残留轴另读 `references/替换清单.md`（保留例外怎样才成立、到期未删怎么办）；文档轴另读 `dw-doc-governance` 的 `文档生命周期.md` §3；查代码事实按 `dw-code-facts`。skill 原则轴与 agent 架构轴 MUST NOT 加载本 skill，判据全在各自的伴生 skill 里。
