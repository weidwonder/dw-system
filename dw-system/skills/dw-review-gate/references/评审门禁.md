# 评审门禁：判面、推轴、定档、首行

> 评审门的第一至第四步与不随对象面变化的派发规则。第零步（范围与积压）在 `积压通路.md`。按 RFC 2119 解释规范词。

## 门禁

- 编码完成、基础验证（能跑起来、无编译/语法错）通过后 MUST 执行本门，**或**按 `积压通路.md` §第零步 登记积压把它延到下一次门。**未过门、也未登记积压时 MUST NOT 进入 Step 8，MUST NOT 进入完成与自动合并门。**

### 第一步：判本次改动触碰了哪几个对象面

**对象面是闭集三类，可同时命中多类，MUST NOT 自造第四类。** 判定只看 `积压通路.md` §第零步 算出的那个**评审范围**（`git diff 【基点】...HEAD --name-only`，并入 `git status --porcelain` 里的未提交路径）——**结算积压时该范围比本次任务分支更宽，MUST 按整个范围判面**，MUST NOT 只看本次分支改了什么：

| 代号 | 对象面 | 判定依据 |
|---|---|---|
| **P** | 程序代码面 | 范围里存在**可执行代码文件**（源码、脚本、被程序加载的运行时资产）。传统程序、skill 自带的 CLI / 脚本、Agentic 应用的代码部分**都算本面**。**纯文档格式（含 markdown）不算，即使它被某个脚本读取**——`assets/templates/*.md` 被 `preview.mjs` 读、`assets/config-snippets/*.md` 被 `install.mjs` 读，它们仍是判据文档不是代码。**另有一条测试文件例外，见 ↓〈配套测试不单独构成 P 面〉。** |
| **K** | skill 文档面 | 范围里存在这样的文件：它是 markdown，且它所在目录或任一祖先目录含 `SKILL.md`（即 `SKILL.md` 本身与 `references/` `assets/` 下的 md）。**不在任何 skill 目录树内的文档不属本面** |
| **G** | agent 架构面 | 本次改动触碰 Agent 系统的设计面。判定沿用 `AI-LLM-overlay.md` §Agentic 应用 的既有判据，**本节 MUST NOT 另立一套** |

**"改了 skill" MUST NOT 被读成"只命中 K 面"**——面是按**文件类型**判的，不是按"这次主要在做什么"判的：

| 本次改动 | 命中的面 | 轴集合 |
|---|---|---|
| 只改 `references/*.md` | K | `{S}` |
| 只改 `references/*.md`，但顺手改了 `docs/REQUIREMENTS.md` | K | `{S, D}` |
| 改 `references/*.md` **同时**改了该 skill 自带的 CLI 或它的测试 | **P + K** | `{A, B, C, D, S}` |
| 只改该 skill 自带的 CLI | P | `{A, B, C, D}` |
| 只改 `docs/` 下的文档 | 三面皆不命中 | `{D}` |

第三行是最容易判错的一行：**主体是 skill 文档、代码只是配套**，仍然是 P+K 双面命中——一旦有**非测试的**可执行代码文件进了改动范围，那部分就有 spec 可对照、有替换清单要核销，B 轴与 C 轴的参照物就存在。

**〈配套测试不单独构成 P 面〉**：范围内的可执行代码文件**全部**是**测试文件**时，它们**不单独构成 P 面命中**。判一个文件是不是测试文件要**两条同时成立**：

1. 它位于项目既有测试目录内（探测方式见 `测试资产纪律.md` §2），**或**文件名匹配 `*.test.*` / `*_test.*` / `test_*.*` / `*.spec.*` 之一；
2. 它**不被任何非测试的可执行代码文件** import / require / 加载。

**只要范围内有一个可执行代码文件不满足这两条，本例外即不成立，整个范围照常按 P 面处理。** MUST NOT 把非测试那部分算进 P 面、却把测试那部分摘出去分别派轴——**轴是按面派的，不是按文件派的**，一次评审门只有一个轴集合。

| 本次改动 | 命中的面 | 轴集合 |
|---|---|---|
| 改 `references/*.md` + 它的机器闸 `test/x.test.mjs` | K（测试不单独构成 P）| `{S, A}` |
| 同上，另外还改了 `install.mjs` | **P + K** | `{A, B, C, D, S}` |
| 只改 `test/x.test.mjs`，不动任何 md | **P**（范围内没有 skill 树内的 md，K 不命中）| `{A, B, C, D}` |

**第三行是本例外最容易读错的地方**：例外说的是这些测试文件"不**单独**构成 P 面"，它免掉的是"因为范围里有代码文件所以命中 P"这一条因果，**MUST NOT 被读成"测试文件不属于任何面、可以不评"**。范围里除了测试什么都没有时没有别的面可归，P 面照常命中——此时 B/C 轴确实缺参照物（无 spec、无替换清单），按各轴自己的既有降级处理（B 轴走 `子代理模板.md`〈返回格式〉段的无编号降级，C 轴对空清单如实回答"本轴无发现"），**MUST NOT 因此不派**。

**为什么给测试开这个例外**：机器闸测试是**判据的可执行副本**，不是产品功能——它没有独立的 `FR-###` 可对照（B 轴无参照物），也没有替换清单要核销（C 轴无参照物），这与 ↓「仅命中 K 面时轴集合为 `{S}`」给出的是同一条理由。**A 规范轴在此保留且职责加重**：它是唯一在看这份测试代码的轴，MUST 另查这条闸会不会**恒绿**（见 `评审轴.md` §评审轴 A 轴那一行）。

**三个面都不命中时轴集合为 `{D}`**（典型：本次只改 `docs/` 下的文档——真相源归并、归档、覆盖度台账）。**MUST NOT 重判**——重判的输入是同一份改动范围，必然得到同一个结论，那是个没有出口的循环；也 **MUST NOT 静默跳过本门**。

### 第二步：由对象面推出轴集合（取并集）

| 命中的面 | 该面带来的轴 |
|---|---|
| **P** | A 规范轴 + B 忠实轴 + C 残留轴 + D 文档轴 |
| **K** | S skill 原则轴 |
| **G** | E agent 架构轴 |
| **三面皆不命中** | D 文档轴（只改 `docs/`、或只改仓库根 `CLAUDE.md`／`README` 这类既不在 skill 树内、也不是代码的文件，都落在这里）|
| **K + 配套测试**（可执行文件全是测试，见 ↑〈配套测试不单独构成 P 面〉）| S skill 原则轴 + A 规范轴（A 轴在此另查哑闸）|

多面命中时取**并集**，**同一条轴至多派一个子代理**，MUST NOT 因两面都命中而重复派。**算出来是几条就派几条，轴集合 MUST NOT 被裁剪**——2026-09-03 曾有过一条"三条判据全满足时 MAY 舍去 C/D 轴"的裁剪准入，当轮撤回：它换来的收益只是极小改动少派两个子代理，代价却是**轴集合可能被裁成空集**（只改 `docs/` 的单文件小改本就只有 `{D}`，那三条判据恰好全满足），门"过"了却一个子代理都没派。要省成本走 ↓ §其余门禁规则 的合并派发，那条只改怎么派、不改派哪几条。

**怎么派**：MUST 按 ↓ §其余门禁规则 的**参照物分组**——组内可合并给同一个子代理，**组间 MUST NOT 合并**。完整流程与 Lean 的差别只剩**每组派几个**：**完整流程**每组 MAY 一轴一个并行子代理，也 MAY 组内合并；**Lean 路径**每组 MUST 收敛到 **1 个子代理**跑精简版。**两条路径都 MUST NOT 把跨组的轴塞进同一个子代理**——S/E 轴加载的是别的 skill，与 A/B/C/D 同处一个 prompt 会得到一份自相矛盾的指令（既 MUST 加载 dw-review-gate 又 MUST NOT 加载）。**无论怎么合并，报告 MUST 逐轴分节写，MUST NOT 合并成一段总评。**

- **仅命中 K 面、且本次没动 `docs/` 时轴集合为 `{S}`**，A/B/C/D 一条都不跑（动了 `docs/` 则为 `{S, D}`，判据见 ↓ D 轴那条）。**这不是省略**：B 轴对照的是 spec 的 `FR-###` / `AC-###`，C 轴核销的是 spec 的替换清单，而纯 skill 改动按 `纯skill改动.md` 压根不写 spec——那两条轴在此没有参照物。MUST NOT 因为"看着像漏了"就自行加回；要改回 MUST 走一次新的兼容取舍拍板。**A 规范轴不跑的理由不同**：它查的是"是否符合本仓库既有编码规范与惯例"，而 skill 判据文档的书写体例（渐进披露结构、description 触发质量、分册判断）正是 S 轴按 `skill-principle` 的原则库要查的东西，两者重合，派 A 轴只会得到一份 S 轴已经给过的报告。
- **D 文档轴的触发条件不看对象面，看 `docs/` 有没有可能被牵动**：**改动范围含 `docs/` 下的文档、命中 P 面、或三面皆不命中时，D 文档轴恒跑，MUST NOT 由主会话先判"本次有没有碰文档"再决定派不派**——判断"有没有触碰权威面"本身就是盘点，而盘点正是本轴的第一步；把它交回主会话，等于把最容易漏的判断交给最容易漏的人（`文档生命周期.md` §3 明写"只改语义不删东西同样让文档失准"，而这类改动的替换清单往往是空的，最容易被据此判成"没碰"）。**这条触发条件不削弱那条禁令**：本轴触发与否只看改动范围里有没有代码文件、有没有 `docs/` 下的文档，都是列文件名就能判的，不需要盘点。**判据是"它的参照物有没有可能被牵动"**——D 轴看的本来就是 `docs/`，所以由 `docs/` 直接决定，而不是绕过对象面间接决定；改代码同样可能让 `docs/` 失准，故 P 面也照样触发。
- **S 轴与 E 轴都加载伴生 skill 而不是本 skill**，判据一律以那两个 skill 的当前版本为准，本纪律不复述、不锁定项数与文件路径（见 `评审轴.md` §评审轴 的对应两行）。

### 第三步：为每条轴定模型档位

**档位是两档闭集加一条下限，按能力定义，MUST NOT 写死任何厂商的具体模型名**——本体系同时运行在 Claude Code 与 Codex 等不同 harness 上，写死型号会让另一侧的执行者对不上号。

| 档位 | 能力描述 |
|---|---|
| **普通档**（默认）| 该 harness 上够用的中档推理模型：做得了多文件比对与逐条核对，不追求最强推理 |
| **高档** | 该 harness 上与主会话同级的最强推理模型 |

**MUST NOT 在本表里填具体型号**——具名举例会变成事实上的取值清单（本仓库有先例：原型容器塞进一套组件表后，产出方就照它画，禁令拦不住"举例即锚"），且型号随版本演进会失效。档位由执行者在自己的 harness 上按能力描述对号入座。

**下限（MUST）**：**该 harness 提供多个档位时** MUST NOT 派它的**最低档**模型；**只有单档可选时**照常执行，并在报告首行注明"该 harness 单档"。评审的每一轴都是判断题，最低档会把"发现问题"降级成"复述改动"——省下的成本换来的是一份读着像报告、实际没有结论的东西。**"尽量便宜"的下界就在普通档，MUST NOT 再往下探。**

**默认全部轴派普通档，升档是例外不是常态**；仅在下列任一条件命中时，该轴 SHOULD 升到高档：

1. 该轴在**上一轮**评审中报出过 P0——这块地方已经用实证说明过它容易出错。**本条依赖跨轮记忆，因此每轮报告首行 MUST 记下各轴的 P0 计数**（见 ↓ §第四步）供下一轮读；首行没有这项记录时本条视为不命中，MUST NOT 靠回忆推断。
2. 本次命中**大架构确认门**（主干路"形状"变了，判据见 `用户沟通纪律.md`）；
3. **拍板人显式要求**——他比判据更清楚这次难在哪。

**MUST NOT 拿"改动规模"当升档依据**：跨几个边界、spec 有多少条 `FR-###`、改了多少文件，都是**数量信号不是难度信号**——改两个模块的重命名比改一个模块的并发逻辑简单得多，十条 CRUD 需求比三条状态机需求好判。按规模升档，几乎任何跨模块改动都会命中，升档就从例外变成了默认。

**预算不够给所有轴升档时，SHOULD 优先升判断题类的轴**——忠实轴、文档轴、S 轴与 E 轴要把两份材料摆在一起判"意图有没有被偏离""这段正文说的还对不对"；规范轴与残留轴的工作绝大部分是模式匹配与逐条计数（风格是否与邻居一致、引用数是不是 0、清单核销了没有），降档损失最小。**这只是升档的优先序，MUST NOT 被读成"机械轴可以派到普通档以下"**——下限对所有轴一视同仁。

**本条只改执行成本，MUST NOT 借它削减轴数、缩小评审范围或跳过任何一轴。**

### 第四步：判定结论 MUST 写进报告首行

**执行者是主会话，不是子代理**——子代理只知道"本轴由哪个面带来"，写不出完整的轴集合与档位。**主会话 MUST 在汇总各轴报告时把这一行写在最前**，格式：

`本次对象面：【P/K/G 组合，或"三面皆不命中"】｜轴集合：【轴】｜档位：【档】｜各轴 P0 计数：【逐轴列出，供下一轮定档】｜结算积压：【代码 N 行 / 文档 M 行 / 最早 YYYY-MM-DD，无则写"无"】`

落点：有 `docs/report/YYYY-MM-DD-<feature>-review-report.md` 时写在该文件首行，没有则写进本轮评审的会话结论。**缺这一行 MUST 视为未过门**——派了几个子代理、为什么少派，事后无从复核。

### 其余门禁规则（不随对象面变化）

- **派发按参照物分组**（↑ 第二步「怎么派」的细化）：组内 **SHOULD** 合并给同一个子代理，**组间 MUST NOT 合并**。分组按**读什么**而不是按轴：

  | 组 | 参照物 | 轴 |
  |---|---|---|
  | 1 | 本次改动范围 + spec | A 规范、B 忠实、C 残留 |
  | 2 | `docs/` 的现行文档与真相源 | D 文档 |
  | 3 | `skill-principle` 的原则库 + 被审 skill 全貌 | S |
  | 4 | `agentic-principle` + agent 架构 | E |

  **组内合并省的是重复读同一批文件**（组 1 里 A、B、C 都要通读同一份 diff 与同一份 spec，分开派就把同样的内容读上好几遍）；**组间合并省不到任何东西**——D 轴看的 `docs/` 其余各轴一概不看，S/E 轴的判据压根不在本 skill 里，合并只会稀释注意力。**合并的是"读"不是"判"**：报告仍 MUST 逐轴分节、每轴独立结论，**MUST NOT 收成一段总评**（合并成总评会让一轴的显眼问题掩盖另一轴，这条与 ↓ harness 降级那条同源）。**组内某一轴的工作量明显超出时 MAY 把它单独拆出来派**（典型：替换清单条目很多、或改动文件数很大，C 轴要做的全仓引用检索会挤掉另两轴的注意力）。
- **机械可判的发现类型 MUST 固化成机器闸，MUST NOT 每轮靠子代理重查。** 判据是：**同一类问题
  被报到第二次**，就该有一条闸接手（交叉引用失效、索引漏收、同一个量在多处漂移、清单停在未核销
  标记，都属此类）。子代理的注意力 MUST 留给判断题；把机械题反复交给它，既贵又不如闸可靠——
  闸每次都查全量，子代理只看它这次读到的那部分。
- harness 不支持子代理时：降级为主会话**分轮**执行，一轴一轮、一轮一份报告。MUST NOT 合并成一次"总体看看"——合并会让一轴的显眼问题掩盖另一轴。
