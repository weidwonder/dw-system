# 评审轴

> 每条轴只看什么、不看什么。子代理拿到的逐轴职责全文在 `子代理模板.md`。

## 评审轴（分开查、分开报）

| 轴 | 只看什么 | 不看什么 | 典型命中 |
|---|---|---|---|
| **A 规范轴** | 改动是否符合本仓库既有编码规范与惯例（命名、目录结构、错误处理方式、日志措辞），有没有引入坏味道。**范围内有测试文件时另查一件事：这条闸会不会恒绿**——断言是否真的能判红（有没有做过反向自检的记录）、有没有被 `undefined` 正则、空匹配、退出码代替"文件真的变了"这类写法静默接住 | 需求对不对 | 重复代码、过长函数、霰弹式修改、依赖泄漏、和邻居文件风格打架、**哑闸（无论怎么改被检查对象都判绿）** |
| **B 忠实轴** | 逐条对照 spec / lean spec 的需求与验收项：每条都实现了吗？有没有 spec 没要求却擅自加的行为（镀金）？"不做什么"的边界有没有被越过？ | 代码风格 | 漏实现一条验收项、顺手加了个没人要的开关、动了声明不碰的模块 |
| **C 残留轴** | 替换清单是否逐条核销；被新流程取代的旧逻辑是否已删干净；有没有新产生的死代码；**改动是否落在非权威副本上**（同一逻辑存在多处副本，改的不是权威那处）；**卡片有没有跟上**（〈既有系统清单〉里标着本次新补的，卡片真的在吗；被删掉的实现进陷阱项了吗）| 新代码写得好不好 | 旧函数没人调却还在、feature flag 全量后没摘、旧配置项/旧字段/旧文档段落遗留、被注释掉的旧实现、**改了废弃副本而权威实现原封不动**、**为本次改动读了源码却没补卡片** |
| **D 文档轴** | 参照物是 **`docs/` 的现行文档与真相源**（其余各轴都不看它）。只查四件事（④ **同一事实有没有两个家**：本次新写或改过的规则、数字、清单取一句原文全仓检索，两处以上各自展开即报；范围里有卡片改动时跑 `ctx lint-cards`）：①**正文与代码逻辑是否一致**——本次触碰的权威面，描述它的现行文档说的还对吗；②**断链与孤儿文档**——本次新建/移动的文档有没有断链，新建的有没有任何入口指向；③**真相源跟上没有**——`REQUIREMENTS.md`、`docs/requirements/` 一级子模块与 `ARCHITECTURE.md` 描述的能力被本次改动改了吗（**尚未归并只标「待归并」、MUST NOT 报失准**，归并的时机本就在本轴之后，见 `dw-doc-governance` 的 `文档生命周期.md` §6；正文与本次口径**已经背离**才算失准）。**真相源里出现尚未实现的内容、或出现改动前后对比**同样是失准的一种——它们的去处分别是 `docs/TODO.md` 与归档索引。**一条到期豁免（至 2027-02-28）**：eng-spec / lean-change-spec 的**过稿记录节**是 2.11.0 才加进模板的，比它早的存量 spec 天然没有这一节——本轴遇到缺该节的存量文档 MUST 跳过、**MUST NOT 报成缺陷**；到期后删掉本条豁免（届时存量 spec 应已随各自迭代自然带上该节）。**豁免只针对「这一节压根不存在」**，文档里有该节却是空的或与实际过门情况不符，照常报 | 代码本身怎么写；文档的措辞好不好；**skill / 产品代码内部的口径残留**（那归 C 轴——判据是**看参照物不看文件类型**：本轴只看 `docs/` 与真相源，C 轴看替换清单）| 现行 spec 描述的接口/默认值/错误码语义已与代码背离却还挂在 `index.md` 现行区、真相源正文与本次口径**已经背离**（不是尚未归并）、新建文档没有任何入口指向（孤儿）、指向已归档文档的实施依据没改指向接替者 |
| **S skill 原则轴**（仅命中 K 面）| 加载 `skill-principle`，按它 `SKILL.md` 的**审查路径**入口跑它的全部原则判定；另查同一条规则有没有在两个 skill 文件里各展开一份、压缩或搬家的段落有没有丢命题 | 其余各轴管的事 | 判据、原则编号、项数与文件路径全部以该 skill 当前版本为准，本表不复述 |
| **E agent 架构轴**（仅命中 G 面）| 加载 `agentic-principle`，按它 `SKILL.md` 的评审入口跑它的全部评估项 | 其余各轴管的事 | 判据、项数与文件路径全部以该 skill 当前版本为准，本表不复述 |

**S 轴与 E 轴的共同规矩（两轴都加载伴生 skill，不加载本 skill）**：

- 按该 skill `SKILL.md` 当前的入口进入 review 模式（S 轴走**审查路径**，E 轴走**评审入口**），执行该入口列出的**全部**判定项，并遵守它写明的评审边界（哪些问题要先与用户确认成立才给建议、哪些是客观缺陷可直接给处置、以及不得径自改动被审对象）——**以该 skill 当前内容为准，本纪律不复述、不锁定项数与文件路径**。
- 只有**该 skill 整体不在场**时该轴才标"未执行 + 原因"；**某个内部文件按记忆中的路径没找到 MUST NOT 算作不在场**——回到它的 `SKILL.md` 找当前的入口。
- **MUST NOT 用其余各轴顶替这两轴**：它们看的是别的轴一概不看的东西（S 轴看 skill 自身作为指令载体好不好用，E 轴看 agent 系统的架构选型），顶替只会得到一份别的轴已经给过的报告。
- 该 skill 整体不在场时 MUST NOT 阻断本门，其余轴照常跑。

**D 轴与 `ctx probe` 的分工**：本轴 SHOULD 先跑 `ctx probe` 拿机器结论当补充——**它是辅助不是门禁，绿了也不等于文档还准，跑不起来也不豁免本轴**，完整定位见 `dw-doc-governance` 的 `文档生命周期.md` §3 末段（与 `替换清单.md` §替换清单 对静态检查工具的既有定位同源：判据是 MUST，工具是 SHOULD）。

**判据不在本文重复定义**：什么算"触碰权威面"、失准了怎么归档（改 frontmatter + 插头注 + 移出 `index.md` 进 `index-archive.md`）、仍准确怎么留痕（更新 `last_confirmed`），权威定义都在 `dw-doc-governance` 的 `文档生命周期.md` §3，本轴**执行**它、MUST NOT 另立一套。
