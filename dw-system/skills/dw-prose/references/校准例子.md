# 校准例子

用来对齐尺度，不是文字模板。"适中"指：每条要紧的命题都在，解释只给到这个位置需要的量。

## 每条事实子句都留住

**原文**："协调器会小心地按会话串行化写入，在销毁完成之前刷掉缓冲的事件，并把后端失败报告给调用方。"

**删过头**："协调器串行化持久化。"

**适中**："协调器按会话串行化写入，销毁完成前刷掉缓冲的事件，并把后端失败报告给调用方。"

删的是修饰（"小心地"），不是命题。执行者、按会话的范围、销毁的先后、失败的可见性是四条各自独立的事实。

## 范围声明是有功能的

**删过头**："读来源，自行判断。"

**适中**："本 skill 是判断标准，不是完整清单。列出的检查之外也要判断；成文的要求仍然有效。"

**写过头**：用几段话论证为什么清单替代不了独立判断。

范围声明改变了执行者怎么用这份流程，所以要留；反复的劝说删掉。

## 规则旁的理由：留现在时，搬来历

**原文**："MUST NOT 再拿改动规模当升档依据。2.15.0 之前用过'跨两个边界'与'需求十条以上'两条，实测几乎任何跨模块改动都命中，升档从例外退化成了默认。"

**删过头**："MUST NOT 拿改动规模当升档依据。"

**适中**："MUST NOT 拿改动规模当升档依据：跨几个边界、多少条需求是数量信号，不是难度信号——按它升档，几乎任何跨模块改动都会命中，升档就从例外变成了默认。"

**去处**：哪一版用过哪两条阈值、怎么发现的，进决策记录。

理由省掉后，下一个人很容易把"规模大所以升档"加回来，所以留；但留的是"为什么这样不行"，不是"我们当时怎么发现的"。

## 操作指南留动作与验证

**删过头**："给工具加测试。"

**适中**："在单元层测注册与注销，经真实加载路径跑一遍工具，输出变了就更新快照。断言观察的是外部结果，不是模型自己的汇报。"

**写过头**：把示例代码里已经看得见的每个夹具文件和每条断言走一遍。

## 归属与时机

**删过头**："销毁时取消后台工作。"

**适中**："运行时在释放子作用域之前请求取消；后台任务自己负责在销毁完成前等它的工作线程结束。"

谁请求、谁等待、先后顺序，是三条事实。

## 测试注释：只解释非显然的设计

**原文**（文件头四十行）：依次讲了本闸的三种基线口径、各自漏掉什么、实测的数字、后来的人为什么会想改回去。

**适中**："基线取该文件在本分支出现过的历史最大值：只比父提交，分批精简时'这次删一条、下次补一条'永远通过；只比分支起点，分支内新增的条款没有地板。"

**去处**：三种口径的完整比较与实测数字，进决策记录，注释里留一个指向它的链接。

注释回答的是"为什么是这个设计"，给到足以阻止别人改回去的量即可。

## 卡片：判断留下，流水搬走

**原文**（卡片里的一条）："2026-08-16：工具执行链路收口为单内核（2.9.29）——同日早些时候刚勘误出的'两条并行路径'结构已被消除。三类工具的执行闭包统一回调 `executeTool()`……"

**适中**（写进该域卡的〈权威实现与对外接口〉）："工具执行只有一条路径：三类工具的执行闭包都回调 `src/tool/manager.ts#executeTool`，分发优先级为 内建 > MCP > 远程。"（写进〈陷阱项〉）："`getVercelTools()` 里 MUST NOT 再出现第二套分发——两条并行路径会让超限落盘与协作预检只覆盖其中一条。"

**去处**：哪天收口的、此前勘误过什么，属于 git 与变更日志。

## 报错文案

**删过头**："安装失败。"

**适中**："安装校验失败：`CLAUDE.md` 的标记块 `merge-gate="auto"` 不是合法值（合法值：`"direct"` | `"pr"`）。"

出错的对象、违反的规则、怎么改，三样齐全。
