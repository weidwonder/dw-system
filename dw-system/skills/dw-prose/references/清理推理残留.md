# 清理推理残留

推理残留是**站在写作那次会话的视角**写下的文字：引用只有那次会话看得到的东西，叙述改动而不是叙述现状，或者在跟一位已经离开的评审人辩论。处置从来不是一删了之——段落里还成立的事实，逐条改写成站在仓库当前状态也成立的话，再删掉包着它的叙述；一条事实都不含的（审计编号、控制流旁白）才整段删。

## 分类

| # | 类别 | 长什么样 | 处置 |
|---|---|---|---|
| 1 | 失效的设计会话引用 | `（决策 7）`、`审计项 C2`、未入库草稿的 `§4.7`、阶段代号 `T4` / `W3` | 决策有入库的家就按名字和路径引用；没有就删引用，把它承载的那句事实改成独立成立的话 |
| 2 | 分支与 PR 视角 | "本 PR 新增""上一个提交""本分支后面会" | 写已经存在的机制或扩展点；没做的事进 `docs/TODO.md` |
| 3 | 改动叙述与版本戳 | "此前""原来""不再""改名为""2.3.0 起""X 之前叫 Y""本版" | 写现在的行为。修过的回归写成现在时的反事实（"没有 X，Y 会发生"），MUST NOT 写成仓库史（"以前会 Y"） |
| 4 | 评审经过 | "评审中否决""评审人确认过""第五稿""重跑轮报出" | 留下活下来的结论与理由，当作普通事实写；谁在什么时候说的，删 |
| 5 | 对评审人的辩解 | "这个转换是安全的——它只是……""这样是对的，因为……" | 为自己的正确性辩护的注释是写给评审人的。写出让代码安全的那条不变量；代码本身看得出来就删 |
| 6 | 复述与推导过程 | "先做 X，再做 Y"的控制流旁白、测试走查、显然分支的证明、"实测过三种口径" | 删；只留非显然的规则或不变量。被否决的备选方案搬进决策记录 |
| 7 | 含糊与计划残留 | "暂时应该够用""先这样""以后再说" | 写出真实的界限，或挂一条 `TODO` / 进 `docs/TODO.md`；含糊话删掉 |
| 8 | 写作语言串味 | 中文文档里夹着未翻译的英文工作笔记，或反过来 | 翻译或删 |

## 不算残留

不加区分的清理会两头出错：删掉长期有效的引用，留下失效的。下面这些照原样保留。

- **issue 与待办引用**：`#1470`、`TODO(名字):`、"后续由 issue #N 跟进"——在 HEAD 上解析得到。
- **决策记录、bug 修复历史、变更日志、迁移指南里的来历**：那正是来历的家。
- **抑制说明**：lint 关闭的理由、覆盖率忽略的理由、空 `catch` 的解释——是必须写的散文；理由不对就改对，MUST NOT 删。
- **现在时的反事实**："没有这条，Y 会发生""朴素的做法会……"。
- **实测界限**："（实测：512 层嵌套约 0.15 秒）"这类给常量定标的话；"实测"二字是证据来源，要留。
- **运行期的新旧状态**："旧连接排空之后新连接才接受请求"说的是运行时对象，不是仓库史。
- **带日期的有效期**："保留至 2027-02-28"是规则的一部分，不是版本戳。
- **对外部标准或已入库文档的章节引用**：`RFC 9110 §10.1.5`、本仓库某篇文档自己的 `§3`。
- **格式规定的位置**：决策记录的〈考虑过的方案〉一节、迁移指南的〈行为变化知会〉一节。

## 检索式

检索式是探针，不是定义：它们天生既多报又漏报。每条先拿一个已知的正例和一个形似的反例校准，再相信它在全范围上的结果；另外 MUST 不带检索式通读范围内最密的几篇。

```sh
# 改动叙述与版本戳
rg -n '此前|原来是|原先|不再|已改为|改名|让给了|之前叫|曾经|当初|本版|本次改动|这次改' <范围>
rg -n '[0-9]+\.[0-9]+\.[0-9]+ ?(起|前|之前|之后|新增|引入)' <范围>
# 评审经过与分支视角
rg -n '评审|重跑轮|上一?轮|第.稿|本 ?PR|本分支|上一个提交' <范围>
# 推导过程
rg -n '实测过|试过|备选过|选了.*因为|之所以|后来的人一定会' <范围>
# 含糊
rg -n '暂时|先这样|以后再|应该够|大概' <范围>
# 失效引用
rg -n '决策 ?[0-9]+|审计项|§[0-9]' <范围>
```

排除项写在最后，免得后面的包含规则又把它们放回来：历史文档目录、决策记录、变更日志、迁移指南、本文件自身（它把残留措辞当例子引用）。

已知的假阳性：

- "评审"出现在**描述评审门流程**的文档里是正当主题词；要抓的是"某段文字采用了某一次评审的视角"。
- "不再"描述运行期行为（"过期后不再重试"）不是仓库史。
- "原来"作"原来的位置"讲（搬迁时的空间指代）不是时间指代。
- `§N` 指向本仓库已入库文档自己的章节，可以留。

## 矫枉过正的四种删法

删之前对照命题清单，确认没有落进这四种：

1. **把义务删成了认可**："MUST 先核对再删除"压成"删除前会核对"——模态丢了。
2. **把假设写成了已有功能**："若将来支持多仓，这里要……"压成"支持多仓"。
3. **删掉了一条真事实**：来历叙述里夹着的界限、默认值、失败行为，跟着叙述一起被删。
4. **丢了证据来源**："（实测：……）"去掉"实测"，读者分不清这是量出来的还是拍脑袋的。

## 成批清理的顺序

1. 先只读跑检索式，列候选；通读最密的几篇补漏。
2. 逐处判类，列出命题，决定改写、搬走还是删。
3. 要搬走的来历与否决方案，先写进决策记录，再从原处删——顺序反了就只剩 git 里那一份。
4. 先改来源再改派生物；有测试断言某句原文的，同步更新断言里引用的原文，MUST NOT 为了保住断言而留下残留。
5. 重跑检索式，剩下的应当只有〈不算残留〉里的形态；跑受影响的检查。
