# 仓库地图卡 — 【repo 名】

> **存放路径与文件名是解析契约**：地图卡落 `engineering-context/cards/<repo>.md`，**文件名即 service 名**——
> `ctx get-card <repo>` 的 `<repo>` 就是它（不含 `.md`），放到别的目录一律扫不到。
> 这个名字还 MUST 与 `capability-registry.md`「权威仓库」列填的名字**逐字一致**：
> 匹配是严格相等，写成 `order-service` 对 `orders` 不会报错，只是**静默**失去 card 加权，
> `ctx discover` 于是把本该排第一的卡排到后面。
>
> 每个仓库（或 monorepo 里的每个包）一张。它只回答两件事：这个仓库负责什么、事实按什么业务域分放在哪几张域卡里。
> 具体的权威实现、接口与陷阱 MUST 写进域卡 `engineering-context/cards/<repo>/<域>.md`（模板 `card-domain.md`），MUST NOT 堆在本卡——
> 本卡上限 8,000 字节，`ctx lint-cards` 把守。小节名固定，MUST NOT 自造；用不上的可选小节整节删掉。

## 职责
【本仓库权威负责什么；一句话现状。】

> 根目录：【本仓库相对项目根的路径，如 `services/order`；就是项目根时删掉本行；源码不在本项目里写 `外部`】

## 业务域地图

> **划分方式只写在这里**：按什么维度切、切成哪几块。它与需求真相源 `docs/requirements/` 的子模块 MUST 用同一套切法——
> 两套切法并存之后，没人能判断一条事实该往哪找。新事实先找所属的域；找不到才新开域，新开域 MUST 先改本表。

划分维度：【按业务能力 / 按用户旅程阶段 / 按包 ……，一句话】

| 业务域 | 一句话 | 域卡 |
|---|---|---|
| 【订单导出】 | 【把订单按条件导出成 CSV / Excel】 | `cards/【repo】/【订单导出】.md` |

## 跨域陷阱
> 可选。只放**不属于任何单个域**的陷阱；属于某个域的写进那张域卡。本节被 `ctx` 逐行当成误用警告，引导文字一律用 `>` 引用块。
