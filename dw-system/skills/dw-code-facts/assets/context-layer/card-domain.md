# 业务域卡 — 【repo 名】 › 【域名】

> **存放路径与文件名是解析契约**：域卡落 `engineering-context/cards/<repo>/<域>.md`，目录名即 service 名、文件名即域名——
> `ctx get-card <repo> <域>` 读的就是它。域名 MUST 先登记在地图卡 `cards/<repo>.md` 的〈业务域地图〉里。
>
> 一个业务域一张，上限 16,000 字节（`ctx lint-cards` 把守）；超限先把来历搬走，再把域拆细。
> **小节名固定，MUST NOT 自造**：职责 / 权威实现与对外接口 / 陷阱项 / 确认 四节必备，〈测试入口〉〈日志与排障〉〈端侧补充〉按需，用不上整节删掉。
>
> **只写现状，只记判断。** 卡片记的是从代码里读不出来的人工判断：哪个是权威、哪个是陷阱、约束是什么。
> MUST NOT 出现带日期的小节、"本次核实"式的累积清单、版本号流水——事故经过去 bug 修复历史，取舍来历去决策记录，对外变化去变更日志。
> MUST NOT 逐个方法照抄签名，MUST NOT 抄依赖清单、调用图、最后修改时间、DB schema 全文——机器随时能现查，抄进来就有两份，且这一份必然先过期。
> **MUST NOT 为了凑满本模板把没核对过的字段填上**：填出来的是一条过期权威，比空着更危险。

## 陷阱项

> 一行写清"哪个不能用、为什么、改用哪个"。**把新旧写在同一行**是推荐写法——`ctx` 会自动区分两者，
> 不会把替代物也判成废弃（判据见 `scripts/ctx/README.md` §card 格式约定 的「废弃行怎么写」条）。
> 用**反引号**把接口 / 类名括起来：那是 `ctx` 认候选实体的依据。
> 本节被 `ctx` **逐行**当成误用警告：引导文字一律用 `>` 引用块；"仍在维护""非废弃"这类话 MUST NOT 写进来。
> 被本次改动删除的实现也记在这里（写清"已删除"）。确实没有陷阱写 `无`。

- 【旧接口/旧类/中间产物】 — 【为什么不能用】，改用 【新接口】

> 表格形态同样可以，**第一列固定放不能用的那个**：

| 废弃项 | 改用 | 为什么 |
|---|---|---|
| 【旧接口】 | 【新接口】 | 【上次重构的中间产物 / 已下线 / …】 |
