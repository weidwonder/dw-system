# 业务域卡 — 【repo 名】 › 【域名】

> **存放路径与文件名是解析契约**：域卡落 `engineering-context/cards/<repo>/<域>.md`，目录名即 service 名、文件名即域名——
> `ctx get-card <repo> <域>` 读的就是它。域名 MUST 先登记在地图卡 `cards/<repo>.md` 的〈业务域地图〉里。
>
> 一个业务域一张，上限 16,000 字节（`ctx lint-cards` 把守）；超限先把来历搬走，再把域拆细。
> **小节名固定，MUST NOT 自造**：职责 / 权威实现与对外接口 / 陷阱项 / 确认 四节必备，〈测试入口〉〈日志与排障〉〈端侧补充〉按需，用不上整节删掉。
>
> **只写现状，只记判断。** 卡片记的是从代码里读不出来的人工判断：哪个是权威、哪个是陷阱、约束是什么。
> MUST NOT 出现带日期的小节、"本次核实"式的累积清单、版本号流水——事故经过去 bug 修复历史，取舍来历去决策记录，对外变化去变更日志。
> MUST NOT 逐个方法照抄签名，MUST NOT 抄依赖清单、调用图、最后修改时间、DB schema 全文——机器随时能现查，抄进来就有两份，且这一份必然先过期。
> **MUST NOT 为了凑满本模板把没核对过的字段填上**：填出来的是一条过期权威，比空着更危险。
>
> **落在 `dependencies/<上游名>/<域>.md` 时的三点差异**（外部上游仓库的事实用本模板，四节与体积上限完全相同）：
> ① 目录名即上游名、文件名即域名，`ctx get-card <上游名> <域>` 读的就是它；上游名取依赖声明的同一套命名（含 `/` 的 npm scoped 包写成 `@scope__name`）。
> ② 域名登记在 `dependencies/<上游名>.md` 的〈业务域地图〉里，**不是**地图卡——一个上游仍然只有一个入口文件。
> ③ 源码不在本项目里，`ctx lint-cards` 对这张卡**整卡跳过 cite 校验**（按位置即豁免，不必写 `> 根目录：外部`）。cite 的形态与域卡相同（`路径#符号`，行号可附在后面），**路径相对上游仓库根**。**不受校验的只有 cite 这一类**（四节齐全、体积上限、带日期小节、陷阱项噪声照常检查，`ctx lint-cards` MUST 照跑）：路径、符号、行号写错没有任何一条机器规则拦得住，每条 MUST 对着刚读过的上游源码核一遍再落笔。也正因为不校验，本卡 MUST NOT 记本项目的调用点——调用点唯一的家是声明的〈用到的部分〉列。

## 权威实现与对外接口
> 只列**有判断要下**的条目：同一能力有多处实现时哪一处权威、哪个入口才是对外承诺、调用它有什么约束。
> 入口不只是 HTTP，还含 RPC、Worker / 定时任务、MQ consumer；仅内部可见、已废弃仍在线的，在"约束"列标明——不标，下游会把它读成对外承诺。

## 陷阱项

> 一行写清"哪个不能用、为什么、改用哪个"。**把新旧写在同一行**是推荐写法——`ctx` 会自动区分两者，
> 不会把替代物也判成废弃（判据见 `scripts/ctx/README.md` §card 格式约定 的「废弃行怎么写」条）。
> 用**反引号**把接口 / 类名括起来：那是 `ctx` 认候选实体的依据，一行两个以上实体时尤其重要。
> 本节被 `ctx` **逐行**当成误用警告：引导文字一律用 `>` 引用块；"仍在维护""非废弃"这类话 MUST NOT 写进来。
> 被本次改动删除的实现也记在这里（写清"已删除"），MUST NOT 直接抹掉——后来的 agent 要知道这名字曾存在、现在不该再用。确实没有陷阱写 `无`。

- 【旧接口/旧类/中间产物】 — 【为什么不能用】，改用 【新接口】

> 表格形态同样可以，**第一列固定放不能用的那个**：

| 废弃项 | 改用 | 为什么 |
|---|---|---|
| 【旧接口】 | 【新接口】 | 【上次重构的中间产物 / 已下线 / …】 |

## 日志与排障
> 可选。卡片的高频用途之一是"出问题先看哪"，填不满可只留关键几行。
