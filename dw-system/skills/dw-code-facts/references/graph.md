# 代码图谱（graph）

> 加载条件：探测到 `.codegraph/codegraph.db` 时加载。
> 本文按 RFC 2119 解释 MUST / MUST NOT / SHOULD / MAY。
> 代码图谱回答的是「**找得到吗**」——本项目已建有本地代码知识图谱索引，结构性检索走它，不靠全仓扫描。
> 它是**可选的加速面**：探测到索引才加载本文，查不了就按 §4 回退，MUST NOT 阻断流程。

## 1. 与代码事实层的分工（先读这条）

| | 代码图谱（本文） | 代码事实层（`代码事实纪律.md`） |
|---|---|---|
| 回答的问题 | **找得到吗**（检索） | **信哪个**（消歧） |
| 给出什么 | **现状代码事实**：符号定义与源码、调用链、影响面 | **权威口径**：card + cite（path#anchor @确认时间） |
| 事实来源 | 索引器扫描当前工作区文件，随文件变更同步 | 人工确认后写入并标注确认时间 |
| 承载物 | codegraph 索引（`.codegraph/codegraph.db`） | `engineering-context/`：`capability-registry.md` → cards，按需递进到 scene / probe |
| 是否可选 | **可选**：探测到索引才启用，没有就按 §4 回退 | **必备**：装了本体系的项目一律维护，缺哪块按 §4 当场补哪块 |

**两者 MUST NOT 互相替代**：

- 代码图谱会如实列出 v1 与 v2 两处支付实现，但它**不知道哪个是权威**——判权威 MUST 走 `代码事实纪律.md`：先查卡片；**卡片查不到时读源码定权威，并当场把结论补成卡片**（最小形态见该文 §4.1），每条结论给 `文件:行` 出处。
- 卡片告诉你哪个是权威实现，但它**不保证覆盖每一个符号与调用边**——找调用方、算影响面 SHOULD 走代码图谱。
- 两者都可用时分工是固定的：**权威判定用 card，结构检索用图谱**。图谱查出的结果与 card 冲突时，以 card 为准，并按 `代码事实纪律.md` §7 第 4 条**就地修正卡片并更新确认时间**（协作面为 team 时在合并说明里点名，让 owner 事后复核，但 MUST NOT 因为等 owner 而把错卡片留着）。

## 2. 什么时候用代码图谱

**先确定怎么查**（不写清这一句，下面的 MUST NOT 就是空转）：codegraph 以**当前 harness 里可见的 codegraph 工具**（MCP 工具，安装器默认接线到项目级）或 **`codegraph` 命令**暴露，二者任一可用即可。**具体子命令与参数以工具自身的说明为准**（`--help` 或工具描述），本文不复述——它是外部工具，版本会变，抄一份在这里只会过期。两条通道都看不到、或调得起来却查不出结果时按 §4 回退。

以下问题 SHOULD 先查图谱，MUST NOT 直接开全仓 grep：

- 「这个函数/类/常量定义在哪、源码长什么样」
- 「谁调用了它、它调用了谁」（正反向调用链）
- 「改这个签名会波及哪些文件」（影响面，用于 spec 的〈既有系统清单〉与替换清单）
- 「这个模块的对外入口有哪些」

代码图谱是**检索加速与影响面证据**，不是结论。写进 spec / plan 的每条影响面陈述仍 MUST 指到精确文件路径（`dw-workflow` 的 `spec写作纪律.md` §1）。

## 3. 代码图谱不改变分流默认倾向

Triage 之后走 Lean 还是完整流程，由 `dw-workflow` 的 `00-流程总纲.md` §默认倾向 **无条件**定义，与本项目有没有代码图谱无关。索引只让"查得快"，不代表"影响面说得清"——**MUST NOT 因为能查图谱就把该升级的改动压回 Lean**。

## 4. 图谱不可查时的回退（非硬依赖）

**进入条件**：`.codegraph/codegraph.db` 存在，但出现下列任一情况——

- **通道缺失**：§2 的两条通道都看不到（harness 里没有 codegraph 工具，且 `codegraph` 命令未安装 / 不在 PATH / 调用被工具本身拒绝）。
- **通道可用但查不出结果**：调得起来，却持续查询失败或索引损坏读不出内容。

进入本节后：

1. **MUST NOT 阻断流程。** 索引不可查不是任务失败条件。
2. **MUST 回退到子 agent 重探索外包**（`dw-workflow` 的 `上下文卫生.md` §2 规则 4）：把"大范围代码探索、全仓检索、多方案对比"这类读得多、结论少的工作交给子 agent，主会话只收结论，不让海量文件内容冲刷主上下文。
3. **MUST NOT 退回无策略的裸 grep。** 裸 grep 指没有收窄目标、没有外包、直接在主会话里全仓扫描并把命中内容读进主上下文——它同时丢掉了检索效率与上下文卫生。子 agent 内部按需使用 grep 是允许的，因为结论才回到主会话。**回退到外包之后，收回来的结论同样 MUST 按 `代码事实纪律.md` §4 落成卡片**并随本次分支提交——图谱不可查只是换了取事实的路子，不豁免补卡。
4. SHOULD 一句话提示用户实际情况后继续干活，MUST NOT 反复提示。提示语按**上面观察到的原因**二选一：通道缺失时说"代码图谱索引存在但没有可用通道（harness 里没有 codegraph 工具、`codegraph` 命令也不可用），重跑安装器或在客户端接上 MCP 服务可恢复"；通道可用但查不出结果时说"代码图谱通道可用但读不出结果，重建索引可恢复"。

同理，索引明显滞后于工作区（刚做过大规模重构、查到的符号已不存在）时，MUST 以工作区源码为准，SHOULD 提示重建索引。

## 5. 边界

codegraph 是**外部工具**，本 skill 只声明"何时用它、它给什么、不可用怎么办"。它的安装、索引方式与命令细节不在本 skill 范围内，由安装器负责保持可用；工具本身的用法以它自己的文档为准。本文 MUST NOT 扩写成 codegraph 使用手册。

## 一句话

代码图谱 = 一层随代码变化的现状事实检索面，管"找得到"；管"信哪个"的是必备的代码事实层（卡片），两者不互相替代；索引查不了就外包给子 agent，结论照样补成卡片，绝不退回裸 grep。
