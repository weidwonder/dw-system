# dw-system_技术 Spec — 执行层补强与体积闸收窄

> 来源：对照已卸载的 AgentKit 套件（本机归档 `~/projects/agentkit`），拍板人在 2026-10-08 的对话里选定要吸收的条目；未选的条目与理由见 §1「不做什么」。
> 本次范围含一处可执行代码（体积闸的判定逻辑与它的测试），其余是 skill 文档改动；全部需求统一编号在 §1.1，详细设计只有 FR-001 需要（§2–§4）。

## 0. 阅读导引

- **一句话目的**：体积闸只管单篇上限；评审门、实现、交接、诊断、合并收尾几处补上 AgentKit 做得好而本体系缺的执行层规则，每处只补一两句。
- **端到端场景**：
  1. 维护者往 `dw-workflow/references/` 新增一节 → 体积闸只看这一篇有没有超单篇上限，不再看八份分册加起来超没超。
  2. 评审门派忠实轴 → 子代理除了逐条对照 spec，还核对实现逻辑与被波及的调用方；某个既有行为变了却没进兼容取舍表 → 记一条 `越界`。
  3. 主会话把 coding plan 的一批任务派给子代理或外部编码工具 → 收回后自己重跑验证命令、读 diff，不凭对方的汇报判完成。
  4. 回归类 bug 已有红回路 → 用 `git bisect run <红回路命令>` 找到引入问题的提交。
- **流程图**：

  ```mermaid
  flowchart TD
    A[node --test test/doc-budgets.test.mjs] --> B{清单有未知顶层键?}
    B -->|有| R[判红：点名该键]
    B -->|无| C[files / classes / lines 逐项比对]
    C --> D{超限?}
    D -->|是| R
    D -->|否| G[全绿]
  ```

- **决策表**（FR-001）：

  | 输入 | 条件 | 处置 | 结果 |
  |---|---|---|---|
  | 清单只含 `files` / `classes` / `lines` / `blockExcluded` | 各项都在上限内 | 正常比对 | 绿 |
  | 清单含 `totals` 或其他未知键 | — | 判红并点名该键 | 红：留着它等于一条不生效的规则 |

## 1. 范围

- **本仓库做什么**：§1.1 的十条。
- **不做什么**：
  - 安装器不改：不加安装清单与哈希、不加卸载命令、不改"先删目录再复制"——拍板人定：用户不应改动已装的 skill，覆盖即预期行为。
  - 不把 `secrets/` 写进 Claude Code 的 `permissions.deny`：那要改安装器，本次只补规范文字。
  - 不加运行时挂钩（"落盘前先建 worktree"的拦截等）——拍板人定不做。
  - 不新增评审轴：正确性与回归并进忠实轴。
  - 不加交接文档模板文件：只在规则 2 里补内容项与触发条件。
  - 不搬 AgentKit 的任何启发式判定（关键词、正则、阈值）。
- **依赖的上游 / 下游**：无上游升级。下游是安装了本体系的目标项目，读到的是改后的 skill 文本。
- **既有系统清单**：

| 既有模块 / 机制 | 从哪知道它的 | 本次可能怎么碰到 | 卡片补了吗 |
|---|---|---|---|
| 体积闸 | `test/doc-budgets-lib.mjs#checkBudgets`、`test/doc-budgets.json` | 删 `totals` 分支，加未知键判红 | 已有卡片 `engineering-context/cards/dw-system/skill文档.md`（只点名清单文件，不涉 `totals`），刷确认日期 |
| 忠实轴 | `dw-review-gate/references/评审轴.md` §评审轴、`子代理模板.md` 本轴职责 | 扩一句职责 | 同上卡片不覆盖评审轴细则，无需补 |
| 交接文档 | `dw-workflow/references/上下文卫生.md` §2 规则 2 | 补内容项与触发 | 不涉代码 |
| 其余各 skill 小节 | §1.1 各行点名 | 各补一两句 | 不涉代码 |

### 1.1 功能需求

| 编号 | 需求 |

| FR-002 | 忠实轴顺带查两件事：实现逻辑是否成立（边界、错误分支）；本次改动波及的既有调用方逐个列出 `文件:行` 并核对是否被改坏。既有行为发生变化却不在 spec 兼容取舍表（Lean：兼容取舍一行）里的，记 `越界`。 |

## 2. 数据模型

`test/doc-budgets.json` 的合法顶层键为闭集：`files`、`classes`、`lines`、`blockExcluded`。删除 `totals` 键及其下全部内容（含 `dw-workflow`、`dw-prd` 两条 `overrides`）。

## 3. 接口契约

`checkBudgets(root, manifest)` 的签名与返回形状 `{rows, failures}` 不变。变化：不再产出 `合计 …` 行；`manifest` 含闭集以外的顶层键时，`failures` 多一条点名该键的记录。

## 4. 核心逻辑

```
KNOWN = {files, classes, lines, blockExcluded}
for key in keys(manifest):
  if key not in KNOWN: failures.push("清单有未知键：<key>（判定逻辑不认识它，留着等于一条不生效的规则）")
……其余 files / classes / lines 逻辑不变，删除 totals 循环
```

未知键判红服务于 FR-001：没有它，有人日后把 `totals` 加回清单会静默不生效，闸看着在守、其实没守。

文档改动的落点由 coding plan 列出，规则原文以改后的 skill 文件为准。

## 5. 错误处理

清单 JSON 解析失败的行为不变（测试直接抛错）。

不适用：不涉及持久资源与凭证处理（FR-010 是规范文字）。
