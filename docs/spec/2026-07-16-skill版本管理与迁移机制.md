# Skill 版本管理与迁移机制

> 日期：2026-07-16 ｜ 状态：已实现（`install.mjs` + `test/installer-migration.test.mjs`）
> 目标：分发包有显式版本；存在迁移动作的升级有独立迁移指南；安装器在升级过程中高亮提示。

## 1. 版本源与命名

- **`ai-dev-system/VERSION`**：分发包唯一版本号（`x.y.z` 纯文本），随 git 安装源分发。npm 包只含 `install.mjs`（skill 内容始终从 git 源 clone），故 package.json 的 version 不承担此职责。
- **追认基线**：显式版本化之前的 main 初版 = **1.0.0**（`install.mjs` 的 `LEGACY_VERSION` 常量）。
- **bump 纪律**：
  - 凡改变**已安装项目的行为契约**（流程纪律、模板结构、ctx 命令语义、目录约定）→ 至少 minor bump。
  - 凡需要**用户在目标项目里做动作**（补文件、重跑命令、改已有文档）→ bump 的同时**必须**新增迁移指南。
  - 反向同样是硬规矩：**零手动动作的升级 MUST NOT 建迁移文件**（重装即可、不改标记块字段、不要求回填存量文档），更 MUST NOT 为了过闸补一份「需要的动作：无」的空指南——安装器会把它高亮全文打印，读的人下次就不再认真读高亮块了，那正是这条判据要挡的噪音。
  - 纯错字/措辞修订 → patch bump，可无指南。

## 2. 迁移指南

- 位置与命名：`ai-dev-system/migrations/<新版本>.md`，一个文件 = "升级**到**该版本"的指南。
- 必含章节：**结论**（有无破坏性变更）、**需要的动作**（按受影响人群分列，如"一般情况" / "原本就在用 engineering-context 的项目" / "配置未入库的多人项目"；无动作写"无"）、**行为变化知会**（自动生效、无需动作的部分）。
- 篇幅纪律：安装器会全文打印到终端，指南保持一屏内。**上限以机器闸为准：`test/installer-migration.test.mjs` 判 ≤45 行**（本文此前写的 ≤35 行是 1.x 的旧值，两个数字并存过一段时间，以闸为准）。

## 3. 安装器行为（install.mjs）

1. **源版本**：读安装源的 `ai-dev-system/VERSION`；源无此文件（更旧的源）时跳过全部版本逻辑，行为同旧版安装器。
2. **已装版本**：读目标 `.claude/skills/ai-dev-system.version` 或 `.agents/skills/ai-dev-system.version`（stamp）；无 stamp 但目标已存在源同名 skill → 按 1.0.0 的旧安装处理；两处都无 → 全新安装，不提示迁移。
3. **升级提示**：已装 < 源版本时，收集 `migrations/` 下 `(已装, 源]` 区间的全部指南按版本升序，在确认前（含 `--dry-run`）**高亮**（TTY 下黄色加粗 + 分隔线）全文打印；安装完成后再提醒一次"执行需要的动作"。区间内无指南则打一行"无需额外动作"。
4. **降级警告**：已装 > 源版本时高亮警示，不阻断。
5. **stamp 写入**：复制 skill 成功后，把源版本写入两个 skills 目录的 `ai-dev-system.version`。

## 4. 发布检查清单（维护者）

- [ ] 本次改动是否触发 bump？触发则更新 `ai-dev-system/VERSION`。
- [ ] 有用户动作 → 新增 `migrations/<新版本>.md`（含"需要的动作"节，一屏内）。
- [ ] `node --test test/installer-migration.test.mjs` 全绿。（契约 2.5.0 已改，勾验时按新口径核：①"当前版本有同名指南"**已放宽为条件式**——有指南才校验命名与「需要的动作」节，没有不算违规，以便零手动动作的 bump 不被逼出空指南；②新增"目录里每一份指南都必须是 `<版本>.md` 命名、含「需要的动作」节、≤45 行"；③新增"VERSION MUST NOT 低于目录里最高的那份指南"——写了指南却没 bump 到位，那份指南永远不会被安装器打印。）
- [ ] 用旧 stamp 目标手工 `--dry-run` 一次，确认高亮提示可读。
- [ ] 合入 main 后打 annotated tag `v<版本>`（与 VERSION 一致），并连 tag 一起推送（`git push --follow-tags`）。历史基线：`v1.0.0` = 显式版本化前的 main 初版补记版本号后的提交。
