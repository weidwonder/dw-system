# 原型风格分层与批注框架修复（2.12.0）

## 0. 阅读导引

本次两条主线：**①把原型的视觉风格决定权从容器交还给项目**（架构调整，用户拍板）；**②修一批"页面照常打开、零报错"的框架缺陷**（bug 修复）。二者独立，但 ① 放大了其中几个 bug 的触发概率，因此同批处理。

起因是一次验收：派 codex 生成测试原型验证 2.9–2.10 的迭代效果，用户逐项目测，暴露出下列问题。

## 1. 范围

### 1.1 功能需求

- **FR-001** 容器分两层装配：结构层恒装配，外观层默认不装配。
- **FR-002** `init --with-baseline` 才追加外观层。
- **FR-003** 框架自用的外观类私有化，默认路径下批注 UI 不得裸奔。
- **FR-004** `UI原型纪律.md` §8.3 明确风格归属：棕地继承现有设计、绿地与用户确认、确无来源才兜底。
- **FR-005** 废除 `--anno-right`，屏注解区恒挂该屏下方。
- **FR-006** 屏名恒在设备壳左上角。
- **FR-007** 桌面屏给出横向比例（860×540），与移动屏可区分。
- **FR-008** 打通 `.device → .screen → 状态层` 的满高链路，提供 `.fill` / `.scroll-y` 原语。
- **FR-009** 状态切换按钮由 `screen` 命令生成，行为由容器 `[data-state]` hook 提供。
- **FR-010** `check` 检测空状态层。
- **FR-011** `check` 校验状态按钮 `data-state` 取值合法且指向本屏真有的状态层。
- **FR-012** 删除 `check` 的跨屏状态并集噪音。
- **FR-013** 图钉与注解区按钮的尺寸盒对产出方样式免疫。
- **FR-014** 框架 UI 内的 `[hidden]` 恒生效。
- **FR-015** 发号不复用已被回复引用的 `data-anno-id`。
- **FR-016** `slot --set screens` 按说明文本续接 `data-anno-id`，新旧两侧都唯一才续。
- **FR-017** `writeAtomic` 临时文件名唯一，失败清理半成品。

### 1.2 非目标

1. 不为桌面屏画浏览器 chrome（地址栏之类）——原型展示的是产品界面。
2. 不给并发改稿加锁：唯一化只消除崩溃，后写覆盖先写仍成立，串行执行即可。
3. 不解决"框架升级后已有原型需重建、而重建清空批注块"——记入 `docs/TODO.md`。

## 2. 关键决策与依据

**外观层默认不装配（用户在大架构确认门选定）。** 备选是"彻底移除"与"改造成中性灰阶"。选中方案保留能力但默认关闭：容器塞一套完整控件库，产出方就会照它画，而那套样子与本次项目无关。实测佐证：codex 生成的原型 91 个 class 里 71 个来自容器组件表，且它自己写的 `btn-primary` 是 Bootstrap 习惯而非 shadcn——**风格是被容器带的，不是它自己选的**。

**结构层与外观层的切分线**：批注框架与 `check` 的锚点归结构层（画布 / 设备壳 / 屏 / 状态层 / 注解区 / 图标尺寸 / 排版原语），控件外观归外观层。

**`data-state` 作为状态按钮的唯一属性名**：框架写回逻辑本就按它复位（`anno.js` 的 `serialize()`），而 `check` 此前按 `data-act` 找——两处不一致且骨架零示范，实测导致产出方按钮写一个、选择器查另一个，零个监听器绑上。

## 6. 真跑发现

三条机器闸各自对应一次真实翻车，**都不是设想出来的检查项**：

1. **`[hidden]` 被自己的 `display` 击穿**。`[hidden]` 的 `display:none` 来自 UA 样式表，任何作者的 `display` 都压过它。框架早先为 `.anno-notes-panel` 单独补过一次，但逐条补必然漏——本次新增的编辑态提示与"放弃修改"按钮各踩一次。
2. **`!important` 的传染性反噬**。给 `.anno-pin` 加 `!important` 挡产出方后，框架自己的 `[data-anno-hidden] .anno-pin { display:none }` 与 `.anno-btn--icon` 也被一并挡住，"隐藏批注"整个失效。
3. **字符串替换的四连击**。给 `openNote` 加绑定时锚点在四个函数里都存在，`replace` 默认全替，`openEditor` / `openGlobal` / `newNote` 各被塞进一行绑定不存在元素的代码，`null.onclick` 抛 TypeError 使函数整个中断，三个弹窗全打不开——表现只是"按钮点了没反应"。

另有一次**哑闸**：图钉免疫的第一版断言写作 `width:[^;]*!important`，命中了 `min-width: 0 !important` 的子串，拿掉真正的 `width` 保护照样全绿；`height` 同样被 `line-height` 骗过。补前置边界后两个破坏点均判红。反向自检是发现它的唯一途径。
