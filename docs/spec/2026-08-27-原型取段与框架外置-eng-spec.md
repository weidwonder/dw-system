# ai-dev-system_技术 Spec — 原型读侧取段（extract）与框架源码外置

> 单仓库的详细技术规范。遵循 `references/core/spec写作纪律.md`：零上下文可动手、RFC2119、无占位符。
> 本文按 RFC 2119 解释 MUST / MUST NOT / SHOULD / SHOULD NOT / MAY。
> 本文档属工程内部详细设计，由 AI 与工程侧自主完成并自检，不要求业务用户确认。

## 0. 阅读导引（MUST，前置）

- **一句话目的**：让下游读原型时只取界面内容（token 降约 85%），并把埋在 HTML 注释块里的 74KB 框架代码解放成可 lint、可 diff 的独立 css/js 源文件，而产出的原型文件一个字节都不变。

- **端到端场景**：
  1. `ai-dev-workflow` 的 Step 1 拿到 PRD 与 `docs/spec/2026-08-26-原型注解分层-prototype.html`（85,236 字节）→ 跑 `preview.mjs extract <文件>` → 拿到 TITLE + NOTES + SCREENS 三段共约 11.7KB → 据此写需求理解与问题清单，**不再通读整份 HTML**。
  2. `ai-prd` 要建一份新原型 → `preview.mjs init out.html --title 订单改版` → 装配器读容器模板 `ui-prototype.html` 与 `ui-prototype-framework/` 下六个框架源文件，按装配表把每份内容包进 `<style>` / `<svg>` / `<script>` 填进对应区间 → 落盘的 out.html 与外置改造前的 init 产物**逐字节相同**。
  3. 维护者要改批注框架的某条 CSS 规则 → 直接编辑 `ui-prototype-framework/anno.css`（真 CSS 文件，编辑器高亮、格式化、diff 全部可用），不再在 848 行 HTML 内嵌脚本里定位。
  4. **异常**：框架源文件缺失或读不到 → `init` MUST 报错退出（**退出码 1**）并指明缺的是哪个文件的哪个区，MUST NOT 落一个缺样式或缺批注框架的残页。
  5. **异常**：`extract` 的目标文件不含 `SCREENS` 分区标记（不是本体系的原型容器产物）→ 报错退出（退出码 2），MUST NOT 输出半段内容让读者误以为原型只有这些。

- **核心流程图**：
  ```mermaid

    subgraph 写侧
      I[init] --> C[composeTemplate]
      C --> T[容器模板 ui-prototype.html]

      X --> R[下游 Step 1 / 4 / 8]
      N --> R
    end
  ```

- **决策表**：

  | 输入 / 状态 | 条件 | 走向 / 处置 | 结果 |
  |---|---|---|---|
  | `extract <文件>` | 文件含 `SCREENS` 分区标记 | 取 TITLE、NOTES、SCREENS 三区 | 分段输出到 stdout，退出码 0 |
  | `extract <文件> --with-css` | 同上 | 追加 PROJECT-THEME、CUSTOM-CSS 两区 | 五段输出，退出码 0 |

## 1. 范围

- **本仓库做什么**：给 `ai-prd` 的 `preview.mjs` 增加读侧取段命令 `extract`；把 `ui-prototype.html` 的六个固定实现区外置成独立源文件，由 `init` 时装配回单文件产物；把 `ai-dev-workflow` **五个**读原型的执行点从「打开该文件 / 通读整份 HTML」改为「先跑 `extract` + `annotations`」（五个落点的清单在 FR-014，全文以那份为准）。

- **不做什么**（明确边界）：
  - **MUST NOT 改变原型产物的形态**：仍是单文件、零外链、可离线打开的 HTML；不引入构建步骤、不产出多文件原型、不让产物依赖任何外部资源。
  - **MUST NOT 改变 `ui-prototype.html` 的文件路径**：十余处文档与两份测试引用它，路径不变则这些引用零改动。
  - **MUST NOT 给 `extract` 加 `--json`**：它的消费者是读者的上下文而不是程序，JSON 转义只会让同一份内容更贵；需要结构化数据的场景由 `annotations --json` 承担。
  - **MUST NOT 让 `extract` 输出批注数据**：用户批注、全局反馈、AI 侧说明与回复的唯一入口仍是 `annotations`（`UI原型纪律.md` §7）。
  - **MUST NOT 做摘要式提取**：`extract` 只按分区标记原样取段，MUST NOT 剥 class、压缩嵌套或重述层级——原型是用户可见行为的权威描述，有损摘要会让下游拿不到原始 DOM。
  - MUST NOT 改动批注框架的任何运行时行为、图钉定位、写回协议或 `prd-annotations@1` 数据结构。

## 2. 数据模型 / 数据结构

本次不引入持久化数据结构。唯一新增的进程内结构是装配表：

```js
// preview.mjs —— 容器固定区 → 框架源文件 → 包裹标签 的唯一映射。
// 顺序无关（按 mark 定位区间），但 MUST 与容器里实际存在的固定区一一对应，多一个少一个都判错。
const FRAMEWORK_DIR = path.join(HERE, '..', 'assets', 'templates', 'ui-prototype-framework')
const FRAMEWORK = [
  { mark: 'THEME',              file: 'theme.css',         open: '<style>',                                       close: '</style>' },
  { mark: 'DESIGN-SYSTEM',      file: 'design-system.css', open: '<style>',                                       close: '</style>' },
  { mark: 'ANNO-FRAMEWORK:CSS', file: 'anno.css',          open: '<style>',                                       close: '</style>' },
  { mark: 'ICONS',              file: 'icons.svg',         open: '<svg style="display:none" aria-hidden="true">', close: '</svg>' },
  { mark: 'SCREEN-SCRIPT',      file: 'screen.js',         open: '<script>',                                      close: '</script>' },
  { mark: 'ANNO-FRAMEWORK:JS',  file: 'anno.js',           open: '<script>',                                      close: '</script>' },
]
```

**装配串的构成（MUST，实测值）**：六个固定区在容器中的区间形态完全一致——`markRange` 区间 = `"\n  "` + 包裹开标签 + 内容 + 包裹闭标签 + `"\n  "`。六个区的前后缀**实测都是 `"\n  "`**（两个空格），因此装配表无需逐区记录缩进，用一对常量即可：

```js
const FRAMEWORK_PRE = '\n  '
const FRAMEWORK_POST = '\n  '
// 填充串 = FRAMEWORK_PRE + item.open + <源文件内容> + item.close + FRAMEWORK_POST
```

框架源文件存的就是包裹标签之间的内容**原样**（含其首尾的换行与缩进）。这条是 FR-013 逐字节相等的达成方式：只要切分时按 `markRange` + `indexOf(open)` / `lastIndexOf(close)` 取，装配时按上式拼回，等值**自动成立**，不依赖任何人对缩进的记忆。**MUST NOT 对源文件内容做 trim 或格式化**——那会当场打破等值，且 `.css` / `.js` 文件首行是空行并不影响任何编辑器或 linter。

**`icons.svg` 的形态说明（MUST）**：该文件内容是 `<symbol>` 元素序列，**不是**可独立渲染的 SVG 文档——根 `<svg>` 标签由装配表的 `open`/`close` 提供，且 MUST NOT 给它加 `xmlns` 属性（`test/prototype-annotations.test.mjs:189` 断言容器全文不得出现 `xmlns`，那条闸挡的是「图标被改成 data-URI 外链」）。扩展名取 `.svg` 是为了让编辑器按 SVG 高亮 `<symbol>`/`<path>`，代价是单独打开该文件不渲染；这点 MUST 写进框架目录的 README。

## 3. 接口契约

### 3.1 `extract` 子命令

```
preview.mjs extract <原型文件> [--with-css]
```

- **默认输出区序**：`TITLE` → `NOTES` → `SCREENS`。`--with-css` 时区序为 `TITLE` → `NOTES` → `SCREENS` → `PROJECT-THEME` → `CUSTOM-CSS`。区序 MUST 固定，MUST NOT 按文件中的出现顺序动态排。
- **段头格式**（每段一行，正文前）：

  ```
  ===== SCREENS （源文件第 901 行起） =====
  ```

  行号取该区 `<!-- MARK:BEGIN` 那一行的行号（1-based），由 `html.slice(0, html.indexOf('<!-- ' + mark + ':BEGIN')).split('\n').length` 得出。**MUST NOT 改用 `range.from` 起算**——`markRange` 的 `from` 落在 BEGIN 注释的 `-->` 之后，而 BEGIN 注释本身可能跨多行（`THEME` 的注释就占两行），用它算出的行号会比实际大。行号让读者能把 extract 的输出与原文件对上，也让下游在提问题清单时给得出 `文件:行`。
- **正文**：`html.slice(range.from, range.to)` 原样输出，MUST NOT 做任何 trim、缩进重排或转义。
- **空区处置**：正文去掉空白与 `<!-- … -->` 注释后为空串时，段头照出，正文位置输出单行 `（本区为空）`。判空 MUST 在去注释之后——出厂容器的 `<!-- SCREENS -->` 占位注释否则会被当成已有内容（同一个坑已在 `stripShell` 一带记为陷阱项）。
- **末尾指引**（恒输出，无条件）：

  ```
  ----- 本命令只给界面内容。用户批注、全局反馈、AI 侧 data-anno 说明与回复请跑：
        preview.mjs annotations <原型文件>
  ```

- **失败**：目标路径不存在或不是普通文件时走既有 `readTarget()` 的 `stat()` 分支（退出码 **1**，`preview.mjs:175-183`）；文件存在但 `readFile()` 失败（如无读权限）时**落到顶层兜底**，这是 `readTarget()` 的既有行为，本次 **MUST NOT 顺手改它**——它服务于全部七条命令，改动会越出本次范围。`markRange(html, 'SCREENS')` 返回 `null` 时走 `fail(…, 2)`，退出码分界见 ↓ §5 的那条 MUST（`preview.mjs:174` 一带是约定原文）。终止一律抛 `Abort`、**MUST NOT 用 `process.exit()`**——管道下它会截断已写出的 stdout 而退出码照常。错误文案 MUST 指出「不是本体系的原型文件（缺 SCREENS 分区标记）」，MUST NOT 只报「解析失败」。
- **副作用**：无。`extract` MUST 只读，MUST NOT 写盘、MUST NOT 起服务。

### 3.2 `composeTemplate()`

```js
async function composeTemplate() -> Promise<string>
```

- 读 `TEMPLATE`（容器模板路径，值不变）与 `FRAMEWORK` 表列出的每个框架源文件。
- 对每个表项：`markRange(html, item.mark)` 取区间；返回 `null` 时 MUST 抛错，文案指出容器缺该区标记。
- 填充内容为 `FRAMEWORK_PRE + item.open + <源文件内容> + item.close + FRAMEWORK_POST`（两个常量的实测值见 §2）。源文件内容 MUST 原样使用，MUST NOT trim、MUST NOT 补缩进。
- 任一源文件读取失败：MUST 抛错，文案含区名与完整文件路径。
- **纯函数**：MUST NOT 写盘、MUST NOT 依赖 `cmdInit` 的参数。测试与 `cmdInit` 共用同一个它。
- MUST 从模块导出，供 `test/` 直接调用（FR-015）。

### 3.3 `cmdInit` 的变化

`copyFile(TEMPLATE, file)` + `readFile(file)` 两步被 `const html = await composeTemplate()` 一步取代；随后的三处 `replace`（title / h1 / subtitle）与 `writeAtomic` 不变。目标已存在时的「不覆盖」检查 MUST 保持在装配之前，避免为一个必然被拒的调用白读七个文件。

### 3.4 模块入口守卫（MUST）

`preview.mjs` 顶层现在无条件执行 `main().catch(…)`（`:966-974`）。一旦它开始 `export` 任何东西，`import` 它的测试就会**连带跑一遍 CLI**——实测表现为打印 HELP 并把 `process.exitCode` 设成 2，于是整个测试进程以非零码退出，而每一条断言都是绿的。这种失败读起来像"测试框架坏了"，最难归因。

因此 FR-017 要求：顶层调用 MUST 包在"本文件是否为直接执行的入口"的判断里。判据 MUST 用 `process.argv[1]` 与本模块 URL 的**真实路径**比较（两侧都过 `realpath`），MUST NOT 只比字符串——`node ./scripts/preview.mjs` 与经符号链接调用时 `argv[1]` 的形态不同。判断失败（取不到 `argv[1]`）时 MUST 视为"不是直接执行"，即不跑 `main()`：被 import 时静默是正确行为，而 CLI 少跑一次会立刻显形。

### 3.5 `HELP` 文案

```
  extract <文件> [--with-css]                           取界面内容（结构+文案；批注用 annotations）
```

## 5. 错误处理 / 降级 / 失败模型

| 失败 | 触发条件 | 处置 | 用户看到什么 |
|---|---|---|---|
| 原型文件路径不存在 / 不是普通文件 | `readTarget()` 的 `stat()` 失败 | 抛 `Abort`，**退出码 1** | `找不到原型文件：<path>` |
| 原型文件存在但读取失败（如无读权限） | `readTarget()` 的 `readFile()` 抛错 | **落到顶层兜底**（`preview.mjs:966-974`），退出码 1 | `preview.mjs 执行失败：…` + 「这是工具自身的问题，MUST NOT 因此改用手工编辑原型文件」 |
| 不是原型文件 | `markRange(html,'SCREENS')` 为 `null` | 抛 `Abort`，退出码 2，不输出任何区段 | `不是本体系的原型文件（缺 SCREENS 分区标记）：<path>` |
| 待输出区缺标记（非 `SCREENS`） | 如存量原型缺 `NOTES` 区 | 段头写 `===== <区名> （区标记不存在） =====`，**正文另起一行**写 `（本区不存在于该文件）`，退出码仍为 0 | 其余区照常输出；形态 MUST 与空区分支一致——两支形态不同，下游按「段头之后是正文」解析会在这一支拿到空串 |
| 框架源文件缺失 | `composeTemplate()` 读文件失败 | 抛错，`init` 退出码 **1**，目标文件不创建 | `框架源文件读不到：<区名> → <完整路径>` |
| 容器缺固定区标记 | 容器被误改，`markRange` 返回 `null` | 抛错，同上（退出码 **1**）| `容器缺固定区标记：<区名>` |
| 容器模板本身读不到 | skill 安装不完整 | 抛错，退出码 **1** | `容器模板读不到：<路径>` |

> **退出码分界（MUST）**：**"用户把参数指错了"是 2，"文件内容或安装状态不对"是 1**。所以 `extract` 拿到一份根本不是原型的文件是 2（参数取值非法），而"容器缺固定区标记""框架源文件读不到""容器模板读不到"都是 1——它们与既有的 `找不到界面插槽（SCREENS 区被改写了？）`（`cmdScreen`）、`找不到插槽 X 的标记（该区被改写了？）`（`cmdSlot`）完全同类，那几处一律用 1。**MUST NOT 因为"这也是一种非法"就把后一类改成 2**：同一份文件里对同类错误给两种码，下一个照抄邻居代码的人必然写出第三种。

**降级**：`extract` 跑不起来（Node 缺失、脚本路径找错）时，读取方 MAY 降级为直读原型文件，但降级 MUST 是显式的、MUST 在问题清单里记一笔，MUST NOT 把降级当默认路径——降级路径每次多付约 18k token。

## 6. 安全 / 鉴权 / 配置 / 不变量

本次不触碰鉴权、网络与凭证面；`extract` 无网络访问、无写盘。

- **Invariant 1（装配完整）**：`composeTemplate()` 的输出里，六个固定区的区间 MUST 均为非空，且各区的包裹标签成对出现。强制机制：FR-016 的机器闸。
  > **它 MUST NOT 被写成「与改造前逐字节相等」**：那条等值只在外置落地的那一次成立，固化成常驻闸之后，日后任何一次改 `anno.css` 或 `design-system.css` 都会判红，而那正是本次外置想让它变容易的事。等值的一次性验收归 AC-007。
- **Invariant 2（产物形态不变）**：装配产物 MUST 仍满足零外链自检——无 `http(s)://`、无 `<script src=>`、无 `<link href=>`、无 `@import url(`、无 `xmlns`。强制机制：`test/prototype-annotations.test.mjs` 既有的零外链断言在 FR-015 改造后作用于装配结果，自动覆盖。
- **Invariant 3（容器空区）**：容器 `ui-prototype.html` 中六个固定区的 `markRange` 区间内容 MUST 为空白串。强制机制：FR-016 的机器闸逐区断言。它挡的是「改框架时图省事又往容器里写了一段」——那会让同一份 CSS 出现两处副本，且装配后静默重复。
- **Invariant 5（装配表忠实）**：`composeTemplate()` 结果中每个固定区的区间 MUST 逐字节等于 `FRAMEWORK_PRE + open + <该项 file 的内容> + close + FRAMEWORK_POST`。强制机制：FR-016 的机器闸逐区读源文件对比。**这条与 Invariant 1 不是一回事**：Invariant 1 只说"区间非空、标签成对"，把装配表某一项指向另一个源文件仍能满足它；本条才挡得住"`anno.css` 的内容被装进了 `THEME` 区"这类映射错误。
- **Invariant 4（`extract` 只读）**：`extract` 执行路径上 MUST NOT 出现 `writeFile` / `writeAtomic` / `rename` / `createServer`。
