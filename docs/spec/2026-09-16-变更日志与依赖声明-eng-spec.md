# ai-dev-system_技术 Spec — 变更日志与依赖声明（多项目变更感知）

> 单仓库的详细技术规范。遵循 `references/core/spec写作纪律.md`：零上下文可动手、RFC2119、无占位符。

## 0. 阅读导引（MUST，前置）

- **一句话目的**：让一个项目的**不兼容改动**能被它的下游在升级时**只读两份文件就判断出影响面**——上游在合并时写"我改了什么"，下游在自己的代码事实层里写"我用了你什么"，两边用同一套接口名，升级时取交集；**不新增任何门，正常路径不多派一个子代理**。

- **端到端场景**：
  1. B 项目改了 SDK 的 `createOrder` 签名。兼容取舍确认门已让拍板人把这条判成"不兼容"。实现阶段主会话按 spec §8.1 把它写进 B 仓库根 `CHANGELOG.md` 的 `## 未发布 › 不兼容`，以接口名开头、写清旧调用方式 / 新调用方式 / 迁移步骤。评审门的忠实轴对照 §8.1 与 CHANGELOG，缺一条记 `漏做`。完成门只核对"条目在"。零新增子代理。
  2. B 的产品经理发版：把 `## 未发布` 改成 `## 1.0.0 — 2026-10-01`，按"有不兼容升主版本"定号，打 tag。本体系只写这条规则，没有门。
  3. A 项目升级 B 的 SDK 到 1.0.0。加载点触发：主会话读 A 自己的 `engineering-context/dependencies/b-sdk.md`（用到 `createOrder`、`listOrders`，调用点 `src/order/service.ts:41`），读 B 的 `CHANGELOG.md` 0.9.x→1.0.0 之间的 `不兼容` 条目，取交集得到 `createOrder` 一条，改那一处调用，更新声明里的版本与确认时间。零子代理。
  4. A 升级另一个上游 C，C 没有 `CHANGELOG.md`。主会话派 **1 个**子代理看 C 两个版本之间的 diff，**只看声明里列出的那几个接口**是否被改。
  5. A 升级上游 D，A 从没给 D 写过声明。主会话按上下文卫生规则 4 把"A 哪里调了 D"外包给子代理扫一遍，**当场把声明补上**，再回到场景 3 的路径。下次升级 D 时不再需要子代理。
  6. 有人绕过流程直接往 B 的主分支推了一个 hotfix，没写 CHANGELOG。B 下一次过完成门时，一条 `git log --first-parent` 列出"自上一版本 tag 以来没碰 CHANGELOG.md 的提交"，一句话告知拍板人，由他决定补不补条目。零子代理。

- **核心流程图**：
  ```mermaid
  flowchart LR
    subgraph 上游 B
      B1[兼容取舍确认门: 不兼容清单已拍板] --> B2[实现阶段: 写 CHANGELOG 未发布节]
      B2 --> B3[评审门 忠实轴: 对照 spec §8.1 与 CHANGELOG]
      B3 --> B4[完成门: 核对条目在 + first-parent 漏写检查]
      B4 --> B5[发版 由人做: 未发布 → 版本号 + tag]
    end
    subgraph 下游 A
      A1[触发: 要升级上游 B] --> A2{有 dependencies/b.md?}
      A2 -->|无| A3[外包子代理扫调用点 → 当场补声明]
      A3 --> A4
      A2 -->|有| A4{B 有 CHANGELOG?}
      A4 -->|有| A5[读旧→新之间的 不兼容 条目 ∩ 声明的用到的部分]
      A4 -->|无| A6[派 1 个子代理看两版本 diff, 只看声明里的接口]
      A5 --> A7[交集逐条进 spec 范围 → 改调用点 → 更新声明版本]
      A6 --> A7
    end
    B5 -.CHANGELOG.md.-> A4
  ```

- **决策表（下游升级时派几个子代理）**：

  | 有依赖声明 | 上游有 CHANGELOG | 动作 | 新增子代理 |
  |---|---|---|---|
  | 有 | 有 | 读两份文件取交集 | 0 |
  | 有 | 无（或缺该版本区间） | 子代理看上游两版本间 diff，范围限于声明列出的接口 | 1 |
  | 无 | 任意 | 先外包扫调用点并当场补声明，再按上两行走 | 1（本来就该外包的重探索，不算净增） |

## 1. 范围

- **本仓库做什么**：
  1. 给 `ai-dev-workflow` 增加**上游侧**的变更日志纪律：仓库根 `CHANGELOG.md` 的形态、写条目的时机、评审门忠实轴的对照义务、完成门的核对与漏写检查、发版时的改名与版本号规则（规则不是门）。
  2. 增加**下游侧**的依赖声明纪律：`engineering-context/dependencies/<上游名>.md` 的载体与最小五项、补写义务、上游升级时的处置顺序与兜底。
  3. `ctx init` 骨架增加 `dependencies/` 目录；新增声明模板 `assets/context-layer/dependency.md` 与 `commands.js` 内的 stub。
  4. 同步 Lean 自足册、入口加载点清单、注入目标项目的片段、本仓 `CLAUDE.md` 与需求真相源；本仓库自己落一份仓库根 `CHANGELOG.md` 作为第一个实例。
  5. 新增机器闸 `test/change-awareness.test.mjs`。
- **不做什么**：
  - MUST NOT 新增任何门。发版（定版本号、打 tag）是产品经理的动作，本体系只写规则，MUST NOT 为它设门、MUST NOT 让 AI 定版本号。
  - MUST NOT 在合并门或发版时回头读两个 tag 之间的全部 commit——条目在每次合并前就写好，回读是本方案要消灭的成本。

  - MUST NOT 改动 Triage 四问、五道门的集合、对象面三类闭集、轴集合推导规则。

  - MUST NOT 改安装器：CHANGELOG 放仓库根，不受安装器对 `docs/` 与 `engineering-context/` 的入库决定影响；依赖声明属代码事实层，随 `engineering-context/` 的入库决定走。

### 1.1 功能需求（MUST 编号）

| 编号 | 需求 |
|---|---|
| FR-001 | 装了本体系的每个项目在**仓库根**维护 `CHANGELOG.md`；顶部固定一个 `## 未发布` 节，其下分类是**五类闭集**：`不兼容` / `新增` / `变更` / `修复` / `内部`，MUST NOT 自造第六类。 |
| FR-002 | **每次合并到主分支 MUST 在 `## 未发布` 下至少写一条**；自认为对外不可见的改动写进 `内部`。MUST NOT 以"本次无对外变化"为由不写——拍板人已定"一律写"。 |
| FR-003 | `不兼容` 条目 MUST 以**对外接口名**开头（与本仓卡片 §对外接口 里的名字一致；没有卡片时用代码里的导出名 / 路由 / 事件名），并 MUST 含三项：旧调用方式、新调用方式、迁移步骤。缺任一项视为条目未写。 |
| FR-004 | `不兼容` 条目的来源是 spec §8.1 兼容取舍决策表（Lean：兼容取舍一行）里拍板为"不兼容"或"兼容一段时间"的每一行，**一行一条**；MUST NOT 另派子代理去读 diff 生成条目。 |
| FR-005 | 条目 MUST 在**实现阶段、代码评审门之前**写好（完整流程 Step 7 内；Lean 第 5–6 步内），使评审门有物可对；MUST NOT 推到完成门才写。积压通路 MUST NOT 豁免本条（它只豁免评审门）。 |
| FR-006 | 忠实轴增加一项对照：spec §8.1 判为不兼容 / 兼容一段时间的每一行 MUST 在 `## 未发布 › 不兼容` 有对应条目且三项齐全，缺一条记一条 `漏做`；spec 声明"本次无兼容取舍"而 CHANGELOG 出现 `不兼容` 条目时记一条 `做反了`。 |
| FR-007 | 完成与自动合并门新增一项准出核对：`CHANGELOG.md` 的 `## 未发布` 下有本次分支写的条目。**只核对、不生成**；缺条目 MUST 退回实现阶段补，MUST NOT 在门内代写。 |
| FR-008 | 完成门 SHOULD 跑一条 git 检查：自上一个版本 tag（`v*`）以来，目标主分支 first-parent 链上每个提交（含 merge commit）是否都触碰了 `CHANGELOG.md`；没触碰的逐个列出，一句话告知拍板人。没有版本 tag 时跳过本检查。**MUST NOT 派子代理去补写**，补不补由拍板人定。 |
| FR-009 | 发版规则（只是规则，不是门，由人在发版时执行）：把 `## 未发布` 改名为 `## <版本> — YYYY-MM-DD`，并在其下新开一个空的 `## 未发布`；版本号按该节内容定——有 `不兼容` 升主版本，否则有 `新增` / `变更` 升次版本，否则升修订号；SHOULD 打 annotated tag `v<版本>`。AI MUST NOT 替拍板人定版本号或打 tag。 |
| FR-010 | 下游侧：每个被本项目调用的上游（SDK、服务、共享库）在 `engineering-context/dependencies/<上游名>.md` 各有一份**依赖声明**，`<上游名>` 取依赖清单文件里的包名 / 模块名，服务类上游取 registry 里的仓库名。 |
| FR-011 | 声明的最小五项：**上游与当前锁定版本**；**用到的部分**（对外接口名清单，与上游 CHANGELOG / 卡片同名）；**调用点**（每个接口至少一处 `文件:行`）；**注意事项**（隐含假设、默认值依赖、踩过的坑；没有写 `无`）；**确认时间**。内容 MUST 从本项目源码读出，MUST NOT 从上游文档或 PRD 抄。 |
| FR-012 | 补写义务与卡片同构：本次任务读到或改到了对某个上游的调用、而该上游还没有声明时，MUST 在本次任务内补上并随分支提交，MUST NOT 顺延；只增不减、与源码不符就地修正并更新确认时间。 |
| FR-013 | 上游升级的触发条件：本次任务要把某个上游升到新版本（依赖清单文件里该上游的版本号变化，或服务类上游宣告了新版本）。命中时 MUST 按顺序处置：①读本项目对它的声明；②读上游仓库根 `CHANGELOG.md`（SDK 包内若随包分发同一份文件亦可）里旧版本→新版本之间的 `不兼容` 条目；③与声明的「用到的部分」取交集；④交集为空一句话告知拍板人后继续，非空则每条 MUST 进 spec 的〈既有系统清单〉并带调用点 `文件:行`，随本次改动一并改调用；⑤升级完成后更新声明里的版本与确认时间。 |
| FR-014 | 兜底一：上游没有 `CHANGELOG.md` 或缺该版本区间时，派 **1 个**子代理看上游两个版本之间的 diff，**范围限于声明「用到的部分」列出的接口**，MUST NOT 全量看 diff。 |
| FR-015 | 兜底二：本项目对该上游没有声明时，MUST 先按上下文卫生规则 4 外包一次调用点扫描并当场补声明，再回到 FR-013 的路径；MUST NOT 在主会话裸 grep。 |
| FR-016 | `ctx init` 完整骨架增加 `engineering-context/dependencies/` 目录（含 README stub，说明文件命名与五项）；`--minimal` 不生成它。既有项目缺该目录时，首次补声明时直接建目录，MUST NOT 要求重跑 `ctx init`、MUST NOT 建迁移指南。 |
| FR-017 | 新增模板 `assets/context-layer/dependency.md`，与 `commands.js` 内的 stub 保持精简副本关系（既有的模板↔stub 同步约定）。 |
| FR-018 | 上述判据同步到全部复述落点（§2.2）；Lean 自足册每条要点带来源锚点；注入目标项目的 `base.md` 就地写全，MUST NOT 改成指名引用。 |
| FR-019 | 新增机器闸 `test/change-awareness.test.mjs`：K 侧断言各落点在场（五类闭集、三项必填、忠实轴对照句、完成门核对句、五项、处置顺序），P 侧断言 `ctx init` 真生成 `dependencies/` 且 stub 与模板一致；闸 MUST 做反向自检。 |
| FR-020 | 本仓库自身落一份仓库根 `CHANGELOG.md`，`## 未发布` 下记本次改动；2.17.0 之前的历史不回填，节首一句话指向 `docs/spec/` 与 git tag。 |

**编号规则（MUST）**：格式为 `FR-###` / `AC-###`，三位零填充；永不复用、永不重排；删除的原地保留编号并改写成"**已撤销** —— 原因"。`FR-###` 与 §6 的 `Invariant N:` 是两套独立编号。

## 2. 数据模型 / 数据结构

本次不引入程序数据结构。引入两份**文件级契约**：

### 2.1 `CHANGELOG.md`（仓库根）

```markdown
# CHANGELOG

> 每次合并到主分支写一条；`不兼容` 条目以对外接口名开头。规则见 ai-dev-workflow 的 `references/core/代码事实纪律.md` §10。

## 未发布

### 不兼容
- `createOrder(payload)` —— 旧：第二个参数 `opts.currency` 可省略、默认 CNY；新：`currency` 为必填的第一层字段；迁移：调用方把 `opts.currency` 提到 `payload.currency`，未传时会得到 `400 order_currency_required`。

### 新增
- `listOrders` 支持 `cursor` 分页。

### 变更
### 修复
### 内部
- 订单模块内部的重试封装换成共享实现，不改任何对外行为。

## 0.9.2 — 2026-09-01
...
```

- 五个分类标题在 `## 未发布` 下**固定存在**（空的也留着），使追加时不必判断该不该新建小节。
- 发版后的历史节 MUST NOT 再改；改错只能在 `## 未发布` 下补一条 `修复`。
