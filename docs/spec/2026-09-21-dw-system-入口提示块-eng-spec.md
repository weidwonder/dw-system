# dw-system_技术 Spec — 入口文件的 dw-workflow 提示块

> 本文按 RFC 2119 解释 MUST / MUST NOT / SHOULD / MAY。

## 0. 阅读导引

- **一句话目的**：在目标项目的 `AGENTS.md` / `CLAUDE.md` 顶部放一段两行的提示块，让零上下文的 agent 一打开项目就知道"动手前先加载 `dw-workflow`"，不必依赖 skill 自己的 description 被触发。
- **端到端场景**：
  1. 开发者在一个已装本体系、`CLAUDE.md` 里已有 `dw-workflow` 标记块的项目里重跑安装命令 → 安装器在 `CLAUDE.md` 顶部幂等写入提示块（文末的标记块照旧同步）→ 下次会话里 agent 读 `CLAUDE.md` 第一屏就看到"起步先加载 dw-workflow"。
  2. 全新项目、两个入口文件都不存在，开发者在会话里唤起 skill → 初始化按现有流程问协作面 → 在 worktree 内写标记块（`CLAUDE.md` 与 `AGENTS.md` 各一份，本次不改）→ 提示块只写进 `AGENTS.md`。
  3. 项目只有 `AGENTS.md`（Codex 单侧项目）→ 提示块写 `AGENTS.md`，`CLAUDE.md` 由标记块同步照旧创建、其中没有提示块。
  4. 项目里两个入口都没有 `dw-workflow` 标记块 → 安装器一如既往什么都不写，提示块也不写。
  5. 重复安装 / 使用者手改过提示块正文 → 就地替换回当前版本的正文，块的位置不动，MUST NOT 追加第二份。
- **核心流程图**：
  ```mermaid
  flowchart TD
    A[安装器 main] --> B{两个入口里有 dw-workflow 标记块吗}
    B -->|没有| Z[不写标记块 也不写提示块]
    B -->|有| C[按现行规则组装标记块 两入口都写]
    C --> D{该入口在本次写入前就存在吗}
    D -->|存在| E[顶部幂等写入提示块]
    D -->|本次才被创建| F[只写标记块 不写提示块]
    G[skill 初始化 第 5 步] --> H[写标记块到两个入口]
    H --> I{写入前哪些入口已存在}
    I -->|存在若干| J[给这些入口写提示块]
    I -->|一个都不存在| K[只给 AGENTS.md 写提示块]
  ```
- **决策表**：

  | 写入前的入口状态 | 标记块落点（不变） | 提示块落点 |
  |---|---|---|
  | `AGENTS.md` 与 `CLAUDE.md` 都存在 | 两个都写 | 两个都写 |
  | 只有 `CLAUDE.md` 存在 | 两个都写（`AGENTS.md` 被创建） | 只写 `CLAUDE.md` |
  | 只有 `AGENTS.md` 存在 | 两个都写（`CLAUDE.md` 被创建） | 只写 `AGENTS.md` |
  | 两个都不存在（仅 skill 初始化会遇到） | 两个都写（都被创建） | 只写 `AGENTS.md` |
  | 两个入口都没有 `dw-workflow` 标记块（安装器路径） | 不写 | 不写 |
  | 两个入口是同一个实体文件（软链接） | 只写一次 | 只写一次 |

## 1. 范围

- **做什么**：新增一对提示块标记与正文片段；安装器在同步标记块时一并幂等维护提示块；skill 初始化在注入标记块时一并写提示块；本仓库自己的 `CLAUDE.md` 同样加上提示块；配套机器闸、卡片、CHANGELOG、README 同步。
- **不做什么**：
  - **不改 `dw-workflow` 标记块的任何既有行为**：仍是两个入口都写、字段仍以 `CLAUDE.md` 为准、首次写块仍归 skill 初始化（安装器只在已有块时同步，cite: `cards/dw-system/标记块与旧版迁移.md#权威实现与对外接口` @2026-09-17）。
  - 不新增任何命令行开关来控制提示块的开关或位置（YAGNI）。
  - 不为提示块做 `LEGACY` 迁移：本次是全新标记，更名前的安装里不存在它。
  - 不改 skill 自身的 `description`，不改 skill 的触发方式。
  - 不因为提示块而改变"哪个入口的字段说了算"的收敛规则。
- **既有系统清单**：

  | 既有模块 / 机制 | 从哪知道它的 | 本次可能怎么碰到 | 卡片补了吗 |
  |---|---|---|---|
  | 标记块起止与幂等替换 `upsertMarkedBlock` / `getMarkedBlock` / `removeMarkedBlock` | cite: `cards/dw-system/标记块与旧版迁移.md#权威实现与对外接口` @2026-09-17；`install.mjs:1928`、`install.mjs:1966` | 提示块复用同一套幂等写块工具 | 已有卡片，本次刷新 |
  | 首次写块归 skill 初始化，安装器只同步已有块（`install.mjs#main` 里 `workflowSettings` 为空即不写） | cite: 同上；`install.mjs:599-615`（`resolveWorkflowSettings` 收到 null 返回 null） | 提示块沿用同一条界线 | 已有卡片，本次刷新 |
  | 入口软链接解析与共用实体判定 `assertWritableEntry` / `sharedEntry` | `install.mjs:387-419`、`install.mjs:1725-1728` | 提示块写入必须落到链接目标，两入口同实体时只写一次 | 已有卡片（安装主干） |
  | 标记块正文片段 `assets/config-snippets/base.md` + `collab-<协作面>.md` | cite: `cards/dw-system/标记块与旧版迁移.md#权威实现与对外接口` @2026-09-17 | 提示块正文同样作为片段随 skill 分发 | 已有卡片，本次刷新 |
  | skill 初始化第 5 步注入两个入口 | `dw-system/skills/dw-workflow/references/init-初始化.md` §流程 第 5 步 | 该步追加提示块的写入规则 | 不适用（skill 文档判据的家就是 skill 文档） |

### 1.1 功能需求

| 编号 | 需求 |
|---|---|
| FR-001 | 提示块是一对新的幂等标记 `<!-- dw-workflow:hint:start -->` / `<!-- dw-workflow:hint:end -->` 包住的一段引用文字，点名要加载的 skill 是 `dw-workflow`，并指出详细字段在文末的 `dw-workflow` 标记块里。正文 MUST 不超过 3 行。 |
| FR-002 | 提示块 MUST 写在入口文件的最开头（第一行起）；文件已有内容时原内容整体下移，MUST NOT 改动原内容。 |
| FR-003 | 提示块的落点按 §0 决策表：写入前已存在的入口文件都写；两个都不存在时只写 `AGENTS.md`；两个入口是同一实体文件时只写一次。 |
| FR-004 | skill 初始化在 worktree 内注入标记块时，MUST 按 FR-003 一并写入提示块。 |
| FR-005 | 安装器 MUST 只在"本次确实要为该入口写 `dw-workflow` 标记块"时才写提示块；两个入口都没有标记块因而不写块时，MUST NOT 写提示块。 |
| FR-006 | 重复安装幂等：已有提示块时就地替换块内正文，块的位置保持不变，MUST NOT 追加第二份、MUST NOT 把块移到别处。 |
| FR-007 | 安装器的计划输出（含 `--dry-run`）MUST 列出提示块会写进哪些入口文件；`--dry-run` MUST NOT 落盘。 |
| FR-008 | 写入后 MUST 重新读回文件校验提示块存在且正文与预期逐字相等，不相等即报错中止（与标记块写后核对同档）。 |
| FR-009 | 本仓库自身的 `CLAUDE.md` MUST 按同一规则带上提示块。 |

## 2. 数据结构

无持久化数据结构。新增两个模块级常量与一份正文片段：

| 名字 | 值 / 位置 |
|---|---|
| `WORKFLOW_HINT_START` | `<!-- dw-workflow:hint:start -->` |
| `WORKFLOW_HINT_END` | `<!-- dw-workflow:hint:end -->` |
| 正文片段 | `dw-system/skills/dw-workflow/assets/config-snippets/hint.md`，块内层即提示正文，与标记块片段同一取法 |

## 3. 接口契约

对使用者可见的契约只有三条：

1. 入口文件顶部出现的那对标记与其间的正文（FR-001、FR-002）。
2. 安装器计划输出里新增的一行（FR-007）。
3. `install.mjs` 的命令行参数不变。

## 4. 核心逻辑

1. **组装**：`buildWorkflowHintBlock(skillsRoot)` 读 `hint.md`，取其标记块内层，用 `WORKFLOW_HINT_START` / `WORKFLOW_HINT_END` 包住返回。片段缺失（裁剪过的源）时返回 null，本次不写提示块，也不报错——与标记块片段缺失时的宽容度一致。
2. **落点**：在安装器读取 `initialClaudeRaw` / `initialAgentsRaw` 的同一处记下两个入口在写入前是否存在（`fs.existsSync` 判的是解析软链接后的实体路径），算出提示块目标集合。
3. **写入**：复用现有的幂等写块工具，在该入口写标记块的同一次文件改写里完成；块不存在时插到文本最前面，存在时就地替换。
4. **校验**：写完重新读回，提示块正文与预期逐字相等（FR-008）。
5. **skill 初始化**：`init-初始化.md` 第 5 步追加同一套规则，判据与安装器同源，两边 MUST NOT 各写一套。

## 5. 错误处理

| 情形 | 处置 |
|---|---|
| `hint.md` 片段不存在 | 不写提示块，安装继续，计划输出里不列这一行 |
| 入口文件是断链软链接 | 沿用 `assertWritableEntry` 的既有行为：在复制任何 skill 之前中止，目标项目零改动 |
| 写后校验不通过 | 报错中止，与标记块写后核对同档 |

## 6. 不变量

- 提示块与标记块的正文 MUST NOT 互相复述具体规则：提示块只说"去加载 `dw-workflow`"和"字段在文末标记块里"，规则的家仍在各 skill。
- 安装器 MUST NOT 成为"首次写块"的路径：没有标记块的项目，安装器仍然一个字也不写进入口文件。
- 提示块正文 MUST NOT 引入新的 MUST 规则清单，只允许一条"起步先加载"。

## 7. 可观测性

安装器计划输出与完成输出各一行，说明提示块写进了哪些入口文件。
