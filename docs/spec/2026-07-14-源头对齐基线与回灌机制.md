# 源头对齐基线与回灌机制

> 本体系裁剪自若干上游参考体系（仅维护者本地持有，不入库、不公开）。这些源头**仍在演进**——2026-07-06 首版裁剪后，一次对齐审计发现多处缺口本质是"裁剪基线定格在某快照，之后源头继续更新未回灌"。本文规定定期 diff 回灌机制，避免再次静默落后。
>
> **基线表不入本仓库**：每个被裁剪源文件的仓库名、文件名与基线 commit 属上游内部信息，登记在本地不入库的 `orgin/回灌基线.md`（`orgin/` 已被 `.gitignore` 忽略）。本文只保留机制与决策留痕。

## 1. 回灌机制（每季度或源头有大改时执行一次）

1. 对基线表（`orgin/回灌基线.md`）中每个源文件，在源头仓库跑 `git log <上次基线 sha>..HEAD -- <文件>`；有新提交则读 diff。
2. 判断新增内容是否属本体系范围（技术栈无关、非上游专有）：是 → 回灌进对应 ai-dev-system 文件；否 → 在下面"有意不回灌"登记原因。
3. 更新基线表的基线 sha 为当前源头 HEAD。

## 2. 裁剪基线表

见本地 `orgin/回灌基线.md`（不入库）。表结构：`源文件 | 源仓库 | 基线 commit | 本体系对应`，覆盖 14 个被裁剪源文件。

## 3. 有意不回灌（out-of-scope，非遗漏）

以下源头内容经判断**不纳入**本体系分发，属有意裁剪（补记本表即为决策留痕，呼应设计文档 §9 非目标）：

- **完整 Agent 平台重型骨架**（agent loop 状态机、Autonomy Levels 全表、trajectory eval 平台那套指南全量）：高度贴具体平台，超出"技术栈无关内核"定位。本体系只在 `AI-LLM-overlay.md` 给平台无关的最小 agent 契约（判定边界 + 自主级别/审批闸门要点 + 继承声明 + 缺口清单），覆盖"给已有 agent 加能力"的 80% 日常；平台核心改造应参照使用方团队自有的重型规范。
- **Agentic / Agent 能力扩展产品 PRD 的整套模板**：`ai-prd` 只在分流表声明边界，指引使用方参照其团队自有的 Agentic 产品 PRD 规范，不随包分发重模板。
- **上游在线 MCP 的部分方法**（跨会话变更感知 / 服务 README / 技能发现 / 打包快照信息）：MCP→ctx 有意改形态（设计 D3/D8）。跨会话变更感知改用 `git diff engineering-context/`（`references/core/代码事实纪律.md` §8 新鲜度纪律）；服务级 README 信息由每仓 card 兼职；技能发现在原生 SKILL 分发下无对应；打包快照信息因 ctx 读活文件而不需要。
- **上游专有基建的排障手册**：贴其具体基建，非通用内容。设计文档 §9 已列。
