# 源头对齐基线与回灌机制

> 本体系裁剪自三个上游源头（`上游开发指南` + `engineering-context` + `doc-principles`）。这些源头**仍在演进**——2026-07-06 首版裁剪后，一次对齐审计发现多处缺口本质是"裁剪基线定格在某快照，之后源头继续更新未回灌"。本文记录每个被裁剪源文件的**基线 commit**，并规定定期 diff 回灌机制，避免再次静默落后。

## 1. 回灌机制（每季度或源头有大改时执行一次）

1. 对下表每个源文件，在源头仓库跑 `git log <上次基线 sha>..HEAD -- <文件>`；有新提交则读 diff。
2. 判断新增内容是否属本体系范围（技术栈无关、非 上游 专有）：是 → 回灌进对应 ai-dev-system 文件；否 → 在下面"有意不回灌"登记原因。
3. 更新本表的基线 sha 为当前源头 HEAD。

源头仓库 HEAD（本次回灌基准，2026-07-14）：`doc-principles@66d1ad5`、`engineering-context@a094f11`。
