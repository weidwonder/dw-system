- **Issue / 链接**：N/A（用户口述需求，2026-08-25）
- **Owner**：weidwonder
- **写作进度**：Done
- **Triage 复核**：AI/LLM 行为？否 鉴权/安全/设备？否 跨服务/迁移/不可逆？否 指标/规则/对外承诺？否
  - borderline 记录：第 4 问"对外承诺"曾倾向"是"——本次改变了已安装项目的原型产出契约。但它是**纯增量**（旧原型文件照常打开、照常有效，不要求任何回填），且没有任何跨服务或不可逆面，故判否走 Lean。

## 改什么（现状 → 期望）

现状：`ai-prd` 的 UI 原型纪律要求"面向 PM 的解释、标注、设计理由 MUST 放在画布外的设计说明栏"，但说明栏是一整段自由文本，**说不清指的是哪个控件**。于是 agent 反复把针对某个元素的说明直接画进屏幕里，原型与设计内容混在一起——这是一条**只有禁令、没有出口**的规则，禁令挡不住需求。同时用户读原型只能在对话里口述意见，指不准元素、也留不下痕迹。

期望：模板内置一层批注框架，把两侧需求各给一个标准载体，且不增加 agent 的 token 负担。

**本次功能需求**：

- FR-001 — 模板内置 AI 侧元素批注：给元素加一个属性即可在其右上角挂一枚小气泡，悬浮才展开说明文字；另有一种视觉区分"待用户拍板"的项。
- FR-002 — 模板内置用户侧批注工具栏：画布顶端常驻，可进入拾取模式点选任意界面元素写意见，可改可删。
- FR-003 — 用户批注精准绑定到具体元素与所在屏（多屏原型可区分），AI 可据此定位。
- FR-004 — 工具栏提供一个全局反馈入口，收针对整份原型、不指向单个元素的意见。
- FR-005 — 批注随时修改、随时保存，并以 AI 可读的形式落在原型文件内。
- FR-006 — 框架整体封装成固定实现，agent 产出原型时不必读、不必写框架代码；取用户反馈时不必通读整份 HTML。
- FR-007 — 框架不破坏原型既有硬约束：单文件、零外链、可离线打开。
- FR-008 — 下游（`ai-dev-workflow`）读原型时知道气泡里的说明属于行为契约，并知道批注块的读法。
- FR-009 — 原型有一套开箱可用的中性视觉基线与常用控件样式，产出的原型不必自己攒样式；该基线 MUST NOT 构成对使用方项目技术栈的任何要求，也 MUST NOT 假设产品有暗色模式（2026-08-26 按真跑反馈收窄：容器原本带明暗两套 token 与切换按钮，但多数项目没有暗色，容器的能力会被误读成对内容的要求）。
- FR-010 — 容器**不含任何示例业务内容**，且产出原型时不需要读容器：要填的位置与可用样式全部由纪律以插槽契约的形式给出。
- FR-011 — 用户第一次写批注时，容器 MUST 主动说明「批注要存进文件、AI 才读得到」，不能指望用户从工具栏按钮名猜出用途。
- FR-012 — 纪律教给 agent 的取批注命令 MUST 在容器上真能跑通；批注文本是用户自由输入，MUST NOT 因其内容破坏数据块。
- FR-013 — 把原型交给用户看的默认路径 MUST 是**零操作**的：批注自动写回原型文件，用户不需要为「让 AI 读到批注」点任何东西。手动授权与下载副本只作降级，MUST NOT 当默认。
- FR-014 — 建原型与改稿 MUST 有一条工具化路径（`init` / `screen` / `slot`）：agent 不手工复制容器、不逐行替换、不为改一处而把整份原型读进上下文；改稿 MUST NOT 丢掉用户已写的批注与元素锚点（2026-08-26 评审发现：只有"复制容器 + 填插槽"这一条路时，改稿要么整份重读、要么重新生成而抹掉批注，两条都不可接受）。
- FR-015 — 交付前的结构自检 MUST 由工具执行（`check`）：哪些 class 有子结构要求、哪些交互靠哪个属性、图标 id 有没有拼错、内联样式有没有写死颜色——这类知识 MUST 收进工具，MUST NOT 要 agent 靠记住纪律正文来避开。
- FR-016 — 取批注 MUST 有**单一命令入口**（`annotations`）：一次给出用户逐元素批注、全局反馈与 AI 侧 `data-anno` 说明（含 `question` 待拍板项），每条带所在屏与元素；**真正打开原型的每个执行点**都 MUST 就地给出这条命令，MUST NOT 只在总纲/自足册里写一遍（2026-08-26 评审发现：Step 1/4/8 是下游真正打开原型的地方，此前整篇零处提到批注）。
- FR-017 — 预览服务的生命周期 MUST 由 AI 持有：AI 后台起、AI 在派复核子代理之前停，MUST NOT 要求用户自己起服务或自己按 Ctrl+C。
- FR-018 — 用户写的批注与 `data-anno-user` 锚点是需求的一部分，MUST 随原型整份落盘进 `docs/spec/`；`data-anno-kind="question"` 的待拍板项 MUST 在落盘确认门逐条摆给用户，MUST NOT 跟着原型静默进库。
- FR-019 — 框架 MUST NOT 成为某类原型风格的阻碍：组件表覆盖不到的控件样式、hover、动画、媒体查询 MUST 有一个专门插槽（`custom`）承接，且它 MUST 排在设计系统之后以便覆盖。

## 为什么

"禁止把说明画进界面"这条规则从 1.x 起就在，agent 仍反复违反。原因不是规则不够严，而是**没有既能指向具体元素、又不占界面版面的表达方式**——说明栏只能整段写，写完读者对不上是哪个控件，于是最省事的做法就是画在旁边。给出口比加禁令有效。

用户侧同理：原型是"要被工程读的行为契约"，而用户对它的意见此前只能落在对话里，随上下文一起丢失，也无法精确到元素。

## 影响范围 / 不做什么

- 影响：只影响 `ai-prd` 产出新原型的方式，与 `ai-dev-workflow` 读原型的方式。
- **不做**：不回填存量原型文件（旧原型没有框架也照常有效，见兼容取舍）；不改 PRD「UI 原型」五项表的项名；不引入任何构建步骤或第三方依赖；不把批注做成跨用户共享（它是单机单文件的本地机制）。
- 关键 NFR：框架 MUST 不引入任何外部资源（原型的零外链约束是硬线）；框架的全部运行时 DOM MUST 可从回写内容中剥离干净，否则文件会越写越脏。
- 既有系统清单：
  - `assets/templates/ui-prototype.html` 的既有结构（`.stage` / `.devices` / `.device-wrap` / `.device-name` / `.screen` / 状态切换脚本）—— 出处：该文件本身，本次读过全文。框架依赖 `.device-wrap` + `.device-name` 取屏幕名、依赖 `.devices` 作为画布范围。
  - `UI原型纪律.md` §2/§6 的零外链与"全文无 `【`"两道静态自检 —— 出处：`ai-dev-system/skills/ai-prd/references/UI原型纪律.md` §6。框架因此 MUST NOT 用 SVG data URI（会引入 `xmlns` 的 `http://` 串），拾取光标改用跟随鼠标的 DOM 元素实现。
  - `test/lean-selfcontained.test.mjs` 的自足册覆盖率闸 —— 出处：该文件 §Invariant 4。给总纲某小节新增 MUST 会同时新增一条 Lean 覆盖义务。
- 本次补的卡片：无需新补（本仓库是方法论分发包，`engineering-context/` 未建；改动全在 skill markdown 与模板内，无跨模块代码事实）。

## 兼容取舍（用户拍板，定稿前必填）

- **存量原型文件没有批注框架** —— 谁在依赖：已安装本体系的项目里 `docs/spec/*-prototype-*.html` —— 决定：**不回填，纯增量**。旧文件照常打开、照常是现行界面依据；下次该界面被改动时由新原型接替，新原型自带框架。确认于 2026-08-25。
- **批注写回文件依赖浏览器能力** —— Chrome / Edge 用 File System Access 自动写回；Safari / Firefox 只能"下载副本后覆盖原文件"或"复制 JSON 粘回对话"。决定：**三级自适应降级，不为兼容降低主路径体验**；状态灯显式告诉用户当前批注有没有落到文件里。确认于 2026-08-25。

## 真跑发现（2026-08-26，四个都不是当时的机器闸能发现的）

1. **跟随光标的气泡藏不住**（已修，补闸 AC-020）：`.anno-cursor` 写了 `display:flex`，作者样式压过 `[hidden]` 的 UA 默认 `display:none`，于是 `cursor.hidden = true` 全程无效——取消批注后气泡残留在页面上。**教训**：凡是用 `hidden` 属性控制显隐、自身又设了 `display` 的元素，都要显式写 `[hidden]{display:none}`。
2. **取批注的命令把自己废掉了**（已修，补闸 AC-017）：容器注释里写了取段命令作示例，而命令文本本身含该区结束标记的字样；按行取段的命令扫到这一行就停，只取回三行注释、解析不出 JSON。**教训**：按标记取段的区域内，任何位置都不能出现该区结束标记的字样——连「教人怎么读」的注释也不行。修这条时又在 JS 注释里写了一次字面的脚本结束标签，当场把那段脚本闭合掉、语法检查立刻判红——同一个坑连踩两次，足见其隐蔽。
3. **批注文本能破坏数据块**（已修，补闸 AC-018）：批注是用户自由输入，内容里出现脚本结束标签会让 JSON 块提前闭合，整份文件的批注报废。写入前把 `"<" + "/"` 转义即可，JSON 的 `\/` 解析回来仍是 `/`。
4. **「连接文件」没人看得懂**（已修，新增 FR-011）：按钮名没能自解释，用户不知道它做什么用。改为「保存到文件」并加悬浮说明，更关键的是**第一次写批注时主动弹一次说明**——「浏览器不能擅自写硬盘」这件事必须在用户第一次需要它的那一刻讲，而不是指望他去猜工具栏。
5. **「为什么还要用户选文件」**（已修，新增 FR-013）：用户指出——原型是 agent 生成的、路径 agent 自己知道，凭什么还要用户在弹窗里再选一次。**浏览器不让网页未经手势授权写本地文件是硬约束，页面知道自己的路径也拿不到写句柄**，但这不构成"用户必须点两次"的理由：换 http 打开就没有这层限制。于是新增 `scripts/preview.mjs`（零依赖、只绑回环、只服务这一个文件、校验 Host 挡 DNS rebinding、payload 不像原型就拒绝、原子写盘），页面检测到自己是被 http 提供的就直接 POST 回写，全程零操作；`file://` 直接打开时才降级到手动授权/下载副本。**教训**：把平台限制原样转嫁给用户，往往说明还没找到绕开它的那条路。
6. **光标气泡停在上一次位置**（已修）：进入拾取模式时鼠标正停在刚点过的按钮上，不产生 mousemove，气泡就保持上次坐标直到鼠标移动。改为全程记录指针位置，进入拾取时先摆正再显示。

## 评审发现（2026-08-26，三个子代理复核 + 一次零上下文实测）

6. **封装只做了一半**（已修，新增 FR-014/FR-015）：纪律教的是"复制容器再填插槽"，那是**建**的路径；**改**的路径不存在——改一处要么整份读进上下文（几万 token），要么重新生成而抹掉用户已写的批注。零上下文实测里这条当场变成死锁：用户批注完提了意见，agent 无路可走。**教训**：封装一个产物，"怎么建"与"怎么在不丢已有内容的前提下改"是两件事，只做前一件等于没封装。
7. **判据写在总纲，读者却不在那里**（已修，新增 FR-016）：批注要求只写在 `00-流程总纲.md` 与 `路径-lean.md`，而真正打开原型的是 Step 1 / Step 4 / Step 8——那三处整篇零处提到批注。**教训**：一条"读到 X 时要做 Y"的判据，MUST 写在真会打开 X 的那个执行点上；写在总览里等于写给一个当时不在场的读者。
8. **纪律里的结构知识 agent 记不住**（已修，新增 FR-015）：`.kv-row` 要配 `<dt>`、状态层必须是 `.screen` 直接子元素、tab 要 `aria-selected`——写错了页面照样打开、只是版式塌掉，零报错。**教训**：这类"错了不报错"的知识 MUST 由工具检查，纪律正文只负责说清"跑哪条命令"。
