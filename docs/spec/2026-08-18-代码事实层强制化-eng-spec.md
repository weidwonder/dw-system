# 代码事实层强制化 eng-spec（2.1.0）

## 1. 背景与决策

2.0.0 把项目形态拆成两个正交维度：**协作面**（配置字段）与**能力位**（运行时探测）。
能力位又分两位：**图谱位**（`.codegraph/codegraph.db`）与**权威位**（已填写的
`capability-registry.md`）。权威位未启用的项目允许直读源码，卡片是"建议补建"而非必备。

用户决策（2026-08-18）：**装了这套体系的项目一律按"必须有卡片"对待，不再分档。**
卡片**渐进补齐**——初始化时只建骨架，之后"要用某个模块的事实时先查卡片；没有卡片就
读源码，读完把卡片补上"。

决策理由（用户原话的工程表述）：分档的判据永远滞后于项目实际风险。一个人维护的十万行
遗留系统被判成"没有资产 → 默认走 Lean → 直接 grep 旧代码"，正是这套体系最初要消灭的
失败模式。与其造一套"什么时候该建资产"的判据（那正是 `资产补建信号.md` 在做的事，
且它只产出建议、可被用户一次性拒绝），不如取消这个选择：**卡片是地基，不是升级项。**

## 3. 新的核心纪律（`core/代码事实纪律.md`）

一句话规矩：

> **要用某个模块的事实，先查卡片；没有卡片就读源码，读完把卡片补上。**

### 3.1 取事实的固定顺序（MUST）

1. `ctx find-scenes <关键词>` —— 未限定单仓时**必须**先取端到端全景（排序铁律，2.0.0 已有，保留）
2. `ctx discover "<意图>"` —— 意图 → 应加载的 card 清单 + out-of-scope 警告
3. `ctx get-card <repo> [域]` —— 收窄到具体 card
4. `ctx search-semantic "<自然语言>"` —— discover 未命中时的兜底

命中 → 事实带 cite（path#anchor @确认时间），**无 cite 视为幻觉**（2.0.0 已有，保留）。

### 3.2 未命中时（本次变更的核心）

未命中不再意味着"这个项目没有权威位、可以直读"。未命中只意味着**这个模块的卡片还没建**。
处置 MUST 按序：

1. **读源码建立事实**。定位方式按项目实际：图谱位可用 → 走代码图谱；不可用 → 按
   `core/上下文卫生.md` 规则 4 外包给子代理。**MUST NOT 在主会话裸 grep 全仓。**
2. **把读到的权威事实补成卡片**，随本次任务分支提交。补卡是本次任务的一部分，
   **MUST NOT 顺延到"以后有空再补"**。
3. 补完的卡片即成为后续事实来源，本次任务后续引用它时照常带 cite。

### 3.3 补一张卡片的最小形态（MUST）

新建 `engineering-context/cards/<repo>.md`，或在既有卡片里追加一个 `## <域>` 段。最小内容四项：

| 项 | 写什么 |
|---|---|
| 职责 | 这个模块负责什么业务能力，一句话 |
| 对外接口 | 本次真正读到并核对过的接口 / 字段 / 事件，每条带 `文件:行` |
| 陷阱项 | 相似但不该用的旧实现；确实没有就写 `无` |
| 确认时间 | 本次读源码的日期 |

同时在 `engineering-context/capability-registry.md` 追加一行（三列即可）：
`Capability | 权威实现 | 陷阱项`。

**MUST NOT 为了凑满模板把没核对过的字段填上**——没读到的就不写，写了就等于制造过期权威。

### 3.4 只增不减（MUST）

- 卡片库**只增不减**：MUST NOT 因为"这次没用上"删除既有卡片内容。
- 发现既有卡片与源码不符 → **就地修正并更新确认时间**，MUST NOT 保留两份互相矛盾的说法。
- 真相方向铁律不变：card 事实 **MUST 以合入后的源码为准，MUST NOT 从 PRD 生成**。

### 3.5 新鲜度（保留 2.0.0 口径）

改动触碰**权威面**（canonical 接口签名、废弃标记、路由/配置版本、DB schema、兼容窗口）
—— 哪怕只有 3 行 —— MUST 刷对应卡片。纯内部实现改动 MAY 不刷。判据是**是否碰权威面**，
不是改了多少行。

## 4. 路由逻辑的新形态（`SKILL.md`）

三步不变，但第 ① 步内容收缩：

```
1. 【探测】只探测一件事：项目根下 .codegraph/codegraph.db 是否存在 → 图谱位。
   探测不到就按没有算，MUST NOT 阻断流程。
   **不再探测 engineering-context**——它是必备资产，不是可选开关。
   缺失时由初始化补建（在 worktree 内），不影响本次分流。
2. 【读标记块】不变（只读、不落盘）。
3. 【加载】常驻集合里加入 **代码事实纪律.md**——这是本次改动在加载侧的全部内容。
   再追加：协作面必选一份；图谱位命中则加 capability/graph.md。
   （2.1.0 当时的常驻集合是 core 七篇：00-流程总纲 / worktree开发纪律 /
    spec写作纪律 / 文档治理 / 用户沟通纪律 / 上下文卫生 / 代码事实纪律。
    **2.5.0 起该集合已改**：收缩为六份并分两批取，worktree开发纪律 /
    spec写作纪律 / 文档治理 三篇移出常驻、改按 SKILL.md〈加载点清单〉触发时取，
    代码事实纪律仍常驻但按节读。**MUST NOT 把上面这七篇当成现行加载契约照抄**，
    现行契约在 2026-08-23-渐进式披露与需求追溯-eng-spec.md §4。
    本次的结论——代码事实纪律必须常驻——未变。）
   core/engineering-context设计.md：要动 engineering-context 的**结构**
   （建场景蓝图 / 维护探针集 / 设计 registry 字段）时才读；日常补一张卡片
   只需 代码事实纪律 §4.1 的最小形态（= 本 spec §3.3 定义的那四项）。
```

## 5. 分流默认倾向的新形态（`00-流程总纲.md`）

四问全否之后，**无条件**适用：

> **影响面说不清时，MUST 升级到完整流程出 Overview；说得清才走 Lean。**

"说不清"判据（命中任一即算），四条分两批：

| # | 判据 | 什么时候过 |
|---|---|---|
| 1 | 本次要改的能力在 registry 里跨 ≥2 个权威仓库 | Triage 当场 |
| 2 | `ctx discover` 给出 out-of-scope 警告 | Triage 当场 |
| 3 | 关键事实里有任何一条**给不出出处**（cite 或 `文件:行`）| 回溯触发：Step 1 进行中命中即当场升级 |
| 4 | `discover` / `search-semantic` 都收不窄，且读源码后仍说不清模块边界 | 回溯触发 |

**判据 3 在新架构下 MUST NOT 恒为真**：卡片没建的模块，读完源码补完卡片就有出处了。
它命中的是"读了源码也说不出这条事实从哪来"，不是"卡片里没有"。旧版本正是因为
"没 registry 就永远没 cite"才把这四条限定在权威位启用时——限定条件现在消失，
但判据 3 的措辞 MUST 改成"给不出出处"，否则会把每个新项目都判成说不清。

**MUST NOT 从"只有我一个人"推出"默认走最短流程"**（保留）。

## 6. 初始化的新形态（`init-初始化.md`）

第 3 步探测表：删除"能力位"行的权威位部分，改为只探测代码图谱。**另保留一次纯存在性检查**（`capability-registry.md` 在不在）供第 5b 步判断要不要跳过——它只喂 5b，MUST NOT 参与路由判断、MUST NOT 据此问用户。

第 5 步注入之后新增 **第 5b 步**（在 worktree 内执行）：

> 项目根下不存在 `engineering-context/capability-registry.md` 时，跑 `ctx init`
> 建**完整骨架**（registry / cards/ / scenes/ / probe-set / glossary / README / .gitignore），
> 随本次任务分支提交。**MUST NOT 跑 `--minimal`**——卡片目录必须从第一天就在，
> 否则第一次补卡的 agent 还要先决定目录放哪。
> 骨架里只有模板占位、没有真实数据行，这是**正常起步状态**，MUST NOT 因此告警或提示用户。

第 4 步"MUST NOT 问的三类"保留并加强：**MUST NOT 问用户"要不要建 engineering-context"**
——它是必备资产，不是选项。

机制随之消失。按本仓库自身纪律（被取代的旧逻辑当场删，不留描述性残留），
MUST NOT 保留"该机制已废弃"这类残留说明。

## 8. 兼容取舍

| 被改变的既有行为 | 结论 | 理由 |
|---|---|---|
| 已安装项目下次唤起 skill 时会新建 `engineering-context/` 骨架 | **不兼容**（直接切换） | 骨架是幂等的、只增文件不改既有内容；随任务分支提交、可评审可回退 |
| 旧标记块 `mode` 墓碑字段 | **保持** 2.0.0 口径，`3.0.0` 移除 | 本次不动，避免把两件事混在一起 |
| `docs/report/资产补建信号.md` 已存在的项目 | **不兼容**：不再读、不再写 | 已有账本作为历史记录留在项目里，本体系不再维护它；迁移指南说明可自行删除 |
| `ctx` CLI 的命令、参数、输出格式 | **完全兼容**，不改 | 探测判据变了，CLI 本身没变 |
| `capability-registry.md` 的解析规则（跳过 `【】` 占位行）| **完全兼容**，不改 | 骨架起步态仍是全占位行，解析器行为正确 |

## 9. 非目标

- MUST NOT 在安装时或初始化时**通读项目代码生成全套卡片**（用户明确选了渐进补齐）。
- MUST NOT 新增 `ctx` 子命令。补卡是 agent 写 markdown，不需要 CLI 支持。
- MUST NOT 动 **codegraph 的安装与接线行为**（`install.mjs` 的 `CODEGRAPH` 常量与 `syncCodegraph` 一族函数、子进程调用、`--no-codegraph`），也 MUST NOT 把 `graph.md` 扩写成 codegraph 使用手册。
  `graph.md` 与 `install.mjs` 的**措辞**仍要跟着改：前者原本指向已删除的 `curated.md`，不改就是断链，§3 的重写也是 §2.6 强制的；后者只改注释与打印文案。
- MUST NOT 动 `mode` 墓碑字段的处置（留给 3.0.0）。
