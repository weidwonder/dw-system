## 问题

文档层的失准没有任何一道门在管，具体是三件事叠在一起：

1. **四条轴没有一条的参照物是 `docs/`。** A 规范轴对着邻居代码、B 忠实轴对着 spec、C 残留轴对着替换清单、D agent 架构轴外包给 `agentic-principle`。C 轴的典型命中里有一句"旧文档段落遗留"，但它的参照物仍是替换清单——管的是"被替代的旧段落删没删"，不管"活着的文档说得还对不对"。

2. **文档生命周期结算挂在完成门上，且是主会话自查**（`文档治理.md` §3、`worktree开发纪律.md` §完成与自动合并门）。三个结构性缺陷：
   - **形态与旁边各条不一致**：完成门其余各条都是"核对一个已存在的产物"（三轴报告齐全、P0/P1 清零、用户拍板记录、CI 通过），只有文档结算这一条是"现在开始干一整套活"——盘点权威面 → 扫 `index.md` 现行区 → 逐篇比对 `authority_refs` → 改 frontmatter → 插头注 → 动两个索引。核对项容易打勾，子流程容易整条跳过。
   - **零命中 = 零产物 = 无法与"忘了做"区分**。`文档治理.md` §3 自己写了"判定不留痕等于没判"，但留痕只要求给**命中的文档**留（更新 `last_confirmed`）。比对下来一篇都没失准是常见情况，此时落盘产物是空的，事后分不出"认真扫了确实没有"和"压根没扫"。
   - **时机最差**：完成门在任务最末尾，上下文最满、离常驻加载最远、最可能已被压缩；而落地写法在条件加载的 `文档归档与账本收敛.md`，门口还得临时拉一个文件进来。

3. **本仓库自己就是活证据**：`docs/spec/2026-07-06-ai-prd-design.md` 的组稿链路描述**落后了两道门**——落盘确认门那次没同步，2.2.0 的复核门差点又落后一道，最后是靠人工评审的 C 轴顺手抓到的。现有三轴与 `ctx probe` 都发现不了它：probe 的 `rationale-traceable` 只验 `authority_refs` **非空**，不验它描述的内容还对不对。

## 目标

把文档失准的检查从"主会话在最末尾自查"改成"评审门上的一条独立轴"，让完成门那一条回归它旁边各条的形态——**核对一个已存在的产物**。

## 范围

纯 markdown 纪律改动，不涉及 `ctx` CLI（不加子命令）、不涉及 `install.mjs`。

### A. 新增 D 文档轴，agent 架构轴顺延为 E

**恒跑轴保持连续编号**：A 规范 / B 忠实 / C 残留 / **D 文档**（四条恒跑），**E agent 架构**（仅 Agentic 项目，条件跑）。

D 轴编号从 agent 架构轴让给文档轴，理由是恒跑与条件跑各自连续更好记；agent 架构轴的判据、外包对象（`agentic-principle`）与"不在场才标未执行"的规则**一个字不动**，只改字母。全仓对旧编号的引用只有两处（`CLAUDE.md` §agentic-principle 契约、本纪律自身），改名成本可控。

### B. D 轴查什么（范围已按 `ctx probe` 收窄）

参照物 = **`docs/` 的现行文档与真相源**，与其余各轴均不重叠。只查三件 probe 判不了的事：

| # | 查什么 | 为什么 probe 判不了 |
|---|---|---|
| 1 | **文档正文与代码逻辑是否一致**：本次触碰的权威面，描述它的现行文档说的还对吗 | `rationale-traceable` 只验 `authority_refs` 非空，不读正文 |
| 2 | **断链与孤儿文档**：本次新建/移动的文档有没有断链；新建文档有没有任何入口指向 | probe 不扫链接图 |
| 3 | **真相源是否跟上**：`docs/REQUIREMENTS.md` / `ARCHITECTURE.md` 描述的能力被本次改动改了吗，改了同步没有 | `requirement-reachable` 只验**可达**，不验**内容还成立** |

### C. `ctx probe` 是本轴的辅助工具，不是门禁

照抄 C 残留轴对静态检查工具的既有定位（`代码评审纪律.md` §替换清单 §工具辅助：**清单是 MUST，工具是 SHOULD**）：

- D 轴 SHOULD 先跑 `ctx probe` 拿机器结论（B 类题型：真相源可达、架构节列出的模块路径都存在、现行区各 spec 的 `authority_refs` 非空），把它当作"发现清单漏了什么"的补充。
- **probe 报绿 MUST NOT 被读成"本轴无发现"**——它验的是可达性与字段非空，本轴查的是内容还对不对，两者不是一回事。
- probe 跑不起来（没装 `ctx`、项目无 `engineering-context/`）时本轴照常执行，MUST NOT 因此标"未执行"。

### D. 完成门那一条：从"干一整套活"改成"核对一个产物"

`worktree开发纪律.md` §完成与自动合并门 的「文档生命周期已结算」一条改写为两句：

- **核对 D 轴报告**：报告在、P0/P1 已清零、判定结果已落盘（失准的已完成归档三动作，仍准确的已更新 `last_confirmed`）。
- **自查本次新建的文档**：`lifecycle` 与 `authority_refs` 两个字段齐（只针对自己刚建的那几个文件，成本极低）。

**为什么把重活留给评审门而不是完成门**：代码评审门那一刻 diff 已冻结、spec 在手、子代理机制本来就在跑，边际成本只是多派一个 agent；而完成门在最末尾、上下文最紧。更要紧的是子代理**天然产出报告**——零命中也有一份"扫了 N 篇、0 篇失准"的书面结论，把上面第 2 条缺陷（零产物）一并解决。

### E. 时序切分：Step 8–10 新建的文档归完成门

代码评审门在 Step 7 后、Step 8 前，而 Step 8–10 还会新建 `test-spec`。切分：**D 轴管既有文档是否失准 + 断链孤儿 + 真相源**（重活，要扫全仓），**完成门只留新建文档的字段自查**（逐篇自查，只看自己刚建的）。

### F. 恒跑，不设触发条件

D 轴 MUST 每次都派，MUST NOT 由主会话先判"本次有没有碰文档/权威面"再决定派不派——**判断"有没有触碰"本身就是盘点，而盘点正是本轴的第一步**。把这一步交回给主会话，等于把最容易漏的判断交给最容易漏的人（`文档治理.md` §3 明写"改语义不删东西同样让文档失准"，这类改动的替换清单往往是空的，主会话最容易据此判"没碰"）。

### G. 判据扩展 3 项（实现期新增，**不是执行者调整**）

第一次实跑 D 轴时暴露了三个判据空洞，本次一并补上。**这是对 `文档治理.md` §3 判据本身的扩展**，与 §不做 里"只改执行者"的声明不同——如实登记在此，MUST NOT 当成"执行者调整"混过去：

1. **权威面新增第 8 类「流程与门禁契约」**（门的位置与顺序、轴或步骤的集合与编号、准出项的语义、谁在哪一步执行什么）。原 7 类全是代码型面，纯 markdown 的流程变更套不进任何一类，"本次没触碰任何权威面"就成了合法的收工借口。**这一条扩大了触发面**，见 §兼容取舍。
2. **比对改成两步且都 MUST**：机械比对 `authority_refs` 之后必须再做一次关键术语的现行区全文检索。两步命中集不同——正文整节描述本次改动、却没在 `authority_refs` 里登记自己的文档，机械比对永远够不到。
3. **勾验表按勾选状态判**：未勾选按现行口径（会被续跑），已勾选是历史记载 MUST NOT 改写。此前无判据，每次都要重新拍脑袋。

同时把两份不一致的权威面枚举**合并成一份**（`文档治理.md` §3 第 1 步为唯一权威，`authority_refs` 声明处改指针）——两份枚举本就漂移过，是"改一处漏一处"的温床，本次加第 8 类时正是只加进了没人读的那一份。

## 验收标准（可判定，含边界/失败用例）

- [ ] 正常路径：跑完一次编码后，代码评审门派出 **4 个**并行子代理，D 轴返回一份独立报告，报告里对本次触碰的权威面逐条给出"仍准确 / 已失准"判定。
