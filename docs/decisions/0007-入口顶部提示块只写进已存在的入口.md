# 0007 入口顶部提示块只写进已存在的入口文件

状态：现行 ｜ 日期：2026-09-21

## Context

本体系的 skill 靠各自的 description 被 harness 触发；项目入口文件（`AGENTS.md` / `CLAUDE.md`）末尾的 `dw-workflow` 标记块只写"唤起 `dw-workflow` 时按本块字段路由"，没有任何一句要求 agent 起步先去加载它。结果是：一个零上下文 agent 打开项目、读完入口文件，仍然可能完全不走本流程。

入口文件有两个，两个工具各读一份；标记块的现行行为是两个入口都写、字段以 `CLAUDE.md` 为准，首次写块归 skill 初始化，安装器只同步已有的块。

## Decision

在入口文件**最前面**加一个独立的幂等提示块 `<!-- dw-workflow:hint:start/end -->`，只说一句「动手前先加载 `dw-workflow`」外加一个指向文末标记块的指针。

落点判的是**本次写入前**项目根的状态：两个入口都在就都写，只有一个在就写那个，一个都不在只写 `AGENTS.md`。标记块的行为一条不改。

## Alternatives Considered

- **把这句话加进文末标记块的正文**：标记块已经二十多条，第一屏看不到它；而这次要解决的正是"读了入口文件仍不知道要加载 skill"。
- **把标记块瘦身成一句提示、规则全回 skill**：动到每条规则的家，本次不做这么大的改动（登记在 `docs/TODO.md` 之外，暂无需求）。
- **凡写标记块的入口都写提示块**：全新项目里 `CLAUDE.md` 与 `AGENTS.md` 会各写一份提示；拍板人要的是"不为写提示而凭空造文件"，`AGENTS.md` 优先。
- **只写 `AGENTS.md`、不写 `CLAUDE.md`**：Claude Code 主加载的是 `CLAUDE.md`，只有 `AGENTS.md` 的项目在 Claude 侧读不到任何提示。
- **加一个开关控制写不写**：默认值留在旧行为上，等于这次改动对存量项目不生效。

## Consequences

- 已装项目重跑安装命令即补上提示块，入口文件会出现一处改动，进使用者的 git diff。
- `CLAUDE.md` 有块而 `AGENTS.md` 本次才被标记块顺带创建时，被创建的那个只有标记块、没有提示块：同一项目里两个入口文件长得不一样，读 `AGENTS.md` 的 agent 看不到那句提示。这是"不为写提示而凭空造文件"的直接代价，拍板人 2026-09-21 接受。
- 提示块正文随 skill 分发（`dw-workflow/assets/config-snippets/hint.md`），改文案即改行为，由 `test/workflow-block.test.mjs` 从片段现场读来比对，不在断言里写死措辞。
