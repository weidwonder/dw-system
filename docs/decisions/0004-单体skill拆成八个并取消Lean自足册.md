# 0004 单体 skill 拆成八个，取消 Lean 自足册

状态：现行 ｜ 日期：2026-09-17（3.0.0）

## Context

2.x 的主流程是一个 skill：入口加十几篇分册，靠入口里的一张触发表决定什么时候读哪一篇。为了让小改动少读一些，另有一册约 122KB 的 Lean 自足册，把适用于 Lean 的每条判据重写一份，再用覆盖率测试保证"原篇里每个含 MUST 的小节在自足册里都有对应要点"。

两个问题：自足册是重写副本，原篇每改一处就要同改一处，且给任何原本没有 MUST 的小节加一个规范词，都会自动新增一条自足册覆盖义务；单体 skill 的触发描述要覆盖从评审到文档归档的全部场景，子代理想只加载评审判据时拿到的是整个流程。

## Decision

按职责拆成八个 skill：`dw-workflow`（总纲、路由、分流、步骤顺序、两道确认门、spec 写作、测试阶段）、`dw-prd`、`dw-review-gate`、`dw-doc-governance`、`dw-code-facts`、`dw-bug-diagnosis`、`dw-worktree`、`dw-prose`。每个入口带〈读取条件〉表。Lean 自足册取消，改成一页步骤顺序，每一步指向对应 skill。

搬家时整篇搬的保留文件名与小节标题，只拆超限的三篇（评审纪律拆七篇、文档治理拆出生命周期、总纲的两道确认门另成一篇），以减少指针改动。

## Alternatives Considered

- **保留自足册，缩短它**：副本的性质不变，同改义务仍在。否决。
- **拆得更细**（测试阶段、AI 运行期契约也各自成 skill）：`dw-workflow` 的分册合计仍超目标，这是候选的下一步；本次先不做，避免一次改动同时移动太多锚点。留在 `docs/TODO.md`。
- **拆 skill 但保留旧 skill 名做别名**：拍板人定为不兼容，安装器负责清理旧目录。

## Consequences

- Lean 路径要加载多个小 skill，各读入口加一两篇分册，没有任何一份是副本。（实测：走完一次 Lean，主会话按整篇计读入约 115–130KB——入口、一页顺序、协作面分册、lean 模板，加 worktree / 代码事实 / 确认门 / 实现 / 评审门 / 文档结算各自的入口与分册；拆分前同口径约 150KB，其中自足册一册 122KB。）
- 评审子代理只加载 `dw-review-gate`，不再带上整个流程。
- `lean-selfcontained` 覆盖率测试退役；"Lean 不豁免任何一道门"改由 `gate-sync` 核对一页顺序表里每道门都在。
