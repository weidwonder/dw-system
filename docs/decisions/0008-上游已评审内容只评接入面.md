# 0008 上游已评审的原样带入内容只评接入面

状态：现行 ｜ 日期：2026-10-01

## Context

一个宿主项目把另一个自建仓库已发版、已过评审门的反馈模块注入自己的 skill。当时评审门要求范围内的文件各轴一律通读，本次 diff 约八成是上游原样带入的文件，六条轴的子代理都去重读并评判它们，评的是上游已经评审过的东西。拍板人指出了这一点。

## Decision

轴集合照算、不裁剪；与已过评审门的上游版本逐字节一致、或由其注入 / 生成工具原样写出的文件，经主会话核实后从各轴的阅读范围里点名排除，只评接入面。拍板人选择直接替换旧口径，不保留"全量通读"作为并行选项。判据在 `dw-review-gate` 的 `评审门禁.md` §上游已评审的原样带入内容。

## Alternatives Considered

- 把这类文件从判面输入里剔除：上游脚本将不再触发 P 面，等于另开一个口子裁轴集合，与"轴集合 MUST NOT 被裁剪"冲突。
- 凭目录名或注入标记认定为上游内容：宿主手改过的文件会被一并放过，所以要求逐字节核实。

## Consequences

- 主会话每次派发前多一步核实：逐字节比对或认出生成工具与版本，并在 prompt 里列出排除路径；漏做核实就不能排除。
- 上游每次重新带入后排除清单要重新核实，宿主手改过的文件自动退回普通评审。
- 上游自身的问题不再在宿主评审里展开，只单列一句；修复要回上游仓走它自己的评审门。
