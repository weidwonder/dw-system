# 0001 评审子代理升档不看改动规模

状态：现行 ｜ 日期：2026-09-02（2.15.0）

## Context

代码评审门每条轴派一个子代理，默认普通档模型，个别情形升到与主会话同级的高档。升档条件需要一个判据。

## Decision

升档只认三条：该轴上一轮报出过 P0；命中大架构确认门；拍板人显式要求。改动规模不是依据。

## Alternatives Considered

- **按规模升档**（跨 ≥2 个边界，或 spec 的功能需求 ≥10 条）：2.15.0 之前用的就是这两条。实际跑下来几乎任何跨模块改动都命中，升档从例外变成了默认，成本上去而发现质量没有对应提升。否决理由：规模是数量信号，不是难度信号——两个模块的重命名比一个模块的并发逻辑好判。

## Consequences

条件一依赖跨轮记忆，所以评审报告首行必须记下各轴 P0 计数，供下一轮读取。
