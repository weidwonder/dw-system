# 0005 代码事实卡按业务域分，不按任务追加

状态：现行 ｜ 日期：2026-09-17（3.0.0）

## Context

2.x 的卡片规则是"每仓一张、最小四项、只增不减"。三个已装项目跑下来，卡片良莠不齐：一个项目的单张卡长到约 146KB，里面是三十多个按任务追加的小节；另一个带着五十余条按日期排列的"本次核实"流水；只有一个 monorepo 因为天然按包分卡，质量稳定。共同的成因：补卡的时机是"本次任务读了什么"，于是小节按任务长出来；"只增不减"又不许整理。

## Decision

卡片分两种：仓库地图卡（职责 + 业务域地图）与业务域卡（职责 / 权威实现与对外接口 / 陷阱项 / 确认，小节名固定）。域的切法只写在地图卡里，并与需求真相源的子模块用同一套切法；新事实先找所属的域，新开域先改地图。卡片只写现状、只记判断；cite 以 `路径#符号` 为主。"只增不减"改为"事实不丢，体积有上限"。`ctx lint-cards` 体检，存量违规记入只减不增的基线。

## Alternatives Considered

- **只加体积上限，不规定分法**：超限时 agent 会按"最近的任务"切，切出来仍是流水。否决。
- **按代码目录分卡**：目录是实现的组织方式，会随重构变；读卡的人问的是"这个业务能力的权威实现在哪"。按业务域分，并用地图卡把域映射到目录。
- **体检发现存量违规即判红**：三个已装项目会在升级当天全部变红，只能靠关掉体检继续干活。改为基线：存量只许减，新增判红。
- **cite 只认行号**：行号在任何一次编辑后都会漂，体检会持续误报。以符号为主、行号可附。

## Consequences

- 存量项目要各自跑一次 `--init-baseline`，再按"碰到哪个域搬哪个域"渐进迁移；不要求一次重写。
- 固定小节名与体积上限同时写在两份模板、`代码事实纪律.md` 与 `lint.js` 里，改一处要三处同改，由 `test/ctx-domain-cards.test.mjs` 把守。
- 符号检索是逐字子串匹配，抓不到"符号还在但语义变了"；那一半仍靠触碰权威面时刷卡。
