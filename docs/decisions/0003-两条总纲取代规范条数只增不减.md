# 0003 两条总纲取代"规范条数只增不减"

状态：现行 ｜ 日期：2026-09-17（3.0.0）

## Context

2.x 用三条机器闸守 skill 文档：常驻前置量不超过 50,000 字节、每份文件的 MUST / SHOULD 条数不得下降、几个契约数字单点定义。同一时期常驻判据被要求"就地写全"——入口、总纲、Lean 自足册、注入块各自复述同一批判据，再靠测试断言各处保持同步。

结果是仓库说明长到约 103KB，单体 skill 的分册合计超过 400KB，注入每个目标项目的标记块约 16KB；每加一条判据要同改五到九个文件，体积上限几次被贴着压线通过。对照一个长期维护良好的项目：它的根说明不到两千词，十二个 skill 每个 6–18KB，靠的是"一个事实只有一个家"与"有上限、超限先搬走"两条。

## Decision

立两条总纲，展开只在 `dw-workflow/SKILL.md`：

1. 一个事实只有一个家，别处只放链接。
2. 规范文本有体积上限，超限先搬走、再压缩，最后才抬上限。

配套四样落地约束：归属表指明每类事实的家；家以外只写名字加受检指针；两条机器闸（规范句逐字重复、现行文档重复声明同一权威面）；评审门文档轴与 skill 原则轴加"同一事实有没有两个家"检查项。"规范条数只增不减"改为"含规范词的小节消失须在去向清单里逐条交代"。

## Alternatives Considered

- **保留"只增不减"，只加体积上限**：两条闸直接冲突——上限要求删，棘轮不许删，唯一合法的动作只剩抬上限。否决。
- **继续就地写全，靠同步测试防漂**：同步测试只能断言"那句话在场"，断言不了几份展开的例外与边界一致；副本越多，每次改动的成本与漏改面越大。否决。
- **去向按句子粒度交代**：一次重组涉及上千条规范句，逐句登记的清单没人读得完，清单本身成了新的负担。取小节粒度；小节内部压缩时命题有没有保住，交给评审门按 `dw-prose` 的完整命题规则判。

## Consequences

- 体积上限清单 `test/doc-budgets.json` 里，超目标的文件先冻结在实测值，只许往下走；`dw-workflow` 与 `dw-prd` 的分册合计仍远高于目标，登记在 `docs/TODO.md`。
- 读者要多跳一次才能读到判据。换来的是每条判据只有一个地方要改、只有一个地方可能写错。
- 逐字重复检测抓不到换了措辞的重复展开，那一半仍靠评审门。
