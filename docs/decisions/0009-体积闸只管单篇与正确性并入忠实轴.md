# 0009 体积闸只管单篇，正确性与回归并入忠实轴

状态：现行 ｜ 日期：2026-10-08

## Context

对照已卸载的 AgentKit 套件盘点本体系缺什么时，暴露出两件事。一是 `dw-workflow` 的 `references/` 合计离冻结上限只剩十几个字节，往任何一篇加一句话都要先从别处腾地方，而真正决定一次会话读多少的是单篇大小——分册按读取条件到点才读，合计不对应任何一次真实加载。二是评审门六条轴里没有一条负责找逻辑错误与被改坏的调用方：规范轴不看需求，忠实轴只逐条对照 spec，残留轴只看替换清单。

## Decision

体积闸取消按 skill 的分册合计，只保留单篇、类、单条行长与 `CLAUDE.md` 上限；清单的顶层键改为闭集，出现不认识的键判红。正确性与回归不新开一条轴，并进忠实轴：它本来就读 spec 与 diff，顺带核对实现逻辑与被波及的调用方，未登记进兼容取舍表的既有行为变化归 `越界`。两条都由拍板人在 2026-10-08 选定，兼容取舍为直接替换。

## Alternatives Considered

- 保留合计、再抬一次上限：上限已抬过多次，每次都是"内容确实需要"，合计这个量本身没有对应的成本。
- 新增一条正确性轴：多派一个子代理、多一份报告，而它要读的材料与忠实轴完全相同；拍板人要求尽量轻量。
- 照搬 AgentKit 的挂钩、按关键词与 diff 阈值触发的检查：都是启发式判定，违背本体系"判定来自显式声明"的原则。

## Consequences

- 单篇仍有上限，一篇写胖了照样拦；但一个 skill 的分册可以越拆越多而没有总量护栏，拆分是否合理交给 skill 原则轴判。
- 忠实轴的报告会比以前长，同一改动可能多报 P0；偏离类型闭集不变，覆盖矩阵与 CHANGELOG 对照照旧。
- 以后要加新种类的体积上限，先在 `test/doc-budgets-lib.mjs` 写判定再往清单加键。
