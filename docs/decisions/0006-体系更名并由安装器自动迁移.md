# 0006 体系更名为 dw-system，旧残留由安装器自动迁移

状态：现行 ｜ 日期：2026-09-17（3.0.0）

## Context

skill 拆分之后，`ai-` 前缀的名字既不描述职责也容易与别的 AI 工具撞名。更名涉及：仓库与包名、skill 目录名、版本戳文件名、三处标记块（流程配置块、Codex 约束块、`.gitignore` 块）的起止行、`ctx` 的归属路径。已装项目里这些东西散在两个 skills 目录、两个入口文件与 `.gitignore` 里。

## Decision

全部改为 `dw-` / `dw-system` 前缀，不留别名。升级路径只有一条：重跑安装器。安装器用一张 `LEGACY` 表集中登记全部旧名字，升级时删除旧 skill 目录与旧戳，把三处旧块改写成新块并逐字带入字段与 `docs/` 入库决定；标记块不再写 `mode`，只有旧 `mode` 的块由安装器推断并打印结果。skill 侧读到旧名字的块即请用户重跑安装器，不自己推断；这条识别在 skills 树里只写一处——`dw-workflow/SKILL.md` 路由表的一行，`dw-prd` 不认旧块名，读不到 `dw-workflow` 块一律按 solo。

## Alternatives Considered

- **保留旧名字一段时间，双名并存**：两个 skill 名指向同一份判据，触发与引用都会分叉；拍板人定为不兼容。
- **只改 skill 名，不改标记块与仓库名**：项目入口文件里长期留着旧名字，新来的人无从知道它与 `dw-workflow` 是同一件东西。
- **skill 侧继续保留旧 `mode` 的推断**：同一套映射在安装器与两个 skill 里各写一份，是总纲一要消除的形态；且 skill 不写文件，保证不了"只告知一次"。
- **迁移写成单独的脚本**：用户要多记一条命令，且与安装器的幂等、`--dry-run`、符号链接处理是同一套逻辑。并进安装器。

## Consequences

- 旧名字 MUST 只出现在 `LEGACY` 表、`dw-workflow/SKILL.md` 路由表的那一行、迁移指南、CHANGELOG 既有条目与历史文档里，`test/installer-legacy-upgrade.test.mjs` 逐字核对安装器与 skills 树。
- 对 3.0 之前安装的兼容整体可一次移除：删 `LEGACY` 表及引用它的迁移逻辑、删路由表那一行、删 `installer-legacy-upgrade` 里对应的用例。移除的时点由拍板人定，未设到期日。
- 删除动作有固定的安全边界：只删两个 skills 目录下名字逐字等于登记项的条目，符号链接只删链接本身，删前核对父目录。
- GitHub 仓库改名后旧地址靠平台跳转维持；安装命令与文档统一改用新地址。
