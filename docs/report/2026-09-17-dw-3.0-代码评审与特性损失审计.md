规范正文的搬家质量高，多数文件逐字未变。损失集中在四类，已全部按 2.17 原文补回：

1. **机械改名跟错了家**：Lean 评审子代理被指去加载 `dw-workflow`，拿不到评审判据；`ctx` 的兜底命令指向 `dw-workflow/scripts/`；残留轴子代理不再被指去读 `替换清单.md`，保留例外的核销规则因此没人执行。
2. **只住在被取消的那一份里的命题**：Lean 自足册独有的"改动小 MUST NOT 作为大架构确认的豁免理由""主文档没动 MUST NOT 当收工信号""跨仓需求一律升级"、五道门表的"不过门的后果"一列；旧 §ADR 的"不删旧决策记录"。
3. **注入块瘦身丢掉的反向保证**：评审门的触发词被收窄成"编码完成后"（只改 `docs/` 的会话会据此跳过它唯一的门）、CHANGELOG 分类闭集、cite 的组成与补卡最小四节、脱敏副本入库与覆盖度台账、Agentic 应用的四条判定口径、`worktree-dir` 与 `pr` 合并的三条反向保证。
4. **模板引导语被压成一行**：域卡模板的接口表列、cron 示例、"仅内部可见须标明"、日志排障四项、端侧五项。

可执行代码侧有一条真回归：`ctx` 读卡片改用目录项类型判断后，软链接的卡片被无声跳过，已修并补用例。

接替闸的射程缺口同时补上：`rule-destinations` 加上仓库根 `CLAUDE.md`（它从 116KB 压到 12KB，此前不在任何闸的射程内；去向清单补了五行）；`doc-budgets` 的例外条目必须写成 `{max, note}`；`gate-sync` 重新要求入口点到每道贯穿门的名字；`change-awareness` 恢复判"本次有没有写条目"。

审计模型：评审门/worktree/bug 一路用的是主会话同款模型，其余四路与 skill 原则轴用高档模型；规范轴与残留轴用普通档。

## 体积上限

补回命题与指针属主后，`dw-workflow` 的 references 合计超出拆分时冻结的上限。按总纲先搬走了两处重复展开（取事实顺序的复述、`<skills 根>` 定义的三份副本），仍超 1.3KB，上限从 130,247 抬到 131,700；注入块 `base.md` 从 4,800 抬到 5,400。理由写在 `test/doc-budgets.json` 的 `note` 里，**待拍板人确认**。
