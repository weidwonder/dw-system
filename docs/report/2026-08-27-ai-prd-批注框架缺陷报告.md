# ai-prd 批注框架缺陷报告（2 项）

**目标仓库**：`github:weidwonder/ai-dev-system`
**受影响文件**：`skills/ai-prd/assets/templates/ui-prototype.html` 的 `ANNO-FRAMEWORK` 固定实现区
**发现场景**：用 `preview.mjs` 产出一份含**绝对定位画布**（拓扑图 / 流程图 / 座位图这类）的原型，然后在画布元素上打批注
**发现时间**：2026-08-27
**行号基准**：`preview.mjs init` 生成的原型文件（容器原样展开后的行号）

---

## 缺陷 1（严重）：给绝对定位元素打批注，会把它打回相对定位、当场错位

### 现象

在原型里对一个 `position: absolute` 的元素点「＋ 加注释」并保存后，**该元素立刻脱离原本的坐标、掉进正常文档流**，视觉上"跑飞"。刷新后依旧。

### 根因

`attach()` 会给被批注元素加上 `data-anno-host` 属性：

```js
function attach(el, pin) {
  var host = hostOf(el);
  host.setAttribute("data-anno-host", "");   // ← 这里
  ...
}
```

而固定实现区里有：

```css
/* 生成文件第 744 行 */
[data-anno-host] { position: relative; }
```

问题在于**权重与顺序**：

| | 选择器 | 权重 | 在生成文件里的位置 |
|---|---|---|---|
| 作者自定义样式 | `.topo-node { position: absolute }` | (0,1,0) | `<style id="proto-custom">` 第 627 行 |
| 批注框架 | `[data-anno-host] { position: relative }` | (0,1,0) | 第 744 行 |

**权重相同，框架排在后面 → 框架赢。** 于是 `absolute` 被改写成 `relative`。

这不是个别写法的问题：`proto-custom` 插槽按设计就排在批注框架**之前**，因此**任何**用单个 class 声明 `position: absolute` 的自定义元素都会中招。UI原型纪律 §8.4 又明确要求自定义控件写进 `custom` 插槽，等于把作者引到必然踩雷的位置上。

### 最小复现

```bash
node scripts/preview.mjs init /tmp/repro.html --title 复现 --subtitle 复现
node scripts/preview.mjs screen /tmp/repro.html --name 画布 --desktop --states is-default
# custom 插槽写入：
#   .canvas { position: relative; width: 400px; height: 200px; border: 1px solid var(--border); }
#   .dot { position: absolute; width: 80px; padding: 8px; background: var(--muted); }
# screens 插槽写入：
#   <section class="device-wrap is-desktop"><p class="device-name">画布</p><div class="device">
#     <div class="app-bar"><span class="app-title">复现</span></div><div class="screen">
#     <div class="status is-default"><div class="canvas">
#       <div class="dot" style="left:250px;top:120px">我应该在右下角</div>
#     </div></div></div></div></section>
node scripts/preview.mjs serve /tmp/repro.html
```

打开页面 →「＋ 加注释」→ 点中那个 `.dot` → 随便写一句 → 保存。
**预期**：`.dot` 仍在 (250,120)。
**实际**：`.dot` 跳到画布左上角，`left/top` 失效。

### 建议修法（三选一，推荐 A）

**A. 只在元素本来是 `static` 时才提升**（改 CSS，一行）

```css
[data-anno-host]:not([style*="position"]) { position: relative; }
```

仍不够稳（只挡住行内样式声明的情况）。更稳的是 B。

**B. 在 `attach()` 里按计算样式判断**（改 JS，推荐）

```js
function attach(el, pin) {
  var host = hostOf(el);
  if (getComputedStyle(host).position === "static") {
    host.setAttribute("data-anno-host", "");   // 只有 static 才需要提升
  }
  ...
}
```

配合把 CSS 那行保留原样即可。这样绝对/相对/固定定位的元素一律不动。

**C. 不改定位，改用独立的图钉层**：把 pin 挂到 `<body>` 下的一个覆盖层，按 `getBoundingClientRect()` 定位。最彻底，但改动最大，且要处理滚动与窗口缩放。

## 缺陷 2（中等）：图钉会被裁切、也会被其它元素盖住

### 现象

- 批注保存成功（`annotations` 命令读得到），但**页面上那个粉色图钉看不见**，用户以为批注丢了。
- 有时图钉只露出一部分，被相邻元素压住。

### 根因

图钉是**挂进被批注元素内部**、并定位到该元素**外侧**的：

```css
/* 生成文件第 746-765 行 */
.anno-pin {
  position: absolute;
  top: -6px;        /* ← 元素上边界之外 */
  z-index: 60;
  ...
}
```

```js
pin.style.right = (-6 + n * 21) + "px";   /* ← 元素右边界之外 */
```

由此产生两个问题：

1. **被祖先裁切**：只要被批注元素处在某个 `overflow: auto | hidden` 的容器里（画布类原型几乎必然如此——图比视口宽要滚动），`top:-6px` / `right:-6px` 正好落在裁切区外，图钉被切掉。
2. **被兄弟元素遮挡**：`z-index: 60` 只在**最近的层叠上下文**内有效。被批注元素若处在一个已经建立层叠上下文的祖先内（有 `transform` / `filter` / `opacity<1` / 自身带 `z-index` 的定位元素都会建立），图钉就被关在那个上下文里，外面任何 `z-index ≥` 的元素都能盖住它。

### 最小复现

沿用缺陷 1 的复现文件，把 `.canvas` 改成：

```css
.canvas { position: relative; width: 1200px; height: 200px; overflow: auto; }
```

外面再包一个窄容器。给画布本身打批注 → 图钉落在画布左上角外 6px → 被裁掉，页面上完全看不见。

### 建议修法

1. **图钉不要放在元素外侧**：改成 `top: 0; right: 0`（贴内侧角），或 `inset-block-start: 2px`。这样任何 `overflow` 容器都裁不掉。
2. **把 z-index 拉到框架自己的层**：`.anno-pin { z-index: 2147483000; }`，并在文档里说明自定义样式不得低于此值。
3. 更彻底的仍是缺陷 1 的修法 C——图钉统一挂到 body 下的覆盖层，天然不受裁切与层叠上下文影响。**两个缺陷用同一个方案一并解决。**

## 影响面评估

- 只影响**含绝对定位画布**的原型；表单、列表、卡片流这类正常文档流的原型不受影响。
- 缺陷 1 会让作者误以为是自己布局写错了，从而反复调坐标（本次就发生了：作者先按"间距不够"改了一轮才定位到真因）。
- 缺陷 2 会让用户误以为**批注没保存成功**，可能重复提交或放弃使用批注功能。

## 作者侧的临时规避（已在本次原型中采用，不需要动固定区）

```css
/* 用两级选择器提高权重，压过 [data-anno-host] */
.topo-stage .topo-node,
.topo-stage .topo-frame,
.topo-stage .topo-pill { position: absolute; }

/* 把图钉拉到最上层 */
[data-anno-host] > .anno-pin { z-index: 900; }

/* 给滚动容器留出图钉的空间 */
.topo-wrap { padding: 14px; }
```

这三条能规避，但**每个写画布类原型的作者都得自己踩一遍才知道**，所以仍建议在框架侧修掉。
