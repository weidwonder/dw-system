# 升级到 2.0.0（自 1.10.0）

## 结论

**"个人版 / 团队版"这个概念取消了。** 它把两件互不相干的事捆在了一个开关上：**有没有别人一起干**（要不要对齐 owner、开评审会、走 PR），和**这个项目自己攒了什么家底**（有没有权威口径可查）。纯 AI 开发下这两件事经常错配——单人维护的十万行遗留系统按老规矩是"个人版"，于是 AI 直接 grep 旧代码；三个人的新项目按老规矩是"团队版"，于是被要求维护一整套自己用不上的资产。

2.0.0 把它拆成两条独立的线：

- **协作面**：由配置显式声明（一个人还是多人、合并走本地还是 PR）。**升级时自动从旧设置推断，不用手填。**
- **代码事实供给**：**不再由配置声明，改为每次运行时看项目里实际有什么**——有 `engineering-context/capability-registry.md`（且真填了内容）就走权威口径 + cite，有 `.codegraph/` 索引就用图谱查调用链与影响面，都没有就直接读代码。配置再也不会和实际情况对不上。

**一处会被感知的行为变化**：此前声明为"团队版"、但从没建过 `engineering-context/` 的项目，升级后按实际资产走直读，不再被要求维护整套 Engineering Context。**旧的声明对行为不再有任何效力。**

## 需要的动作

- **一般情况**：重跑一次安装器即可，**不需要手工改任何文件**。安装器会把 `CLAUDE.md` / `AGENTS.md` 里的标记块自动改写成新格式，改写前打印前后对照。
- **升级后第一次唤起 workflow 时**，会用一句话告知推断到的协作面与合并方式（例如"沿用 PR 合并"）。**不对就当场说一声**，会立刻改掉并写回配置，之后不再问。
- **原本就在用 `engineering-context/` 的项目**：无任何动作，权威口径与 cite 纪律照旧，只是启用条件从"声明团队版"变成"这个目录里确实有内容"。
- **未提交 `CLAUDE.md` 的多人项目**：请让每个人都重跑一次安装器。配置文件入库而 skill 不入库，只有一个人升级时，其他人的旧 skill 仍能正常工作（见下条），但用不上新能力。

## 行为变化知会（自动生效，无需迁移动作）

- **标记块里 `mode="team"` 还在，是故意留的**：给尚未重跑安装器的人的旧 skill 认，避免它读不懂新配置又来问一遍。新版 skill 完全忽略它，`3.0.0` 移除。**不要手工删。**
- **AI 会主动提示补建资产了**：项目长大到"改错了非权威的副本""被旧实现误导"这类**实际出过问题**的信号累计到阈值时，会在收尾汇报里建议建 registry 或建代码索引。**只按出过的问题触发，不按代码量或搜索次数触发**；拒绝一次后同类不再提。
- **分流默认假设跟着资产走**：没有权威资产的项目默认走最短流程（Lean）；有权威资产的项目在影响面不清时倾向升级到完整流程。此前这由"个人版/团队版"决定。
- **索引分层判据改了**：`docs/index.md` 与 `docs/index-archive.md` 的分层此前是团队版硬要求，现改为**按文档数量**（超过 20 篇）触发，与人数无关。
- **每个项目都应能零上下文交接**：需求、架构、实现三层真相源要能从 README 或 `docs/index.md` 两跳内找到。升级后 AI 会检查并**报告缺口，但不阻断**你的工作。
- 流程十步、四道门、文档目录约定（`docs/spec|plan|report`）、模板均无变化；存量文档不需要回改。
