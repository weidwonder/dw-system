# v1.8.0 迁移指南

## 发生了什么

`docs/` 文档层补上了退出机制——此前只有"创建后必须更新索引"，没有任何规则让过期文档退场，于是索引随项目年龄单调增长，旧 spec 被后来的 agent 当成现行事实。新增四条规则（权威定义见 `文档治理.md` §文档生命周期与索引门控）：

1. **索引分层**：`docs/index.md` 只索引现行口径，历史文档进 `docs/index-archive.md`。文件原地不动，只有索引分层。
2. **生命周期位**：新建 spec/plan/report/PRD 的 frontmatter 写 `lifecycle`（active / merged / superseded / obsolete）、`authority_refs` 与 `last_confirmed`（最近一次被复核判定仍准确的日期）。
3. **按权威面触发归档**：不按日期老化，按文档描述的权威面是否还成立。触发面与团队版刷 card 用的是同一个面（接口签名、废弃标记、路由配置、DB schema、兼容窗口、命令与目录约定），**改语义不删东西也算触碰**。结算挂在既有的**完成与自动合并门**上，不新增门。
4. **账本收敛**：`bug修复历史.md` 关键词检索不得全文加载、超 300 条或 1500 行分卷；`测试场景覆盖度.md` 是状态表，淘汰场景移入文末「已淘汰场景」区。

## 需要的动作

- **已有 `docs/index.md` 的项目**：拆成两个文件——现行口径（真相源、在做的 spec/plan、现行 ADR 与 UI 原型、两个账本入口）留在 `index.md`，其余条目移入新建的 `docs/index-archive.md`，`index.md` 末尾加一行指向它。这是一次性动作，此后由准出门维持。
- **存量文档不必回改**：没有 frontmatter 的旧文档默认视为 `active`，只在它描述的权威面被改动、触发复核时就地补齐。**不要批量刷 frontmatter**。
- **已有账本超阈值的项目**：按年份切出历史卷 `docs/report/bug修复历史-<年份>.md`，主文件顶部留卷索引表。切卷只搬运不改写条目格式。
- 无 `docs/index.md` 的项目（多为个人版）：无需操作；新建文档时模板已自带 `lifecycle` 字段。
