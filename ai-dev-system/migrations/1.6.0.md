# 升级到 1.6.0（自 1.5.0）

## 结论

**无破坏性变更，但安装器多了一个联网动作，并会写入用户级目录。** 本版本把 Agentic 应用的架构设计外包给独立技能 `agentic-principle`（https://github.com/weidwonder/agentic_principle）：本体系只负责运行期 AI 契约与工程流程，两者内容互不搬运、各自独立演进。

## 需要的动作

- **知悉安装器的新行为**：每次运行安装器会额外浅克隆 `agentic_principle` 读取版本，本地更旧才更新。安装位置是**用户级**（`~/.claude/skills/agentic-principle` 与 `~/.codex/skills/agentic-principle`；v1.6.0 曾误写成 `~/.agents/skills/`，v1.6.1 已修正，见该版迁移指南），**跨项目共享一份，不进目标项目、不写目标项目 `.gitignore`**。不想要这个行为时加 `--no-agentic`。
- **自己在开发 agentic-principle 的人无需担心**：目标是 symlink（指向本地开发目录）或本身是 git 工作区时，安装器**只报告版本差异、绝不覆盖**。
- **离线环境**：拉取失败只打印一行警告，主安装照常完成、退出码仍为 0。本地已装则继续用旧版；本地没有则会提示它是 Agentic 需求的必需依赖，联网后重跑安装器即可。

## 行为变化知会（自动生效）

- **Agentic 应用 MUST 加载 `agentic-principle`**。判定沿用 AI overlay 已有的四条（模型做开放式多步规划 / 直接调用工具接口 / 未经确定性闸门就改状态 / 记忆跨会话影响决策），命中即必须加载，用在三处：
  1. **spec 设计（Step 2/4）**：先用它定场景分类、Agent 划分、编排模式与信息传递链路，再回 AI overlay 补运行期契约；
  2. **开发参考（Step 6/7）**：系统提示词、工具描述、并发拆分照它的规则写；
  3. **代码评审门**：增派 1 个 **agent 架构轴**子代理（完整流程 4 个 / Lean 2 个），该轴加载 `agentic-principle` 并执行它 review-mode 里的**全部**评估项，遵守它写明的评审边界（哪些要先与用户确认成立、哪些是客观缺陷可直接给处置、不得径自改动实现）。项数与判据以该 skill 当前版本为准，本体系不锁定。
  4. **在既有 agent 上加能力**（平台架构不动，只新增 skill/工具/服务）：走它的**增量入口**，不走完整流程。
- **两个 skill 严格独立**：本体系只保留指针，**不复制它的任何判据**；它缺失时不得用 AI overlay 顶替架构设计，也不得临时编一套——应告知用户并在 spec 里把架构选型标为"待补"。
- **AI overlay 移除了原有的 Agentic 建设表述**（为消除与 `agentic-principle` 的重复定义）：判定层级 2 下的两个子档展开、**Inheritance Declaration**（继承声明）、**Gap Watchlist**（平台缺口清单）、agent loop 状态机 / 工具契约登记 / 轨迹级 eval 的提及、"给已有 agent 加能力时的最小契约"整块。这些内容已整理成给对方维护者的补充建议（本仓库 `docs/report/agentic-principle-gap-report.md`），采纳后从 `agentic-principle` 获取。**若你的既有 spec 依赖过这几节，改为按 `agentic-principle` 的对应章节写；它尚未补上时，在 spec 里显式标注为待补，不要凭记忆复写旧版内容。**
- **保留在本 overlay 的**：AI 能力契约的「自主级别」字段（它是每个 AI 能力的契约字段，非 Agent 专属，纯 AI 功能同样要填）、以及全部推理运行期契约（确定性边界 / 版本 pin / 输出校验 / 置信度路由 / 安全管线 / 降级 / 预算准入 / eval 门 / 可观测 / 数据边界 / 可审计）。
- **分工边界**：Agent 系统**怎么设计**（场景选型、提示词、工具与 Skill 边界、模型档位、注意力与并发预算、长产物分区、步骤级用例与评测 Agent）归 `agentic-principle`；推理的**运行期契约怎么写进 spec**（确定性边界、能力契约、版本 pin、输出校验、置信度路由、安全管线、降级、预算准入、eval 门、可观测、数据边界、可审计）仍归本体系的 `AI-LLM-overlay.md`。
- 它产出的设计文档在本体系项目内写 `docs/spec/`（遵循 `文档治理.md`），而不是它默认的 `docs/specs/`。
- 安装器新增两个选项：`--no-agentic`（同义 `--no-companions`）跳过伴生 skill；`--agentic-repo=<url>` 覆盖来源仓库。
