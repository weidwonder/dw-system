# 升级到 1.3.0（自 1.2.0）

## 结论

**无破坏性变更。** 本版本给 `ai-dev-workflow` 新增三组行为约定：

1. **环境冲突扫描**：首次初始化（询问个人版/团队版时）与用户显式要求"体系扫描/体检"时，自动扫描项目自带的 `.claude/`、`.agents/` 下 rules/skills/agents 是否与本体系工作方式冲突；发现冲突逐项交用户决断（移除/修改/保留），未经同意不会改动任何用户文件。
2. **worktree 目录约定**：worktree 统一落在仓库根的 `./.worktrees/`，该设置随 mode 片段写入 CLAUDE.md/AGENTS.md 标记块，每次创建前从设置读取（用户可显式改到别处）；创建前会幂等确保 `.gitignore` 已忽略该目录。
3. **bug 诊断纪律强化**：新增修复历史账本 `docs/report/bug修复历史.md`——诊断前先查有无重复问题，修复后按固定条目格式归档并记修复版本；另吸收设计缺陷优先原则、"3 次修复失败停手讨论架构"门槛、模式对比、反向调用链追溯、纵深防御、源码护栏注释、条件轮询替代固定延时等技术。

## 需要的动作

- **无强制动作。** 三项约定均在下次触发对应流程时自动生效；`bug修复历史.md` 首次写入时自动创建，无需预先建好。
- 已初始化过 mode 的项目不会被重新扫描；想主动检查一遍，对项目说"扫描一下 ai-dev 体系"即可。
- 想让项目 CLAUDE.md/AGENTS.md 显式记录 worktree 目录设置（便于以后修改），可在 `<!-- ai-dev-workflow:start -->` 标记块内补一行：
  ```
  > - Worktree 目录固定在仓库根的 `./.worktrees/`（每次从本设置读取，除非用户显式要求改到其它位置）。
  ```
- 若项目此前已手工维护类似的问题修复记录文件，可告诉 AI 统一并入 `docs/report/bug修复历史.md` 或沿用现有文件（需显式说明，AI 不会擅自合并/搬迁已有文档）。

## 行为变化知会（自动生效，无需迁移动作）

- 冲突扫描只覆盖项目自带的自定义 rules/skills/agents；已知冲突插件（superpowers 等）仍由安装器在项目级禁用，二者不重复。
- 修复历史账本的"修复版本"字段用目标项目自己的版本机制（版本文件 ＞ Git tag ＞ commit hash），与 `ai-dev-system` 自身的版本号无关。
- 若诊断中发现同一问题在账本里复发过，AI 会先判断是方案不合理还是回归测试没拦住，不会直接照抄旧方案重放。
