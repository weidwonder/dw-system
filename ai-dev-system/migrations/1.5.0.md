# 升级到 1.5.0（自 1.4.0）

## 结论

**无破坏性变更，但流程新增两道强制门。** 编码完成后必须过**代码评审门**（子代理跑规范/忠实/残留三轴），spec 定稿前必须过**兼容取舍确认门**（是否向后兼容由用户逐条拍板，AI 不得默认兼容）。同时新增测试资产纪律：长链路必须有断言中间结果的端到端用例，真实输入必须固化成可复用样本，没覆盖的重要场景挂账到台账。

## 需要的动作

- **已安装本体系的项目**：重新运行安装器即可。安装器会更新两个 skill，并幂等改写 `CLAUDE.md` / `AGENTS.md` 里的 mode 标记块（新增三条约束），**不影响标记块外的内容**。
- **存量文档无需回改**：旧的 spec / lean spec 不必补替换清单与兼容取舍表；新门只对之后的需求生效。`docs/report/bug修复历史.md` 的条目新增了「测试样本」一行，**存量条目不必回改**。
- **首次固化含凭证的测试样本时**：需要在项目 `.gitignore` 追加对样本目录下 `secrets/` 的忽略（流程会提示，安装器不代劳，避免误伤你已有的忽略规则）。
- **团队项目（可选）**：把死代码检查（`knip` / `ts-prune` / `vulture` / `staticcheck -checks U1000` 等）挂进 PR gate，作为替换清单核销的自动补充。工具链不具备时清单核销照做，纪律不失效。

## 行为变化知会（自动生效）

- **代码评审门（新，两条路径都不豁免）**：完整流程派 3 个并行子代理——规范轴（编码规范与坏味道）、忠实轴（对照 spec 查漏实现/镀金/越界）、残留轴（旧逻辑是否删干净）；Lean 路径派 1 个子代理跑三轴精简版。子代理 prompt 必须点名加载 `ai-dev-workflow`，只报告不改文件；P0/P1 修完才准进 Step 8 与合并门。原 Step 7 的「双轴自查」被它取代并扩为三轴。纪律见 `references/core/代码评审纪律.md`。
- **兼容取舍确认门（新）**：spec 定稿前列出本次改变的每项既有可观察行为，逐条由用户选「不兼容 / 兼容到期 / 永久兼容」；选兼容到期必须同时定下到期日与到期动作。不改变既有行为时也要显式写一句"无兼容取舍"。结论落 eng-spec §8.1。
- **替换清单（新）**：spec 阶段登记本次取代了哪些函数/文件/配置/开关/DB 字段/接口版本，coding plan 把删除拆成具体任务，评审门残留轴逐条核销引用数。引用数为 0 且无保留理由的**必须立即删除**；保留例外只认三类理由（对外契约兼容窗口内、数据迁移未完成、回滚预案依赖），且必须带到期日。
- **测试资产纪律（新）**：长链路（≥3 组件 / 异步多阶段 / 有中间产物）必须有端到端用例，且**每个环节的交接产物各写一条断言**，不许只断言末端；用户提供的真实文件/报文/日志/口头场景一律固化进测试资产目录（探测项目既有惯例，兜底 `tests/fixtures/<场景名>/`），只重命名不改内容，凭证进 `secrets/` 并 gitignore、脱敏副本 `secrets.example/` 入库；同场景样本按覆盖特征标签去重（标签集是别人子集的淘汰）。
- **测试场景覆盖度台账（新）**：`docs/report/测试场景覆盖度.md`，固定文件名的单一追加账本（与 `bug修复历史.md` 同为报告命名规则的显式例外），模板 `assets/templates/test-coverage.md`。缺素材的场景挂 ❌ 并写清"需要用户提供什么"，攒批后一次性向用户索要，不逐个打扰。
- **bug 修复流程强化**：复现命令由 SHOULD 固化升为 **MUST** 固化为回归测试；触发 bug 的真实输入必须落成测试样本；跨长链路的 bug 回归测试必须是带中间结果断言的端到端用例；修复后同样过评审门（残留轴清理诊断期的临时探针与调试日志）。
- 个人版**不裁剪**上述任何一道门，可裁剪的只是台账深度（只记高重要度场景）。
- **流程文档改为分层加载（不改判据，只改投放节奏）**：`00-流程总纲.md` 瘦身为骨架（分流 + 四道门 + 步骤索引），Step 细节拆到三个分册——`路径-lean.md`（Triage 四问全否时读这一份就够）、`步骤-1-7-设计与实现.md`、`步骤-8-10-测试.md`。所有判据原样保留，只是不再一次性全读。Overview 的 A/B 核查判据统一收敛到 `overview.md` §14 一处。
