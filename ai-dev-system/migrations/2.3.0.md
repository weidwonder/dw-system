# 升级到 2.3.0（自 2.2.0）

## 结论

**代码评审门从三轴变四轴，新增的那一轴专管文档。** 编码完成后派出的子代理由 3 个变 4 个（Lean 路径仍是 1 个，但多跑一轴）。

新的 **D 文档轴**只盯一件别人不盯的事：**你改完代码之后，`docs/` 里描述这块逻辑的文档还准不准。** 它查三样——现行文档的正文与代码是否已经背离、本次新建或移动的文档有没有断链和没人指向的孤儿、真相源（`REQUIREMENTS.md` / `ARCHITECTURE.md`）跟上本次改动没有。

此前这件事挂在**完成与自动合并门**上由主会话自己做，有三个毛病：它是那道门里唯一一条"现在开始干一整套活"（旁边各条都只是核对已有产物，于是它最容易被整条跳过）；比对下来一篇都没失准时不产出任何东西，事后分不出"扫了确实没有"和"压根没扫"；而且它在整个任务的最末尾，上下文最满的时候。

## 需要的动作

**什么都不用做。** 重跑一次安装器升级 skill 即可，没有新配置、没有新问题要回答。

下次编码完成后你会看到 4 份评审报告而不是 3 份。第 4 份即使没查出问题，也会明确写一句"扫了 N 篇现行文档、0 篇失准"——这句话本身就是凭据。

## 代价（说在明处）

每次代码评审多一个并行子代理，评审阶段的耗时与 token 成本相应上升。换掉的是"旧口径被后来的 AI 当成现行事实"这类**无声的错**——它不会报错、不会测试失败，只会让下一个人（或下一个 agent）按一份已经不作数的文档去实施。

这道门**不提供跳过开关**，也不能由 AI 先判断"本次没碰文档"就不派——判断"有没有碰"本身就是这一轴的第一步工作。

## 其它变化

- **`agent 架构轴` 的编号从 D 改成 E**（仅 Agentic 项目会派的那一轴）。判据、外包给 `agentic-principle` 的方式、"它不在场才标未执行"的规则**一个字没改**，只是让出字母让四条恒跑的轴保持连续编号 A/B/C/D。
- **完成与自动合并门那条"文档生命周期已结算"语义变了**：从"在此执行整套盘点与判定"变成"在此核对 D 轴的报告与落盘结果"，外加一项自查（本次新建的文档带没带 `lifecycle` 与 `authority_refs`）。
- **`ctx probe` 的定位没变，仍是辅助不是门禁**：D 轴 SHOULD 先跑它拿机器结论，但 **probe 全绿不等于文档还准**——它验的是可达性与字段非空，不读正文。
- 十步流程、四道门、Triage 判据、文档目录约定、模板与 `ctx` 命令均无变化，存量文档不需要回改。
