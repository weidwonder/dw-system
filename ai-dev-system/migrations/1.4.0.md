# 升级到 1.4.0（自 1.3.0）

## 结论

**无破坏性变更。** 本版本让「用户可见界面的改动」在体系里首尾闭环：`ai-prd` 在涉及 UI 时必须先自查现有样式、再产出可离线打开的单文件 HTML 高保真原型；`ai-dev-workflow` 则把这份原型与 PRD 一起当作 Step 1 的输入，下游 Overview / eng-spec / test-spec 按它落用户可见行为。

## 需要的动作

- **已安装本体系的项目**：重新运行安装器即可获得新版两个 skill；安装器会覆盖旧 skill 文件并写入版本 stamp。
- **存量 PRD 文档**：无需批量回改。只有后续新增 / 调整用户可见界面的 PRD，才按新版流程补 “UI 原型” 节和 HTML 原型文件。
- **有前端代码的项目**：无需准备材料——新流程会自己去查设计 token（`tailwind.config.*` / `theme.*` / `variables.css` / `*.tokens.json`）、组件库依赖和同类现有页面。只有这些都查不到时，才会向你要截图或参考链接；仍然没有的话，原型会显式标注为临时视觉假设，开发前需替换为真实样式依据。

## 行为变化知会（自动生效，无需迁移动作）

- `ai-prd` 新增 `references/UI原型纪律.md`（涉及 UI 时才加载）与 `assets/templates/ui-prototype.html` 原型骨架（支持 2–5 屏并排）。
- 三类 PRD 模板（变更 PRD、轻量 PRD、整品 PRD）新增统一的 “UI 原型（如适用）” 五项表：原型文件 / 覆盖路径 / 样式依据 / 关键状态 / 不在用户界面内展示。
- **触发范围**：新增或调整页面、组件、入口、状态、信息层级、交互路径才出原型；**不改结构与交互的纯文案改动豁免**，在 PRD 写清改动前后文案即可。
- **原型必须能离线打开**：单文件、零外链（无 CDN、无网络字体、无远程图片）。质量清单新增可静态自检的 gate（外链数为 0、占位符清零、声明的每个状态都有切换入口）。
- `ai-dev-workflow` 的 Step 1 / Step 2 / Step 4 / Step 8 输入声明与参考 prompt 均已加入 UI 原型；测试 spec 的输入权威等级中，原型在「用户可见行为」上与 PRD 同级，二者冲突时标为待确认或立成开放问题，不由下游自行取舍。
- 团队版文档治理：PRD 与 UI 原型都要进 `docs/index.md`；变更 PRD 归并归档后，**原型留在原地**升级为该能力的现行界面依据，供后续需求继承。
- 本次只引入轻量原型纪律与单文件 HTML 模板，不引入独立的设计系统目录、预览服务器或设计工作流。
