# 环境冲突扫描：检查项目自带 rules / skills / agents 与本体系的工作方式冲突

> 触发时机（仅两种，其余场景不读本文件）：
> 1. **初始化**：首次在项目调用 skill、询问 mode 时执行，冲突决断与 mode 询问同一批抛出（见 `init-初始化.md`）。
> 2. **体系扫描**：用户显式要求"扫描 / 体检 / 检查项目的 ai-dev 体系"时单独执行（已有 mode 时不重问 mode）。

## 扫描范围

逐个读取以下位置每个文件的 frontmatter / 开头指令段（读到能判定其工作方式即可，不必全文精读）：

- 项目根 `.claude/rules/` 下的规则文件
- 项目根 `.claude/skills/*/SKILL.md`
- 项目根 `.claude/agents/` 下的 agent 定义
- 项目根 `.agents/skills/*/SKILL.md`（Codex 入口，若存在）

**排除**本体系自装内容：`ai-prd/`、`ai-dev-workflow/` 两个 skill 目录与 `ai-dev-system.version` stamp。目录不存在则跳过。

安装器（install.mjs）已在项目级禁用 4 个已知冲突**插件**（superpowers 等）；本扫描针对的是**项目自带的自定义** rules/skills/agents，是安装器的补充，不重复处理插件。

## 冲突判定（只看工作方式，逐条对照）

命中任一类即记为冲突候选：

| 冲突类别 | 症状举例 | 抵触的本体系纪律 |
|---|---|---|
| 流程截胡 | 强制动手前先走另一套工作流/门禁（brainstorming 硬门、plan→execute 引擎、"任何响应前必须先调某 skill"） | `00-流程总纲.md` 的 Triage→10 步 |
| 产物路径 | 要求 spec/plan/report 写入其他目录或项目根 | `文档治理.md` |
| 工作区纪律 | 禁止建 worktree、强制在主工作树直接开发、或另一套分支/合并门禁 | `worktree开发纪律.md` |
| 代码事实来源（团队版） | 强制 grep / 其他检索方式作为权威事实来源 | `mode-team.md` 的 ctx + cite 纪律 |
| 沟通方式 | 强制一问一答、要求用技术语言向用户确认详细程序设计 | `用户沟通纪律.md` |

**不算冲突**：纯领域能力（画图、文档格式化、某 API 用法等）、与流程无关的编码规范、只在用户显式调用时生效且不抢流程的 skill。宁缺勿滥：拿不准的标为"疑似"交用户判断，MUST NOT 自行定性并移除。

## 处置流程

1. 扫描是事实收集，自动完成，不问用户。
2. 有冲突 → 输出冲突清单并**批量**抛给用户决断（初始化时与 mode 问题同一批，不一问一答），每项含：
   - 来源文件（相对路径）
   - 冲突点（引用原文关键句，一句即可）
   - 抵触的本体系纪律（上表右列）
   - 建议：**移除 / 修改 / 保留** 三选一 + 一句理由（业务语言）
3. 按用户逐项决断执行：
   - **移除** → 删除该文件（或用户指定的禁用方式），并复述删了什么。
   - **修改** → 最小化编辑冲突语句，保留其余内容，并复述改了什么。
   - **保留** → 不动文件；本次会话内记住该冲突，流程走到相关步骤时以本体系纪律为准并提醒用户。
4. **未经用户逐项同意，MUST NOT 删除或修改任何用户的 rules/skills/agents。**
5. 无冲突 → 一句话报告（如"已扫描 N 个文件，无工作方式冲突"）后继续流程，不再打扰用户。

## 案例（初始化场景）

扫描发现项目自带 `.claude/rules/must-plan-first.md`，内含"任何代码改动前必须先输出完整实施计划并等待批准"。判定为**流程截胡**（抵触 `core/00-流程总纲.md` 的 Triage 分流——Lean 小改动不需要完整计划）。与 mode 询问同一批抛出：

> 1. 这个项目用 ai-dev-workflow 的哪种模式？个人版 / 团队版
> 2. `.claude/rules/must-plan-first.md` 要求"任何代码改动前必须先输出完整实施计划并等待批准"，与本流程的 Lean 直接实现路径冲突。建议：**修改**——限定为"仅大需求需要完整计划"，与 Triage 分流一致。移除 / 修改 / 保留？

用户答"个人版 + 修改"后：先最小化编辑该 rule 的冲突语句并复述改了什么，再注入个人版 mode 片段，继续流程。
