# 环境冲突扫描：检查项目自带的指令与扩展（CLAUDE.md 正文 / skills / agents / commands）与本体系的工作方式冲突

> 触发时机（仅两种，其余场景不读本文件）：
> 1. **初始化**：首次在项目调用 skill、询问协作面时执行，冲突决断与协作面询问同一批抛出（见 `init-初始化.md`）。
> 2. **体系扫描**：用户显式要求"扫描 / 体检 / 检查项目的 ai-dev 体系"时单独执行（标记块已存在时不重问协作面）。

## 扫描范围

逐个读取以下位置：有 frontmatter / 开头指令段的读到能判定其工作方式即可，`CLAUDE.md` / `AGENTS.md` 这类纯正文的通读一遍找指令性句子，都不必全文精读。

- 项目根 `CLAUDE.md` 与 `AGENTS.md` 里**标记块之外的正文**——项目级流程指令最常见的落点，"任何改动前先出完整计划""不要建分支，直接在主干改""所有文档写进 /doc" 这类句子典型地写在这里，且每次会话都会被读进上下文。
- 项目根 `.claude/skills/*/SKILL.md`
- 项目根 `.claude/agents/` 下的 agent 定义
- 项目根 `.claude/commands/` 下的自定义斜杠命令（用户敲一条命令就能把流程带走，判据与 skill 同一套）
- 项目根 `.agents/skills/*/SKILL.md`（Codex 入口，若存在）

**排除**本体系自装内容：`ai-prd/`、`ai-dev-workflow/` 两个 skill 目录、`ai-dev-system.version` stamp，以及 `CLAUDE.md` / `AGENTS.md` 里由本体系写入的两个标记块（`<!-- ai-dev-workflow:start -->…<!-- ai-dev-workflow:end -->` 与 `<!-- ai-dev-system:codex-conflicts:start -->…<!-- ai-dev-system:codex-conflicts:end -->`）——把自己的声明当冲突扫出来只会制造噪音。文件或目录不存在则跳过。

安装器（install.mjs）已在项目级禁用 4 个已知冲突**插件**（superpowers 等）；本扫描针对的是**项目自带的**指令正文与自定义 skills/agents/commands，是安装器的补充，不重复处理插件。

## 冲突判定（只看工作方式，逐条对照）

命中任一类即记为冲突候选：

| 冲突类别 | 症状举例 | 抵触的本体系纪律 |
|---|---|---|
| 流程截胡 | 强制动手前先走另一套工作流/门禁（brainstorming 硬门、plan→execute 引擎、"任何响应前必须先调某 skill"） | `00-流程总纲.md` 的 Triage→10 步 |
| 产物路径 | 要求 spec/plan/report 写入其他目录或项目根 | `文档治理.md` |
| 工作区纪律 | 禁止建 worktree、强制在主工作树直接开发、或另一套分支/合并门禁 | `worktree开发纪律.md` |
| 代码事实来源 | 强制 grep / 其他检索方式作为**权威事实来源** | `core/代码事实纪律.md` §3 的取事实顺序与 §5 的 cite 纪律，**无条件适用**（卡片层是必备资产，不存在"这个项目不查卡片"的情形）：项目规则把 grep 定为"哪个是权威实现 / 这个能力落在哪个仓"的**事实来源**时 MUST 记为冲突。**结构性检索另算**——符号定义 / 调用链 / 影响面按 `capability/graph.md` §2 处理：探测到代码图谱时该节对"先查图谱"是 SHOULD 级、但对"直接开全仓 grep"是 **MUST NOT**，项目规则把全仓 grep 定为这四类问题的**首选检索通道**时 MUST 记为冲突，只把它当图谱之外的辅助手段时至多标疑似；没有代码图谱的项目里，"用 ripgrep 全仓找实现"本身并不抵触本体系（`core/上下文卫生.md` 规则 4 只要求把重探索外包给子代理，读到的结论仍 MUST 按 `core/代码事实纪律.md` §4 落成卡片），此时至多标为**疑似**。以上各种情况都 MUST NOT 中止流程，也 MUST NOT 建议用户移除他正常的检索规则 |
| 沟通方式 | 强制一问一答、要求用技术语言向用户确认详细程序设计 | `用户沟通纪律.md` |

**不算冲突**：纯领域能力（画图、文档格式化、某 API 用法等）、与流程无关的编码规范、只在用户显式调用时生效且不抢流程的 skill。宁缺勿滥：拿不准的标为"疑似"交用户判断，MUST NOT 自行定性并移除。

## 处置流程

1. 扫描是事实收集，自动完成，不问用户。
2. 有冲突 → 输出冲突清单并**批量**抛给用户决断（初始化时与协作面问题同一批，不一问一答），每项含：
   - 来源文件（相对路径）
   - 冲突点（引用原文关键句，一句即可）
   - 抵触的本体系纪律（上表右列）
   - 建议：**移除 / 修改 / 保留** 三选一 + 一句理由（业务语言）
3. 按用户逐项决断执行：
   - **移除** → 删除该文件（或用户指定的禁用方式），并复述删了什么。冲突落在 `CLAUDE.md` / `AGENTS.md` 正文里时，"移除"只指**删掉那几句**，**MUST NOT 删除或清空这两个文件本身**。
   - **修改** → 最小化编辑冲突语句，保留其余内容，并复述改了什么。
   - **保留** → 不动文件；本次会话内记住该冲突，流程走到相关步骤时以本体系纪律为准并提醒用户。
4. **未经用户逐项同意，MUST NOT 删除或修改任何用户的 rules/skills/agents。**
5. 无冲突 → 一句话报告（如"已扫描 N 个文件，无工作方式冲突"）后继续流程，不再打扰用户。

## 案例（初始化场景）

扫描发现项目根 `CLAUDE.md` 标记块之外的正文里写着"任何代码改动前必须先输出完整实施计划并等待批准"。判定为**流程截胡**（抵触 `core/00-流程总纲.md` 的 Triage 分流——Lean 小改动不需要完整计划）。与协作面询问同一批抛出：

> 1. 这个项目除你之外，还有其他人一起开发吗？
>    - 没有，只有我（我 + AI 也算"只有我"）
>    - 有其他人（同事 / 外包 / 开源协作者）
> 2. 做完之后怎么并回主干？建议「本地直接合并」（没检测到远端仓库与 CI 配置）：
>    - **本地直接合并**：门禁全过后在你本机把任务分支合进主分支。
>    - **推 PR 走平台**：推分支开 PR，评审与 CI 通过后由平台合并。
> 3. `CLAUDE.md` 里要求"任何代码改动前必须先输出完整实施计划并等待批准"，与本流程的 Lean 直接实现路径冲突。建议：**修改**——限定为"仅大需求需要完整计划"，与 Triage 分流一致。移除 / 修改 / 保留？

（三问同一批抛出，措辞与批次的权威定义在 `init-初始化.md` §流程 第 4 步：全部用业务语言问，**MUST NOT 把 `solo` / `team` / `direct` / `pr` 这些字段值抛给用户认**。）

用户答"只有我一个人 + 本地直接合并 + 修改"后：先最小化编辑 `CLAUDE.md` 正文里那一句并复述改了什么（只动那一句，标记块与其余正文不碰），再按 `collaboration="solo"` + `merge-gate="direct"` 注入配置片段（见 `init-初始化.md` §流程 第 5 步），继续流程。
