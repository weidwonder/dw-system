# 初始化：把协作面写入 CLAUDE.md / AGENTS.md

> 首次在某项目唤起 skill、且两个入口都找不到标记块时执行。**只问一个问题（协作面）+ 一条待拍板的合并方式建议**，之后固化。
> **能力位不问**——项目有哪些代码事实资产（图谱位 / 权威位）由 `SKILL.md` §路由逻辑第 1 步**每次运行探测**得出，MUST NOT 写进标记块：写成配置，项目一长大它就过期。
> 本文按 RFC 2119 解释 MUST / MUST NOT / SHOULD / MAY。

## 流程

> **第 1–4 步只读文件、只与用户对话，MUST NOT 落盘任何东西。**
> 注入（第 5 步）与冲突处置的写盘 MUST 发生在**过完工作区隔离门、进入 worktree 之后**
> （`core/worktree开发纪律.md` §工作区隔离门 第 4 步）。两个原因：
> ① 隔离门要检查主工作树是否干净，在门前写 `CLAUDE.md`/`AGENTS.md` 会把它弄脏，
>    于是**每个项目第一次唤起本 skill 都会被自己的门拦在门外**；
> ② 在主工作树写下的标记块**不会出现在随后新建的 worktree 里**（worktree 是从主分支检出的），
>    配置就此悬在未提交状态，下次唤起读不到块又要重新初始化一遍。
> 落在 worktree 内则随本次任务分支提交、随合并门回到主分支，冲突处置也因此可评审、可回退。
>
> **用户只要求"初始化 / 配一下这个体系"、后面没有别的任务时**：初始化本身就是本次任务，
> 同样建任务分支与 worktree、同样走完合并门，MUST NOT 因为"只是改两个配置文件"就跳过。

1. **检测**：读项目根的 `CLAUDE.md` 与 `AGENTS.md`，查找标记块：
   ```
   <!-- ai-dev-workflow:start -->
   ... collaboration="solo|team" merge-gate="direct|pr" worktree-dir="./.worktrees/" ...
   <!-- ai-dev-workflow:end -->
   ```
   - 任一入口的块内**有 `collaboration`** → **不是初始化**：直接读出字段走路由，把同一标记块幂等同步到另一入口，不再询问。
   - 块存在，但**只有旧版安装留下的 `mode` 字段、没有 `collaboration`** → **也不是初始化**：走下方 §从旧标记块推断协作面（只做一次）。
   - 两个入口都没有块 → 继续第 2 步。

2. **冲突扫描**：按 `references/环境冲突扫描.md` 扫描项目自带的 `.claude/`、`.agents/` 下
   rules/skills/agents，产出冲突清单（可能为空）。扫描是事实收集，自动完成，不问用户。

3. **探测与取证（自动完成，一个都不问用户）**：

   | 探测什么 | 怎么看 | 用途 |
   |---|---|---|
   | **能力位** | `.codegraph/codegraph.db` 是否存在；`engineering-context/capability-registry.md` 是否有不含【】占位的真实数据行 | 只决定本次加载哪些 `capability/` 分册。MUST NOT 写进标记块，MUST NOT 据此追问用户"要不要建资产"（补建建议只由结果性信号驱动，见 `core/资产补建信号.md`） |
   | **`merge-gate` 建议** | 有 git 远端（`git remote`）**且**存在 `.github/workflows/` 或等价 CI 配置 → 建议 `pr`；否则建议 `direct` | 只是**建议**，第 4 步交用户拍板。这是初始化时给用户的建议值，**与字段已缺失时的非交互兜底不是同一件事**（后者的唯一权威定义在 `core/worktree开发纪律.md` §完成与自动合并门） |
   | **三层真相源缺口** | 按 `core/文档治理.md` §三层真相源 看需求 / 架构 / 实现是否各有其一、能否从 README 或 `docs/index.md` ≤2 跳到达 | 第 6 步**报告**，不阻断 |

4. **询问**（仅当两入口都无块）：一次抛全，不一问一答。

   > 1. **这个项目除你之外，还有其他人一起开发吗？**
   >    - 没有，只有我（我 + AI 也算"只有我"）
   >    - 有其他人（同事 / 外包 / 开源协作者）
   > 2. **做完之后怎么并回主干？** 建议「<按第 3 步探测给出的那一项>」，理由一句话（如"检测到远端仓库和 CI 配置，建议走 PR"）：
   >    - **本地直接合并**：门禁全过后在你本机把任务分支合进主分支。
   >    - **推 PR 走平台**：推分支开 PR，评审与 CI 通过后由平台合并。

   两问都用业务语言问，MUST NOT 把 `solo` / `team` / `direct` / `pr` 这些字段值抛给用户认。
   若第 2 步冲突清单非空，把冲突决断（逐项 移除/修改/保留 + 建议）与上面两问**同一批**抛出。
   用户答复即为**决断已定**，但**处置动作（删除/编辑用户的 rules/skills/agents）与注入一样延后到
   worktree 内执行**——它们改的是用户的文件，落在主工作树等于绕过隔离门，且不可评审。

   **MUST NOT 问的三类**：项目有哪些代码事实资产 / 用哪一档（探测得出）；`worktree-dir`（有默认值，用户主动要求换位置时才改）；代码规模或行数（不是任何判据）。

5. **注入**（幂等，**在 worktree 内执行**）：把 `assets/config-snippets/base.md` 的块内内容 + `assets/config-snippets/collab-<collaboration>.md` 的块内内容**按序拼接**，用**一个**标记块包裹，写入 worktree 内项目根的 **两个** 文件：

   - `CLAUDE.md`（Claude Code 自动加载）
   - `AGENTS.md`（Codex 自动加载）

   属性行按下表填实，MUST NOT 留 `solo|team` 这类占位：

   | 字段 | 写什么 |
   |---|---|
   | `collaboration` | 第 4 步问题 1 的答复：`solo` / `team` |
   | `merge-gate` | 第 4 步问题 2 用户拍板的值：`direct` / `pr` |
   | `worktree-dir` | 默认 `./.worktrees/`；用户指定过就写用户给的路径 |
   | `mode` | 恒写 `team`，**与 `collaboration` 的实际取值无关**。这是给旧版 skill 读的**墓碑字段**（防止未重跑安装器的同事读不到字段而重新初始化），新版完全忽略它：MUST NOT 用它做任何判断，块**正文**里 MUST NOT 出现它的旧语义说法。`3.0.0` 移除。<br>**为什么恒写 `team` 而不随协作面写值**：旧版的两个取值里 `team` 是行为上的**超集**（它多出的是对齐 owner、走 PR 这类"多做一步"的约束）。旧 skill 读到 `team` 只会让单人项目多做几步对齐动作，读到另一个值却会让协作项目**少做**该做的对齐——两种误判的代价不对称，所以恒取失败偏安全的那一侧。写一个"精确但可能偏危险"的值，不如写一个"粗糙但偏安全"的值 |

   - **文件**不存在则创建；文件已存在**而其中没有标记块** → 在末尾追加（不动其它内容）；
     已有标记块的一律按下方 §幂等规则 替换块内内容，MUST NOT 再追加一个。
   - **写之前先按下方「入口是软链接时」判断**：任一入口是软链接时，写的对象是链接目标，不是链接本身。

6. **报告三层真相源缺口**（报告，不阻断）：把第 3 步查出的缺口一句话说清——缺哪层、补它的**最小形态**是什么（判据与最小形态表见 `core/文档治理.md` §三层真相源：需求 = README 一节或 `docs/index.md`；架构 = README 里一节"架构与边界"，短到 10 行也算；实现 = 代码本身 + 子代理外包探索），然后**继续流程**。

   - MUST NOT 替用户创建 `REQUIREMENTS.md` / `ARCHITECTURE.md` / `docs/index.md`，MUST NOT 为了归档而临时造一个索引（`core/文档治理.md`）。
   - MUST NOT 把"补齐三层真相源"设成开始开发的前置条件——旧项目补齐需要时间，卡住只会让用户绕开整个流程。
   - 无缺口时一句话带过，不展开。

## 从旧标记块推断协作面（升级路径，只做一次）

**触发条件**：标记块存在、含旧版安装留下的 `mode` 字段、**不含** `collaboration`。这是"同事升级并提交了新配置 / 本项目还是旧配置"的必然窗口，不是异常。

**映射**（MUST 照此，MUST NOT 自行发挥）：

| 读到的旧值 | 推出 |
|---|---|
| 旧值为 `team` | `collaboration="team"` + `merge-gate="pr"` |
| 其余旧值（含无法识别的值） | `collaboration="solo"` + `merge-gate="direct"` |
| 块里已有 `worktree-dir` | 原样保留；没有则写默认 `./.worktrees/` |

**三条硬约束**：

- **只推协作维度。** MUST NOT 由旧值推出任何能力位，MUST NOT 用它改变 Triage 的默认假设——那两件事只认运行时探测（`SKILL.md` §路由逻辑第 1 步、`core/00-流程总纲.md` §默认倾向（四问全否之后））。一个旧配置里写着协作项目、但没建任何代码事实资产的仓库，升级后就是直读，这是设计意图。
- **告知一次，然后回写。** 用下面的文案一句话告知推断结果，**允许用户当场改**，随后按上方第 5 步的注入规则幂等回写**两个入口**。回写后块已含显式字段，下次唤起走正常路径——**MUST NOT 每次唤起重复提示**。
- **告知是通知，不是提问。** MUST NOT 因为等用户回应而挂起流程：没有异议就按推断值继续；用户随后纠正，就改字段再幂等回写一次，不再重复告知。

**告知文案**（照此措辞，只填推断结果；MUST NOT 提"旧版本把项目分成哪几类"这种已废弃的说法，也 MUST NOT 说"你原来是哪一类"）：

> 这个项目的配置是早前版本写的，只有一个笼统的模式声明。我据此补了两项显式设置：**这个项目有其他人一起开发**、**做完推 PR 由平台合并**。两项都已写进 `CLAUDE.md` 与 `AGENTS.md`。如果不对——比如其实只有你一个人开发，或想改成在本地直接合并——现在说一声，我当场改。

推断为 solo 时同一句替换后两项即可：

> …我据此补了两项显式设置：**这个项目只有你一个人开发**、**做完在本地直接合并**。两项都已写进 `CLAUDE.md` 与 `AGENTS.md`。如果不对，现在说一声，我当场改。

**若这次回写会改掉另一入口已有的显式 `collaboration` / `merge-gate` 值，MUST 在上面的文案后追加 §幂等规则 里那一句「被覆盖的是什么」**——不追加的话，用户明确配过的设置被静默改掉而毫无察觉。

**只有回写这一段由 `ai-dev-workflow` 做**（`ai-prd` 不写文件，保证不了"只告知一次"）；但**协作面的只读推断两个 skill 用同一套判据**（旧 `mode="team"` → team，其余 → solo），MUST NOT 各判各的，见 `ai-prd/SKILL.md` §路由逻辑第 1 步。

## 幂等规则（重要）

- **只更新标记块内的内容，绝不重复追加**。重复调用初始化时：
  - 若标记块已存在 → 用新内容**替换块内**，保留块外一切。
  - 若不存在 → 追加一个新块。
- **两个入口必须收敛**：只有 `CLAUDE.md` 或只有 `AGENTS.md` 有标记块时，自动补齐另一文件；两边字段不一致时，以 `CLAUDE.md` 为准并同步到 `AGENTS.md`。
  **只要这次同步会改掉另一入口已有的显式 `collaboration` / `merge-gate` 值，就 MUST 告知**（不限于旧 `mode` 那一种）。最常见的两种：`CLAUDE.md` 只有旧 `mode` 而 `AGENTS.md` 已有显式 `collaboration`；两边都是显式值但不一致。口径一律以 `CLAUDE.md` 为准（与安装器 `install.mjs` 同一套判据，两边 MUST NOT 各写一套），但 MUST 在告知文案里**多说一句**被覆盖的是什么：

  > 另外，`AGENTS.md` 里原本写着「<原值的业务语言说法>」，已按 `CLAUDE.md` 的声明统一成上面这两项。如果原来那个才是对的，现在说一声，我改回去。

  这一句 MUST NOT 省——不说的话，用户明确配过的设置被静默改掉，而他不会有任何察觉。
- **块内 MUST NOT 出现第二对标记**：整份 `CLAUDE.md` / `AGENTS.md` 里 `<!-- ai-dev-workflow:start -->` 与 `<!-- ai-dev-workflow:end -->` 各 MUST 只出现一次。块内又出现一对（典型成因：把 `collab-*.md` 连标记一起抄了进来）即视为**块已损坏**，MUST 按"`base.md` 块内内容 + `collab-<collaboration>.md` 块内内容"重建整块（字段值从损坏块里能读到的部分沿用，读不到的按第 4 步重新确认），MUST NOT 只删掉多出来的标记行了事——嵌套一旦发生，块尾那段协作正文可能已在上一次写入时被截断丢失。
- **值非法不猜**：`collaboration` 不是 `solo`/`team`、`merge-gate` 不是 `direct`/`pr` 时，报错中止并列出合法值域，MUST NOT 替用户挑一个。
- 标记用 HTML 注释，对 markdown 渲染无影响，且机器可精确定位。

## 入口是软链接时（重要）

很多项目让 Claude Code 与 Codex **共用一份指导文件**，做法是把 `AGENTS.md` 软链接到 `CLAUDE.md`（反向亦有，也可能两者都链到仓库外的共用文件）。这种链接是用户的刻意配置，**任何写入都必须保留它**。

写 `CLAUDE.md` / `AGENTS.md` 之前，先各判断一次（例如 `ls -l CLAUDE.md AGENTS.md`，或 `readlink CLAUDE.md`（POSIX）/ `Get-Item CLAUDE.md | Select-Object LinkType,Target`（Windows PowerShell），或直接用 harness 的文件工具判断）：

- **不是链接** → 按上面的幂等规则直接写这个文件。
- **是链接** → 逐层解析到实体文件，**把实体文件当作写入对象**，对它照常判断"替换块内"还是"追加新块"。链接本身不删、不改、不替换成普通文件；不要用"先删再建"或整文件覆盖的写法。
- **两个入口解析到同一个实体文件** → 这就是共用一份的情形：**只写一次**，不要把同一标记块注入两遍。此时"两个入口都要有标记块"天然满足，不必再补第二次。
- **断链**（链接目标不存在，或目标所在目录不存在）→ **停下来问用户**，不要新建实体文件把链接顶掉。这通常意味着用户的共用文件被移走了。

## 切换协作面

用户显式要求切换时（如"这个项目现在有其他人一起接手了""以后只有我一个人维护"）：

- 找到标记块，把 `collaboration` 改成新值，并把块内的协作段替换为另一份 `collab-<collaboration>.md` 的**块内内容**（`<!-- ai-dev-workflow:start -->` 与 `<!-- ai-dev-workflow:end -->` 之间的正文，**MUST NOT 把这两行标记一起写进去**——两个 `collab-*.md` 各自带一对完整标记，照抄整份文件会在标记块内部再嵌一对，此后任何"替换首个 start 与首个 end 之间"的写入都会在嵌套的 `end` 处截断，静默丢掉协作段）；`base.md` 那段与其余字段不动。
- **MUST NOT 顺手改 `merge-gate`**——合并方式是独立字段，用户没说就不动；确有必要时单独问一句。
- **切换协作面不影响能力位**：项目有哪些代码事实资产照常探测。MUST NOT 借切换的机会推销建资产——要不要建由结果性信号驱动的补建建议决定（`core/资产补建信号.md`，那是建议不是门）。
- 用户**主动**要求建立权威代码事实时，给最小起步方式：`ctx init --minimal`（只生成 `engineering-context/capability-registry.md`，三列三行即可起步），填过一行真实数据后，权威位下次唤起自动被探测到。

## 写入示例

见 `assets/config-snippets/base.md` 与 `collab-solo.md` / `collab-team.md`——注入标记块内的原文就是"`base.md` 块内内容 + 对应 `collab-*.md` 块内内容"的拼接。
