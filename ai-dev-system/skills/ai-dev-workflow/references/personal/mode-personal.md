# 个人版外壳（personal mode）

> 加载条件：项目 mode = personal。在 `core/` 之上，本文件定义"一个人做轻量项目"的默认与裁剪。

## 核心默认

1. **默认走一页 Lean Change Spec**。除非需求确实复杂，否则一律先假设 Triage 4 问全否，用 `assets/templates/lean-change-spec.md` 一页搞定，直接实现。
2. **流程可跳步**。个人项目里 Step 3（PRD 细澄清）、Step 2（Overview）通常省略——你既是产品又是技术，没有协作方要对齐。
3. **不需要评审会 / 多仓协作 / owner 归属**。这些团队机制在个人版全部关掉。
4. **无 Engineering Context 层 / 无 ctx CLI**。个人项目仓库你自己熟，直接读代码即可，不建 card 体系。
5. **目录不裁剪**。轻量不等于散放：spec 仍写 `docs/spec/`，plan 写 `docs/plan/`，report 写 `docs/report/`。
6. **沟通纪律不裁剪**。用户只确认业务目标、业务边界和必要的大架构；模块内设计通过业务问题取约束；详细程序设计直接完成，不发起技术确认。
7. **worktree 与自动合并不裁剪**。再小的 Lean 改动也先进入独立 worktree；全部验证通过后自动合并主分支，失败则保留 worktree，不直接修改主工作树。

## 什么时候升级到完整流程

即使是个人版，遇到下面情况建议升级（走 Step 2/4/6）：

- 改动**跨多个仓库**或影响面自己都说不清。
- 引入 **AI/LLM 行为**（叠加 `core/AI-LLM-overlay.md`，个人项目也值得把 AI 契约写清，否则最难调）。
- 改动**鉴权/安全/数据不可逆**。
- 复杂到"两周后自己都看不懂当初为什么这么写"——写一份精简 Overview 是给未来的自己省时间。

## 个人 memory 约定

个人版最大的复利来自**把决策沉淀下来**，而不是每次重新想：

- 用你的 AI 工具的 memory 机制（Claude Code 的 memory / Codex 的 AGENTS.md）记录：**非显而易见的**技术决策、踩过的坑、项目特有约定。
- 不记录代码本身已经能说明的东西（结构、历史 fix）。
- 每条 memory 一个事实，写清"为什么"，方便未来判断它是否还成立。

## 一句话

个人版 = `core` 的流程纪律 + 模板，**砍掉一切协作开销**，默认最短路径，只在真正复杂时才加重。
