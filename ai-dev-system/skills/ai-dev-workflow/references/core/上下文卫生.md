# 上下文卫生（core）

> 目的：让关键决策发生在模型推理质量最高的上下文区间，避免"上下文越长越糊涂"侵蚀 spec/plan 质量。
> 适用：整个流程（Step 1–10），两个协作面（solo / team）下同样适用，与项目有没有代码图谱无关。本文按 RFC 2119 解释 MUST / SHOULD。

## 1. 聪明区（smart zone）

上下文窗口的**前半段**推理最清晰；越靠近窗口上限，遗忘、自相矛盾与幻觉越多。经验值：把窗口前 ~60%（如 200k 窗口的前 ~120k token）当作"聪明区"，**方向性决策 SHOULD 在聪明区内完成**——需求澄清、Overview、spec 取舍、coding plan 拆分都属于方向性决策；机械执行（照 plan 写代码）对聪明区要求最低。

> 为什么是 SHOULD 而不是 MUST：agent 通常**读不到自己当前的 token 占用**，"有没有超过 60%"严格说不可自判，写成 MUST 就是一条无法核对的硬约束。可判定的落点是 ↓ §2 规则 5 的三个**可观察**过载信号——以它们为准。规则 2 的 MUST 也挂在同一组信号上，MUST NOT 挂回"逼近 60%"这个不可自判的量。

## 2. 五条规则

1. **决策链保持连续**：需求澄清 → Overview/spec → coding plan SHOULD 在同一连续会话内完成，中途不插入无关任务——plan 的质量依赖它能"看见"全部澄清过程。
2. **交接，不硬撑**：出现 ↓ 规则 5 任一**可观察**过载信号、而决策链未走完时，MUST 写一份**交接文档**（已定决策表 / 未定开放问题 / 证据与 cite / 下一步）再开新会话继续，而不是硬撑到窗口极限，也不依赖自动压缩——压缩丢逐字细节且不可控，交接文档是显式筛选过的记忆。交接文档落任务 worktree 内的 `docs/plan/<feature>-handoff.md`（见 `文档治理.md` 默认命名）。
3. **编码任务零上下文起步**：coding plan 本就按"执行者零上下文"标准编写（Step 6），所以执行侧天然可切换会话。连续执行多个任务后上下文变重时，SHOULD 在 checkpoint 处收尾，让新会话（或子 agent）只带 plan 从下一个任务继续；任务间 MUST NOT 依赖"上个任务的会话记忆"传递信息——该传递的信息必须写在 plan 的 Interfaces 里。
4. **重探索外包**：大范围代码探索、全仓检索、多方案对比这类"读得多、结论少"的工作，harness 支持子 agent 时 SHOULD 交给子 agent，主会话只收结论（编码后的四轴代码评审更进一步，是 MUST 交子代理——见 `代码评审纪律.md`）——不让海量文件内容冲刷主上下文。**取事实的顺序不变**：先用 `ctx` 查卡片（本身就是省上下文的权威入口，见 `代码事实纪律.md` §3），探测到代码图谱时结构性检索优先查它（见 `capability/graph.md`），两者都收不窄时才是子 agent 读码。
   **外包不豁免补卡**：子代理返回结论后，主会话 MUST 按 `代码事实纪律.md` §4 把结论落成卡片（最小四项，带 `文件:行`）并随本次分支提交——否则这份结论只活在这一次会话里，下次唤起 `ctx` 依然查不到，等于把探索成本原样留给下一个 agent。子代理只报告、不落盘，所以这件事 MUST 由主会话做，MUST NOT 指望子代理顺手写掉。
5. **识别过载信号，立即交接**：开始忘记已拍板的决策、重复问已答过的问题、引用不存在的文件/函数——任一出现即视为上下文过载，MUST 按规则 2 交接，不再"再撑一会儿"。

## 3. 决策沉淀进 memory

交接文档解决"这一条决策链怎么跨会话续上"，memory 解决"这个项目的决策怎么跨任务积累"。两者都不可省，且**与协作面无关**——一个人做项目时复利来自不用每次重新想，多人协作时同一条 memory 还替下一个人（和下一个零上下文 agent）省掉一次口头介绍。

- SHOULD 用所在 AI 工具的 memory 机制（Claude Code 的 memory / Codex 的 `AGENTS.md`）记录三类内容：**非显而易见的**技术决策、踩过的坑、项目特有约定。
- **MUST NOT 记录代码本身已经能说明的东西**（目录结构、类型定义、历史 fix 的实现细节）——它们会随代码漂移，且读代码更准。
- 每条 memory **一个事实**，并写清"为什么"，方便未来判断它是否还成立。
- memory 与落盘文档的分工：需要被引用、被评审、被 cite 的结论 MUST 进 `docs/`（见 `文档治理.md`），memory 只放"下次开工前想知道、但不值得单独成文"的短事实。

## 4. 与其他纪律的关系

- 交接文档遵循 `spec写作纪律.md`（零上下文可动手、无占位符）——它的读者就是那个零上下文的新会话。
- worktree 纪律不受会话切换影响：新会话在同一任务 worktree 内继续，完成门照走。
- 本纪律不改变"大架构必须用户确认"（用户沟通纪律）：交接不能把未确认的决策带成"已确认"。
