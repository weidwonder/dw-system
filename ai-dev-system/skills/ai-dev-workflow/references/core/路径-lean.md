# Lean 路径（一页走完）

> 加载条件：Step 0 Triage 四问全否。读完本页就能把这次改动做完，**不需要读 `步骤-1-7-设计与实现.md` 与 `步骤-8-10-测试.md`**。
> Lean 的轻量体现在"文档只有一页、跳过 Step 1–10"，**不体现在跳过门**——四道门一道都不能少。
> 分流默认假设由**能力位**决定（与协作面无关，见 `00-流程总纲.md` §默认倾向（四问全否之后））：无能力位与只有图谱位 → 默认走 Lean；含权威位 → **影响面说不清**时升级到完整流程。
> **读到这里就说明四问已全否且默认倾向没命中。** 那四条"影响面说不清"的判据（跨 ≥2 个权威仓库 / out-of-scope 警告 / 关键事实给不出 cite / 得靠子代理外包）**只在探测到权威位时适用**，定义在 `00-流程总纲.md` §默认倾向（四问全否之后）；**未探测到权威位的项目（无能力位、只有图谱位）不适用**——没有 registry 就永远没有 cite，逐条套会让每个直读项目都被判成"说不清"，与默认倾向正好相反。这两类项目的升级判据同为"确实 hold 不住"一条。

## 顺序

| # | 动作 | 产出 / 判据 |
|---|---|---|
| 1 | **工作区隔离门**（已在路由后完成，未完成先补） | 独立 worktree，见 `worktree开发纪律.md` |
| 2 | 【bug 类才做】过红回路门 | 先查 `docs/report/bug修复历史.md`，再造出能变红的复现命令，见 `bug诊断纪律.md`。**回路不存在不许提假设、不许改代码** |
| 3 | 写一页 Lean Change Spec，**含〈既有系统清单〉** | `docs/spec/<change-name>-lean-change-spec.md`，模板 `assets/templates/lean-change-spec.md`。清单落 §影响范围 / 不做什么——它是 Lean 路径上替换清单与资产补建信号唯一的出处 |
| 4 | 填**兼容取舍**一行 + **替换清单**表；**命中就记资产补建信号** | 判据见总纲 §兼容取舍确认门、`代码评审纪律.md` §替换清单。替换清单出现"同一逻辑多处副本"、或第 3 步被迫打开 ≥2 个入手时不知道存在的模块 → 各记一条，判据与写法见 `资产补建信号.md` §1（**只记账，不阻断，不在这里问用户**） |
| 5 | **兼容取舍确认门**：把清单抛给用户拍板；**命中大架构判据时，同一批附上业务语言摘要过大架构确认门** | 用户逐条选定后才动手实现；无既有行为变更时显式写"无兼容取舍"。大架构判据见 `用户沟通纪律.md` §1，两件事一批抛出，不要分两轮问 |
| 6 | 实现 + **边写边删** | 被取代的旧逻辑当场删除，不留到"最后统一清理" |
| 7 | 跑"如何验证"里的命令 | 每条都真跑过，不靠"应该没问题" |
| 8 | 【命中判定才做】补端到端用例 | 跨 ≥3 组件 / 异步多阶段 / 有中间产物时**必须**有，且断言每个环节的中间产物，见 `测试资产纪律.md` §1 |
| 9 | 【有真实输入才做】固化测试样本 | 落 `tests/fixtures/<场景名>/`，凭证进 `secrets/` 并先确认 gitignore 生效，见 `测试资产纪律.md` §2 |
| 10 | **代码评审门**：派 1 个子代理跑三轴精简版 | 规范 / 忠实 / 残留，报告分三节写；P0/P1 修完才算过门。prompt 模板见 `代码评审纪律.md` |

## Lean 特有的三个提醒

- **拿不准就升级，别硬塞进一页**：Triage 有任何一问是 borderline，在 spec 的「Triage 复核」里写清哪一问、为什么倾向"否"；实在拿不准就升级回完整流程（读 `步骤-1-7-设计与实现.md`）。中途发现影响面变大（跨服务、要迁数据、动了对外承诺）同样立即升级，不要将错就错走完。
- **验收标准别只写 happy path**：小改动最常翻车在异常路径——边界值、空值、并发、依赖不可用各留一条可勾验的验收项。
- **Lean 不等于不写测试**：第 8/9 步的判定命中就照做，协作面为 solo 时也不压缩。压缩的是文档篇幅，不是验证强度。

## 与用户沟通

全程业务语言（见 `用户沟通纪律.md`）。Lean 路径通常只需要用户在两处表态：**兼容取舍**（第 5 步）和**验收标准是否是他要的**。其余技术决策自主完成，不要拿实现方案去问用户。

**例外只有一个：改动命中大架构判据时，多一件事要用户确认**——产品或技术架构的**主干路形状**变了（形状变才算，取值变不算；判据与正反例见 `用户沟通纪律.md` §1）。Lean 从不产出 Overview，所以这道门在本路径上**只能挂在第 5 步**：与兼容取舍同一批抛业务语言摘要，用户确认后才实现。改动小 MUST NOT 作为豁免理由——三行代码把单人审批改成两级会签，和三百行改成两级会签是同一件事。
