# 文档治理（core）

所有 mode 使用同一套项目级输出目录。生成文档前先创建所需目录，不得把交付物散落到项目根或 `docs/` 根。

| 文档类型 | 唯一目录 | 示例 |
|---|---|---|
| 整品 PRD（唯一真相源）及其附录 | `docs/` 根 | `docs/REQUIREMENTS.md`、`docs/REQUIREMENTS-appendix.md` |
| 变更 PRD、Overview、Lean Change Spec、技术 Spec、测试 Spec、设计、契约 | `docs/spec/` | `docs/spec/payment-lean-change-spec.md` |
| Coding Plan、实施计划、迁移计划、交接文档（上下文交接） | `docs/plan/` | `docs/plan/payment-coding-plan.md` |
| 执行报告、验证报告、测试报告、审计报告 | `docs/report/` | `docs/report/payment-verification-report.md` |
| Bug 修复历史（持续追加账本，见下方例外说明） | `docs/report/` | `docs/report/bug修复历史.md` |
| 测试场景覆盖度台账（持续追加账本，见下方例外说明） | `docs/report/` | `docs/report/测试场景覆盖度.md` |
| 测试资产（真实输入样本，**不是文档**） | 项目测试目录，探测优先 | `tests/fixtures/<场景名>/` |
| 架构决策记录（ADR）| `docs/decisions/` | `docs/decisions/0007-use-outbox-for-mq.md` |

## ADR（架构决策记录，按需）

日常小决策记进 Overview 的"已定决策"一行表即可；只有**影响面大、以后可能被反复重议**的架构级取舍才单独立 ADR：

- 顺序编号存 `docs/decisions/NNNN-<短标题>.md`；每篇写 **Context（为什么要决策）/ Decision（定了什么）/ Alternatives Considered（考虑过哪些方案、为何否）/ Consequences（代价与影响）**。
- **不删旧 ADR**：决策被推翻时，写一篇新 ADR 引用并 supersede 旧的，保留决策演进史（防止把同一问题反复重决）。

## 硬规则

- 文件名必须表达业务主题与文档角色，不得使用生成工具名作为目录或文件名前缀。
- 不得创建 `docs/superpowers/`、`docs/claude/`、`docs/codex/` 等工具专属产物目录。
- 不得把 spec 或 plan 放项目根、仓库根或 `docs/` 根。唯一例外：整品 PRD（`REQUIREMENTS.md` 及其附录）作为唯一真相源放 `docs/` 根，便于发现。
- 同一需求的文档通过正文中的相对链接互相引用；移动文档时必须同步修复引用。
- `docs/index.md` 可以作为发现入口，但不能替代上述目录规则。
- 报告只有在流程要求形成书面报告时才创建；一旦创建，必须写入 `docs/report/`。
- **例外（两个固定文件名的单一持续追加账本）**：不按"每次新建一个 `<feature>-<report-type>-report.md`"的规则拆分——
  - `docs/report/bug修复历史.md`：写入规则见 `bug诊断纪律.md` Phase 3 §归档问题处理历史，供 Phase 0 查重检索。
  - `docs/report/测试场景覆盖度.md`：写入规则见 `测试资产纪律.md` §3，模板 `assets/templates/test-coverage.md`，供批量向用户索要真实素材。
- **测试资产不是文档**：用户提供的真实输入样本落项目**测试目录**（探测既有惯例，兜底 `tests/fixtures/<场景名>/`），MUST NOT 塞进 `docs/`。含凭证的样本进同级 `secrets/` 并 gitignore，脱敏副本 `secrets.example/` 入库。规则见 `测试资产纪律.md` §2。

## 默认命名

- Lean Change Spec：`docs/spec/<change-name>-lean-change-spec.md`
- Overview：`docs/spec/<project-name>-overview.md`
- 技术 Spec：`docs/spec/<repo>-<feature>-eng-spec.md`
- 测试 Spec：`docs/spec/<repo>-<feature>-test-spec.md`
- Coding Plan：`docs/plan/<feature>-coding-plan.md`
- 交接文档：`docs/plan/<feature>-handoff.md`（见 `上下文卫生.md` 规则 2；任务未完成时随任务 worktree 走，合并时若已无用可不带回主分支）
- 报告：`docs/report/<feature>-<report-type>-report.md`

项目已有更严格的文件名约定时可以沿用，但目录不可改变。
