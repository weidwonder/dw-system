# 文档治理（core）

所有 mode 使用同一套项目级输出目录。生成文档前先创建所需目录，不得把交付物散落到项目根或 `docs/` 根。

| 文档类型 | 唯一目录 | 示例 |
|---|---|---|
| PRD、Requirements、Overview、Lean Change Spec、技术 Spec、测试 Spec、设计、契约 | `docs/spec/` | `docs/spec/payment-lean-change-spec.md` |
| Coding Plan、实施计划、迁移计划 | `docs/plan/` | `docs/plan/payment-coding-plan.md` |
| 执行报告、验证报告、测试报告、审计报告 | `docs/report/` | `docs/report/payment-verification-report.md` |

## 硬规则

- 文件名必须表达业务主题与文档角色，不得使用生成工具名作为目录或文件名前缀。
- 不得创建 `docs/superpowers/`、`docs/claude/`、`docs/codex/` 等工具专属产物目录。
- 不得把 spec 或 plan 放项目根、仓库根或 `docs/` 根。
- 同一需求的文档通过正文中的相对链接互相引用；移动文档时必须同步修复引用。
- `docs/index.md` 可以作为发现入口，但不能替代上述目录规则。
- 报告只有在流程要求形成书面报告时才创建；一旦创建，必须写入 `docs/report/`。

## 默认命名

- Lean Change Spec：`docs/spec/<change-name>-lean-change-spec.md`
- Overview：`docs/spec/<project-name>-overview.md`
- 技术 Spec：`docs/spec/<repo>-<feature>-eng-spec.md`
- 测试 Spec：`docs/spec/<repo>-<feature>-test-spec.md`
- Coding Plan：`docs/plan/<feature>-coding-plan.md`
- 报告：`docs/report/<feature>-<report-type>-report.md`

项目已有更严格的文件名约定时可以沿用，但目录不可改变。
