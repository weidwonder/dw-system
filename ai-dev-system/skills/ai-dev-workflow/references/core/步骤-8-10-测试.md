# 完整流程 Step 8–10：测试

> 加载条件：完整流程走完 Step 7 且**代码评审门已过**（P0/P1 清零）。进入本阶段前不必再持有 `步骤-1-7-设计与实现.md`。
> 本阶段常在新会话或子 agent 里做——所需输入（PRD / Overview / spec / plan）都是文件，不依赖前面步骤的会话记忆。

## Step 8：生成测试 Spec

**输入** PRD（+ UI 原型 HTML，如有）+ Overview + spec + coding plan ｜ **产出** `docs/spec/YYYY-MM-DD-<repo>-<feature>-test-spec.md` ｜ **对应模板** `assets/templates/test-spec.md`

> **风险驱动 + 可实施**（见模板）：先按隐蔽缺陷清单识别高风险点，再设计测试；产出必须含 **API 调用模型** 与 **测试数据构造方案（Fixture）**，能直接落成测试代码，而不是只写业务场景与测试意图。守两条纪律：**输入权威等级**（PRD ≥ UI 原型 > 技术文档 > 实施方案 > 当前实现；**UI 原型在"用户可见行为"上与 PRD 同级**，且**原型元素上的 `data-anno` 说明、用户逐元素批注、全局反馈与用户对说明的回复都与界面同级**——界面内容 MUST 用 `node <skills 根>/ai-prd/scripts/preview.mjs extract <原型文件>`（`<skills 根>` = 你加载的这份 `SKILL.md` 所在目录的**父目录**——Claude Code 下是 `.claude/skills/`、Codex 下是 `.agents/skills/`，两侧内容一致，用你自己这一侧那份，**MUST NOT 写死其中一侧**） 取，批注 MUST 用 `node <skills 根>/ai-prd/scripts/preview.mjs annotations <原型文件>` 取，两条都跑完才算读过原型，MUST NOT 通读整份 HTML；两条命令都跑不起来时才降级为直读文件并在问题清单记一笔——它们只在悬浮气泡与批注块里，取回后一并作为用例来源，MUST NOT 只照渲染出来的界面设计用例；冲突时标"待确认"而非自行取舍）与 **"待确认"防脑补**（文档没定义的字段/错误码/表结构禁止脑补，标"待确认"）。

> **按 `测试资产纪律.md` 同步做三件事**：
> 1. **判端到端**：流程跨 ≥3 个组件/服务、或含异步多阶段、或有中间产物落盘落库时，**必须**设计端到端用例，且**每个环节的交接产物各写一条断言**，不许只断言末端结果（否则中间环节坏了要么测不出来，要么测出来也不知道坏在哪一环）。
> 2. **优先用真实样本**：Fixture 表里凡有真实样本可用的，直接引用 `tests/fixtures/<场景名>/` 下的文件（目录探测规则见该纪律 §2）；构造数据只用于真实样本覆盖不到的维度。用户提供的文件/报文/日志一律落盘固化，含凭证的进 `secrets/` 并 gitignore，同时留脱敏 `secrets.example/` 入库。
> 3. **更新覆盖度台账**：把识别出的高风险场景登进 `docs/report/测试场景覆盖度.md`（模板 `assets/templates/test-coverage.md`），暂时测不了的标 ❌ 缺素材并写清"需要用户提供什么"，攒批后再一次性问用户。

```text
# 参考 prompt
配合 PRD @【】、UI 原型 @【无则删除本项】、overview @【】、spec @【】、coding plan @【】，
对当前代码仓库涉及的内容增加测试方案。只专注当前仓库涉及的部分，功能代码已开发完成。
```

---

## Step 9：生成测试代码

**输入** 测试方案 ｜ **产出** 测试代码 ｜ 随后执行**单仓 test** 和**模拟链路 test**。

> 落测试代码时守住测试三反模式（清单见 `assets/templates/test-spec.md` §纪律）：不与实现耦合、不写同义反复断言、不水平切片；测试只挂在 spec/接口契约这类稳定缝（seam）上，不挂在随时会重构的内部函数上。
> 端到端用例的中间结果断言按 `测试资产纪律.md` §1 落码：断言挂在环节间的契约（落库记录、消息体、返回结构）上；异步环节用条件轮询等待目标状态，不用固定 sleep 猜耗时。

---

## Step 10：链路测试

跨服务流水线测试，确认端到端链路打通。

> **协作面 = solo**：Step 8–10 通常压缩成"给关键路径补几个测试 + 手动跑一遍"；但命中 `测试资产纪律.md` §1 判定的长链路**不压缩**——端到端用例与中间结果断言照做，一个人维护的项目里这类链路同样最难调。
> **协作面 = team**：链路测试是准出的一部分；发布与线上验证参考团队自己的基建手册。
> 若需要形成书面验证/测试/执行报告，统一写入 `docs/report/YYYY-MM-DD-<feature>-<report-type>-report.md`。
> **准出前复核覆盖度台账**：把 `docs/report/测试场景覆盖度.md` 的状态位与实际用例对齐，别留"已覆盖"其实没写用例的假账；本次仍缺素材的场景保持挂账，连同待索要素材清单一并向用户交代。

---

测试全绿后进入 `00-流程总纲.md` §完成与自动合并门收尾。
