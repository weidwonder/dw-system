# 图谱位（graph）

> 加载条件：探测到 `.codegraph/codegraph.db` 时加载。
> 本文按 RFC 2119 解释 MUST / MUST NOT / SHOULD / MAY。
> 图谱位回答的是「**找得到吗**」——本项目已建有本地代码知识图谱索引，结构性检索走它，不靠全仓扫描。

## 1. 与权威位的分工（先读这条）

| | 图谱位（本文） | 权威位（`curated.md`） |
|---|---|---|
| 回答的问题 | **找得到吗**（检索） | **信哪个**（消歧） |
| 给出什么 | **现状代码事实**：符号定义与源码、调用链、影响面 | **权威口径**：card + cite（path#anchor @确认时间） |
| 事实来源 | 索引器扫描当前工作区文件，随文件变更同步 | 人工确认后写入并标注确认时间 |
| 承载物 | codegraph 索引（`.codegraph/codegraph.db`） | `capability-registry.md`，按需递进到 card / scene / probe |

**两者 MUST NOT 互相替代**：

- 图谱位会如实列出 v1 与 v2 两处支付实现，但它**不知道哪个是权威**——判权威 MUST 走 `curated.md`（未启用权威位时直读源码定权威，每条结论给 `文件:行` 出处，见 `core/步骤-1-7-设计与实现.md` Step 2）。
- 权威位的 card 告诉你哪个是权威实现，但它**不保证覆盖每一个符号与调用边**——找调用方、算影响面 SHOULD 走图谱位。
- 两位同时启用时的分工是固定的：**权威判定用 card，结构检索用图谱**。图谱查出的结果与 card 冲突时，以 card 为准，并按 `curated.md` §6 第 4 条提示 owner 补卡。

## 2. 什么时候用图谱位

**先确定怎么查**（不写清这一句，下面的 MUST NOT 就是空转）：codegraph 以**当前 harness 里可见的 codegraph 工具**（MCP 工具，安装器默认接线到项目级）或 **`codegraph` 命令**暴露，二者任一可用即可。**具体子命令与参数以工具自身的说明为准**（`--help` 或工具描述），本文不复述——它是外部工具，版本会变，抄一份在这里只会过期。两条通道都看不到、或调得起来却查不出结果时按 §4 回退。

以下问题 SHOULD 先查图谱，MUST NOT 直接开全仓 grep：

- 「这个函数/类/常量定义在哪、源码长什么样」
- 「谁调用了它、它调用了谁」（正反向调用链）
- 「改这个签名会波及哪些文件」（影响面，用于 spec 的〈既有系统清单〉与替换清单）
- 「这个模块的对外入口有哪些」

图谱位是**检索加速与影响面证据**，不是结论。写进 spec / plan 的每条影响面陈述仍 MUST 指到精确文件路径（`spec写作纪律.md` §1）。

## 3. 图谱位不改变分流默认假设

Triage 与 Lean/完整流程的默认假设方向由**权威位**决定（见 `curated.md` §1）。仅启用图谱位的项目，分流默认假设不变——索引只让"查得快"，不代表"实现有歧义"。

## 4. 图谱不可查时的回退（非硬依赖）

**进入条件**：`.codegraph/codegraph.db` 存在，但出现下列任一情况——

- **通道缺失**：§2 的两条通道都看不到（harness 里没有 codegraph 工具，且 `codegraph` 命令未安装 / 不在 PATH / 调用被工具本身拒绝）。
- **通道可用但查不出结果**：调得起来，却持续查询失败或索引损坏读不出内容。

进入本节后：

1. **MUST NOT 阻断流程。** 索引不可查不是任务失败条件。
2. **MUST 回退到子 agent 重探索外包**（`上下文卫生.md` §2 规则 4）：把"大范围代码探索、全仓检索、多方案对比"这类读得多、结论少的工作交给子 agent，主会话只收结论，不让海量文件内容冲刷主上下文。
3. **MUST NOT 退回无策略的裸 grep。** 裸 grep 指没有收窄目标、没有外包、直接在主会话里全仓扫描并把命中内容读进主上下文——它同时丢掉了检索效率与上下文卫生。子 agent 内部按需使用 grep 是允许的，因为结论才回到主会话。
4. SHOULD 一句话提示用户实际情况后继续干活，MUST NOT 反复提示。提示语按**上面观察到的原因**二选一：通道缺失时说"代码图谱索引存在但没有可用通道（harness 里没有 codegraph 工具、`codegraph` 命令也不可用），重跑安装器或在客户端接上 MCP 服务可恢复"；通道可用但查不出结果时说"代码图谱通道可用但读不出结果，重建索引可恢复"。

同理，索引明显滞后于工作区（刚做过大规模重构、查到的符号已不存在）时，MUST 以工作区源码为准，SHOULD 提示重建索引。

## 5. 边界

codegraph 是**外部工具**，本 skill 只声明"何时用它、它给什么、不可用怎么办"。它的安装、索引方式与命令细节不在本 skill 范围内，由安装器负责保持可用；工具本身的用法以它自己的文档为准。本文 MUST NOT 扩写成 codegraph 使用手册。

## 一句话

图谱位 = 一层随代码变化的现状事实检索面，管"找得到"；管"信哪个"的是权威位，两者不互相替代；索引查不了就外包给子 agent，绝不退回裸 grep。
