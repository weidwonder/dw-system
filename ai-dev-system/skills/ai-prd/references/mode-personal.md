# 个人版外壳（mode-personal）

> 一个人的轻量项目。默认走最短路径，能省则省，但**非目标 + 可判定验收**两条硬纪律不能省。

## 裁剪原则

- **分流**默认 lite-issue 或 change 模板；只有自己都记不住的复杂改动才用完整 change。
- **现状**靠口述 + AI 就模糊处追问；无 `ctx` 也要显式区分"现状事实"与"我想要的样子"。
- **界面样式是例外，不靠口述**：涉及 UI 时先自查项目里的设计 token / 组件库 / 同类现有页面（`UI原型纪律.md` §1），查不到才向用户要截图或链接。
- **批 C/D** 只写关键业务行为、主要特殊场景、够勾验的验收；运营度量精简到"我怎么知道业务结果达成了"。
- 不强制评审、不强制 index.md（有 index.md 时才要求分层）。
- **frontmatter 的 `lifecycle` 不裁剪**：个人项目一样会攒下过期 PRD，而且没有同事提醒你哪份已经不作数了。新建 PRD 带 `lifecycle: active`，归并后改 `merged` 并加头注——一行的事，省的是几个月后被自己的旧文档带偏。

## 什么时候升级

任一为真就升级到完整 change 流程：改变智能能力结果、改变权限或敏感信息保护、影响多个业务环节或不可逆、改变对外承诺。

## 收尾

写进 `docs/spec/`。若接着要做技术设计，直接把这份 PRD 喂给 `ai-dev-workflow`。
