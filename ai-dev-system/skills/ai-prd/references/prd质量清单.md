# PRD 质量清单（成稿前自检 gate）

> 组稿后逐条自检；任一"否"→ 就该项再批量追问或补写，不过 gate 不交付。

## 完备性（对照骨架）

- [ ] 有**一句话结论**：一句话说清做什么、做完的标志。
- [ ] 有**背景**：为什么现在做。
- [ ] 有**目标**：尽量可衡量。
- [ ] 有**非目标**：非空、且具体（见纪律 §1）。
- [ ] 有**现状/当前逻辑**：团队版每条带 cite。
- [ ] brownfield：有**改动范围** + **不改的线上逻辑**。
- [ ] 有**详细行为/字段/规则**：关键项表格化。
- [ ] 有**边界 case 与冲突**：并发/迟到/依赖/失败/过期等已覆盖。
- [ ] 有**验收标准**：字段/行为/场景三分，逐条可判定。
- [ ] 团队版：有**埋点与看板**，关键指标带公式与粒度。
- [ ] 有**风险与兜底**：每条风险配兜底。
- [ ] 有**流程图**（复杂交互时）与 **changelog**。

## 质量（对照纪律）

- [ ] 无占位符：`【】`/TBD/TODO 已清零，或转为显式"开放问题"。
- [ ] 验收无不可判定表述（"提升体验"等）；用 RFC2119。
- [ ] 现状与意图**分区清晰**，未把愿景写成现状。
- [ ] 非目标与"不改的线上逻辑"具体到可核对。
- [ ] 术语/字段命名前后一致。

## 落位（doc 治理）

- [ ] 写入 `docs/`（变更 PRD → `<name>-PRD-YYYYMMDD.md`；整品 → `docs/REQUIREMENTS.md`）。
- [ ] 团队版：`docs/index.md` 已同步新增条目。
- [ ] 已提示可接 `ai-dev-workflow` 做 Overview / 技术 Spec。
- [ ] 变更 PRD：已注明收尾动作——实现验收后归并回整品 PRD 并转归档（见 `00-prd生成流程.md` §PRD 生命周期）。
