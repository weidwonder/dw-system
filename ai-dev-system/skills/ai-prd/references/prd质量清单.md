# PRD 质量清单（成稿前自检 gate）

> 组稿后逐条自检；任一"否"→ 就该项再批量追问或补写，不过 gate 不交付。

## 完备性（对照骨架）

- [ ] 有**一句话结论**：一句话说清做什么、做完的标志。
- [ ] 有**背景**：为什么现在做。
- [ ] 有**目标**：尽量可衡量。
- [ ] 有**非目标**：非空、且具体（见纪律 §1）。
- [ ] 有**现状/当前逻辑**：团队版每条带 cite。
- [ ] 既有业务变更：有**改动范围** + **不改的现有业务**。
- [ ] 有**详细业务行为与信息要求**：关键项表格化。
- [ ] 有**特殊场景与冲突**：同时操作/信息迟到/前置条件/失败/过期等已覆盖。
- [ ] 有**验收标准**：业务信息/流程规则/场景三分，逐条可判定。
- [ ] 团队版：有**运营度量与看板**，关键指标带公式与粒度。
- [ ] 有**风险与兜底**：每条风险配兜底。
- [ ] 有**流程图**（复杂交互时）与 **changelog**（变更/轻量 PRD；整品 PRD 以 frontmatter 的 date/status 追踪，无 changelog 节则本项跳过）。

## 非功能 / 安全 / 上线（按适用，不适用要显式写"不适用+原因"，不能默默留空）

- [ ] **NFR 可度量**：涉及的性能（P50/P95/P99、吞吐）、可靠性、离线/弱网、无障碍、可观测等，写成可度量目标而非"要快要稳"。
- [ ] **数据 / 隐私 / 安全 / 合规**：涉及的敏感数据清单、采集/使用授权（consent）、留存期、是否用于训练（未成年数据默认不得）、鉴权与越权边界。
- [ ] **Rollout / 回滚 / 监控**：灰度或分批发布方式、回滚条件与动作、上线后监控什么指标、事故 owner。
- [ ] **AI 行为（含 AI 时）**：有 **AI Capability Card**——自主级别、允许/禁止行为、置信度与降级策略、**评测（eval）准出标准**都写清；高风险能力把 eval 作为上线阻断项；重要 AI 行为**没有藏进普通功能需求**里。

## 质量（对照纪律）

- [ ] 无占位符：`【】`/TBD/TODO 已清零，或转为显式"开放问题"。
- [ ] 验收无不可判定表述（"提升体验"等）；用 RFC2119。
- [ ] 现状与意图**分区清晰**，未把愿景写成现状。
- [ ] 非目标与"不改的现有业务"具体到可核对。
- [ ] 业务术语和信息项命名前后一致。
- [ ] 对话与成稿只用业务语言，不含需要用户理解的程序实现和技术选型。

## 落位（doc 治理）

- [ ] 落盘位置正确（变更 PRD → `docs/spec/<name>-PRD-YYYYMMDD.md`；整品 → `docs/REQUIREMENTS.md`，放 `docs/` 根）。
- [ ] 团队版：`docs/index.md` 已同步新增条目。
- [ ] 已提示可接 `ai-dev-workflow` 做 Overview / 技术 Spec。
- [ ] 变更 PRD：已注明收尾动作——实现验收后归并回整品 PRD 并转归档（见 `00-prd生成流程.md` §PRD 生命周期）。
