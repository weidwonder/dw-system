# 提问库（供批量组批）

> 按批取用，一次抛一批。按具体需求增删；已能从材料判定的不要问。问法保持"一次问全 + 给业务例子降低回答成本"，禁止要求用户理解程序实现。
> **每问尽量附一个推荐答案（带一句理由）**：让用户在"改一下推荐"而非"从零作答"上表态，进一步降轮次；决策权仍在用户，推荐只是草案。推荐答案同样只用业务语言。

## 批 A — 立项

1. 一句话说清这次要做什么？做完的标志是什么？
2. 为什么现在做？触发它的问题 / 机会 / 事故是什么？
3. 产品目标有哪些？尽量可衡量（如"XX 成功率 ≥ N%"）。
4. **明确不做什么 / 不改什么？**（逼非目标；给例子："不改变审批职责、不扩大使用人群、不影响进行中的历史业务"）
5. （整品追加）目标用户是谁？核心用户旅程一句话？北极星指标？

## 批 B — 现状与边界

1. 现在这项业务由哪些角色参与，经过哪些环节，各方如何协作，需要记录哪些业务信息？
2. 本次改动范围：新增什么、改造什么？
3. 哪些线上逻辑本次**明确不动**？（brownfield 护栏）
4. （团队版由 ctx 预填后确认）我基于 `ctx` 查到的现状是【…带 cite】，与实际是否一致？哪里要纠偏？

## 批 C — 细节

1. 各角色在什么场景下做什么？何时开始、得到什么结果、按什么顺序和优先规则处理？
2. 业务需要新增或调整哪些信息项？每项信息由谁提供、代表什么、谁可以查看或修改？
3. **特殊场景与冲突**：多人或多次同时操作、信息迟到、前置条件不满足、处理失败、业务过期、跨阶段继续——各自期望怎么处理？
4. （含智能能力）会使用哪些业务信息、给出什么结果、何时转人工或拒绝处理、效果怎么衡量？

## 批 D — 准出

1. 怎么算验收通过？分三类给判据：业务信息、流程与规则、端到端场景（给场景→给预期）。
2. 上线后要能回答哪些问题？关键指标怎么算（公式 + 粒度）？
3. 主要风险有哪些？每条的兜底是什么？

## 追问触发（何时再批量追问，而非直接下一步）

- 非目标为空，或目标不可衡量 → 追问批 A 这两点。
- 现状里出现"应该/希望/打算"等意图词混入事实 → 追问区分现状与目标。
- 验收项出现"提升体验/更稳定"等不可判定表述 → 追问可勾验判据。
- 关键场景（失败/信息迟到/同时操作）无明确处理 → 追问期望处理。
