# 业务域卡 — dw-system › 标记块与旧版迁移

## 职责
维护目标项目两个入口文件（`CLAUDE.md` / `AGENTS.md`）里 `dw-workflow` 标记块的字段模型、正文组装与两入口收敛，并把体系更名前旧安装留下的残留迁到现行名字。

## 权威实现与对外接口

| 能力 / 入口 | 权威实现（cite） | 约束 |
|---|---|---|
| 标记块起止 | `install.mjs#WORKFLOW_MODE_START` | 块的定位只认这对起止注释，不认正文形态。 |
| 首次写块归谁 | `install.mjs#main`（其中 `workflowSettings` 为空就不写块） | 安装器**只在已有块时**同步：首次写块由 skill 的初始化做，安装器只负责迁移、规范化、把一个入口的块补齐到另一个入口。 |
| 字段模型 | `install.mjs#WORKFLOW_FIELDS`、`install.mjs#WORKFLOW_DEFAULT_WORKTREE_DIR` | 闭集三个字段：`collaboration` ∈ solo\|team、`merge-gate` ∈ direct\|pr、`worktree-dir` 非空。代码事实层与代码图谱不设字段：前者是必备资产，后者由 skill 每次运行探测。 |
| 解析 | `install.mjs#parseWorkflowBlock` | 已知字段的值非法 → 报错中止，MUST NOT 猜；块里只有旧 `mode` 也算读到了已知字段。单个入口的块读不出任何已知字段返回 null，交给另一个入口；存在标记块而两个入口都读不出时，`install.mjs#main` 报错中止。 |
| 旧 `mode` 的读取 | `install.mjs#getWorkflowMode` | 只认 `personal` / `team` 两个值；值非法返回 null，让另一个入口的有效块接管。 |
| 旧值映射 | `install.mjs#resolveWorkflowSettings` | `mode` 只在缺 `collaboration` 时用来推协作面（team → team，其余 → solo），MUST NOT 推出别的任何东西；缺 `merge-gate` 时由协作面推（team → pr，solo → direct）。任一字段是补出来的、或旧块还带 `mode`，就走改写，改写前打印「旧 / 新」对照（`--dry-run` 也打印）。 |
| 正文组装 | `install.mjs#buildWorkflowBlock`、`install.mjs#applyWorkflowFields` | 正文 = `dw-system/skills/dw-workflow/assets/config-snippets/base.md#dw-workflow:start` 与 `collab-<协作面>.md` 各自标记块内层的拼接，再全局替换三个字段值并删掉所有 `mode="…"`。安装源里没有片段时：新格式的块原样保留正文以保幂等，旧块只写规范化字段行。 |
| 写后核对 | `install.mjs#assertWorkflowFieldsKept` | 写入后重新解析，三个字段与写入前逐字相等，否则报错。 |
| 两入口收敛 | `install.mjs#main` | 两个入口状态不一致时一律以 `CLAUDE.md` 为准；`CLAUDE.md` 的块读不出时由 `AGENTS.md` 的有效块接管。skill 初始化同步两个入口时用同一套判据（`dw-system/skills/dw-workflow/references/init-初始化.md#各写一套`），两边 MUST NOT 各写一套。 |
| skill 落后于配置的告警 | `install.mjs#WORKFLOW_FIELD_MIN_VERSION` | 块已是新格式而已装版本戳低于该值时显式警告，并提示每个协作者各自重跑。配置入库而 skill 不入库，这种落后在多人项目里是常态，不是异常。 |
| 旧名字登记表 | `install.mjs#LEGACY` | 旧名字（旧 skill 目录名、旧版本戳、三对旧标记、旧 docs 记号、旧 `ctx` 所在 skill）的**唯一**登记处；旧名字 MUST NOT 出现在本表之外，由 `test/installer-legacy-upgrade.test.mjs` 逐字核对。 |
| 残留清单 | `install.mjs#legacyResidue` | 只读：列出旧 skill 目录、旧戳、三处旧标记块，供计划输出与清理共用同一份清单。 |
| 残留清理 | `install.mjs#removeLegacyInstall` | 只删两个 skills 目录下名字**逐字等于**登记项的条目；符号链接只删链接本身；删前核对父目录前缀。同目录的其它条目不碰。 |
| 旧块替换 | `install.mjs#replaceLegacyBlock` | 一次合成最终文本：只有旧块 → 新块落在旧块原位；新旧并存 → 删旧、更新新。旧 `.gitignore` 块里的 docs 入库决定原样带过去，不再发问。 |

## 陷阱项

> 每行一条"这样写会悄悄坏掉"或"这个名字不该再用"。

- `mode` 字段（旧块的唯一字段，取值 `personal` / `team`）已废弃 — 新块 MUST NOT 再写出它；读它只为推协作面，改用 `collaboration` / `merge-gate` / `worktree-dir` 三个字段。
- `ai-dev-workflow`、`ai-prd`（旧 skill 目录名）已废弃 — 现行 skill 名见 `dw-system/skills/`；旧名字只许留在 `LEGACY` 登记表里。
- `ai-dev-system.version`（旧版本戳）已废弃 — 改用 `dw-system.version`。
- 值非法时按默认值继续 — 使用者写错的配置被悄悄替换成另一种协作方式；MUST 报错中止。
- 在没有标记块的项目里由安装器首次写块 — 协作面要问拍板人，这一问只在 skill 的初始化里；安装器只同步已有的块。
- 安装源缺片段时把旧块的正文原样留下 — 旧外壳正文含已废止的说法；旧块此时只写规范化字段行。
- 清理残留时按前缀或通配匹配目录名 — 会删到使用者自己的同前缀 skill；只许逐字等于登记项。
- 分两步替换旧块（先删旧块、再合并新块） — 只有旧块时新块会被追加到文件末尾而不是落在旧块原位；MUST 一次合成最终文本，且 MUST NOT 分两次写文件。
