# 业务域卡 — dw-system › 原型工具

## 职责
`dw-prd` 产出的 UI 原型的唯一容器与唯一工具：`preview.mjs` 七条子命令覆盖建原型、加屏、填插槽、取界面、取批注、自检、预览写回；`ui-prototype-framework/` 是容器六个固定实现区的源码。产物恒为单文件、零外链、可离线打开；零第三方依赖。

## 陷阱项

> 每行一条"这样写会悄悄坏掉"或"这个不该再用"。

- `--drop-anchors` 已废弃 — 传入即报错退出 2；改用 `--agreed --agreed-plan`。
- `--anno-right` 已废弃 — 传入即报错退出 2；屏注解区一律挂在该屏下方，去掉参数重跑即可。
- 手工编辑原型文件或批注数据块 — 会抹掉批注锚点、绕开区间与等值保障；批注块的写入方只有页面工具栏与放行路径上的 `slot` 两个。
- 引用 `slot.re` 而该插槽没有 `re` 字段 — JS 对 `undefined` 正则的容忍让 `match` 给空匹配、`replace` 当字面串，命令零改动却打印成功、退出 0。删改 `SLOTS` 的字段时 MUST 全文搜它的引用。
- 全文查找 `id="anno-data"` 来定位批注块 — 片段里夹带一个假块时，放行数据写进假块、真块原样不动，命令照常打印放行清单并退出 0。
- 用 `process.exit()` 终止 — 管道下输出被截断而退出码正常；抛 `Abort`。
- 让页面自己算磁盘内容的哈希来判冲突 — 等于立一条"服务端按字节、客户端按字符串，两者必须逐字节相同"的隐式契约；409 响应 MUST 直接带 `{version, html}`。
- 把唯一临时文件名当成并发安全 — 它只消除 ENOENT 崩溃，两条命令并发改同一份原型仍是后写覆盖先写；串行执行。
- `check` 收集 class 定义来源时漏掉 `ANNO-FRAMEWORK:CSS` 区 — 屏注解区的按钮用批注框架私有类，漏掉会把工具自己生成的按钮报成"没有样式定义"。
- 框架 UI 借用 `components.css` 里的 `.btn` / `.card-content` — 外观层默认不装配，借用的那一刻框架 UI 在默认路径下完全没有样式，而页面照常打开、零报错；初始 `innerHTML` 与运行时 `className` 赋值两条路径都算。
- 框架自己覆盖带 `!important` 的属性时不带 `!important`（如 `[data-anno-hidden] .anno-pin`）— 压不过自己，"隐藏批注"整个失效。
- 给框架 UI 里的隐藏元素逐个补 `display:none` — 必然漏；靠那条 `[hidden]` 通用规则兜住。
- 把图钉偏移改成负值（元素外侧）— 任何 `overflow` 祖先都会把它整枚裁掉。
- 渲染弹窗的函数绑定自己没渲染的 `data-role` — `null.onclick` 抛 TypeError 让函数整个中断，表现只是"按钮点了没反应"。
- 把 `window.setScreenState` 扩成认识按钮名的函数 — 声明式 hook 失去意义；用其它方式改 DOM 状态则序列化还原不掉，写回时状态被烘进文件且零报错。
- 往框架里引入外部资源，SVG data URI 也算 — `xmlns` 带进 `http://` 串，直接挂掉零外链自检；`icons.svg` 是不含 `xmlns` 的 sprite 片段，拾取光标用跟随鼠标的 DOM 元素而不是 `cursor: url(...)`。
- 往容器 `ui-prototype.html` 的固定区里写正文 — 装配后同一段内容出现两次而页面照常打开。
- 用写死像素的 `max-height` 做滚动区 — 内容区缩成一条，而页面照常打开、`check` 看不出；用 `.fill` + `.scroll-y`。
- 指望改框架源码能修好已生成的原型 — 框架在 `init` 时装配进产物，只能重建，而重建会清空批注块（`docs/TODO.md` 技术欠账）。
