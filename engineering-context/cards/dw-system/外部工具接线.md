# 业务域卡 — dw-system › 外部工具接线

## 职责
主安装完成之后的三段接线：把外部伴生 skill 装到用户级目录并保持最新、把随 skill 落盘的 `ctx` 链接成全局命令、安装或升级 codegraph 并接线建索引。三段的任何失败都只降级为警告，不影响已完成的主安装。

## 权威实现与对外接口

| 能力 / 入口 | 权威实现（cite） | 约束 |
|---|---|---|
| 三段的共同语义 | `install.mjs#syncCompanions`、`install.mjs#syncCtx`、`install.mjs#syncCodegraph` | 都在主安装完成后执行；任何失败只降级为警告；`--dry-run` 下只做只读探测并预告动作。"装完没报错"因此不等于三段都成功，要看各段自己的结果行。 |
| 外部子进程 | `install.mjs#runTool` | 所有外部命令经它启动：Windows 走 shell（全局命令多是 `.cmd` shim）；stdin 一律 `ignore`——codegraph 按 `process.stdin.isTTY` 决定要不要发问，关掉 stdin 才锁定非交互分支，安装器不会被子命令挂住。 |
| 伴生 skill 清单 | `install.mjs#COMPANION_SKILLS` | 仓库地址、`ref`、`subdir`、`why` 的权威定义处。本体系不收录伴生 skill 的内容，只负责装上并保持新。失败文案按各条目的 `why` 生成，`why` 写空会打印一句没有内容的提示。 |
| 伴生 skill 的安装位置 | `install.mjs#userSkillDirs` | 装到用户级 `~/.claude/skills/` 与 `~/.codex/skills/`（全局安装用同一对目录），跨项目共享一份，不进目标项目、不写目标项目 `.gitignore`。两侧不对称：`.agents/` 只是 Codex 的项目级目录，没有用户级形态。 |
| 拉取与校验 | `install.mjs#fetchCompanion` | 浅克隆到临时目录，校验 `<subdir>/SKILL.md` 存在后才读版本；找不到即该条目失败，降级为警告。 |
| 版本比较 | `install.mjs#readSkillMetaVersion`、`install.mjs#companionShouldUpdate` | 版本取 `SKILL.md` frontmatter 的 `metadata.version`，远端更新才覆盖；远端版本判不出时不覆盖已有安装。guard 分支与普通分支共用 `companionShouldUpdate` 这一个判据。 |
| 无版本号的伴生 skill | `install.mjs#companionContentSame` | 两边都没有版本号时按 `SKILL.md` 字节相等判，相同即跳过。没有这条，这类 skill 每次安装都被重写，幂等与 `--dry-run` 两条承诺同时失效。 |
| 不自动覆盖的目标 | `install.mjs#companionGuardReason` | 目标是 symlink 或 git 工作区时只报告版本差异，不覆盖。 |
| 伴生相关 CLI 选项 | `install.mjs#parseArgs` | `--no-companions`（同义 `--no-agentic`）跳过整段；`--companion-repo=<name>=<url>` 覆盖某一个的来源，`<name>` 不在清单内报错中止并列出合法值。 |
| `ctx` 全局链接 | `install.mjs#CTX`、`install.mjs#ctxPackageDir` | 入参是 Claude Code 侧 skills 目录：项目级在 `<目标>/.claude/skills/dw-code-facts/scripts/ctx`、全局在 `~/.claude/skills/dw-code-facts/scripts/ctx` 下 `npm link`；`.agents/` 那份是相同副本，两份都 link 只会互相覆盖同一个全局命令。`--no-ctx-link` 跳过整段。 |
| 链接成功的判据 | `install.mjs#detectCtx` | link 之后实跑 `ctx --help` 并匹配 `CTX.signature` 才报成功；`npm link` 退出 0 只说明 shim 写出去了。PATH 上已有别人的同名 `ctx` → 不 link、不覆盖；link 完仍不在 PATH → 如实报告。 |
| 链接失败的处置 | `install.mjs#ctxFallbackHint` | 一律降级为警告并打印 `node <路径>/src/cli.js` 兜底调用方式。没有这层，`which ctx` 为空会被 agent 读成"代码事实层不可用"而退回裸 grep。 |
| EEXIST 处置 | `install.mjs#linkCtxCli`、`install.mjs#parseEexistPath`、`install.mjs#globalCtxIsOurs` | `npm link` 的输出 MUST 捕获（失败时经 `install.mjs#printNpmOutput` 回显原文）。读出冲突路径后先判归属：PATH 上那个签名匹配，或全局目录下的 `ctx` 是本体系留下的（符号链接字符串含 `dw-code-facts` 或 `LEGACY.ctxSkills` 里的名字——只读链接字符串、不解引用；或入口脚本含签名串）——确认了才 `npm link --force`；判不出归属就不动，打印文件路径、`npm rm -g ctx` 与 `--no-ctx-link`。 |
| 全局 `ctx` 指向哪份代码 | `install.mjs#syncCtx` | 指向**最后一次安装**的那份副本（某个项目里的，或全局安装的用户级那份）；`ctx` 按运行目录找 `engineering-context/`，所以一份命令服务所有项目。那个项目被删后命令失效，重跑安装器恢复。 |
| codegraph 安装与升级 | `install.mjs#ensureCodegraphCli`、`install.mjs#checkCodegraphUpdate`、`install.mjs#installCodegraphViaNpm` | 未装 → npm 全局安装（包名在 `install.mjs#CODEGRAPH`）；已装 → 用它自己的 `upgrade`，`upgrade --check` 报已最新则跳过；没有 `upgrade` 子命令才退回 npm 装 latest；检测失败就盲升，结果以升级前后的版本号为准报告。 |
| codegraph 接线 | `install.mjs#wireCodegraphAgents` | `codegraph install --target=auto --location=<local\|global> --yes`，默认项目级；`--codegraph-location=global` 改范围。全局安装固定 `global`、`syncCodegraph` 的目标传 `null`：不探测 `.codegraph/`、不建索引，只提示到项目根 `codegraph init`。Codex CLI 没有项目级 MCP 配置，项目级接线必然跳过它，安装器显式打印手动全局接线命令。 |
| codegraph 建索引 | `install.mjs#buildCodegraphIndex` | `.codegraph/` 不存在才 `codegraph init`；以 `.codegraph/codegraph.db` 是否存在判定建成，缺了补跑 `codegraph index`。超时 `install.mjs#CODEGRAPH_CMD_TIMEOUT_MS` / `install.mjs#CODEGRAPH_INDEX_TIMEOUT_MS`。 |

## 陷阱项

> 每行一条"这样写会悄悄坏掉"或"这个名字不该再用"。

- `--agentic-repo=<url>` 已移除、不留别名 — 传入落进未知参数路径、退出码 2，并额外打印一行迁移指路；改用 `--companion-repo=agentic-principle=<url>`。
- `~/.agents/skills/` 里的伴生 skill 副本是陈旧的中间产物 — 那不是用户级安装位置；安装器经 `legacyCompanionDirs` 只报告并给删除命令，不自动删。
- 按伴生 skill 的 `name` 推它的 `subdir` — `skill-principle` 的本体在仓库的 `skill/` 子目录，仓库根没有 `SKILL.md`；写错的表现是每次安装都警告"找不到 `<subdir>/SKILL.md`"而主安装照常成功，很容易被忽略。
- 假定每个伴生 skill 都有 `metadata.version` — 它不是伴生 skill 的通用契约，本体系无权要求上游加；新增条目前 MUST 先确认有没有版本字段，没有就落进内容比对分支。
- 伴生 skill 的仓库地址在 `COMPANION_SKILLS` 之外还有手抄副本：`dw-system/skills/dw-workflow/references/AI-LLM-overlay.md` 的手动 clone 指引、`dw-system/migrations/1.6.0.md` — 改地址只改常量时，这两处继续指向旧仓库且不报错；MUST 逐处核对。
- 用 `npm link` 的退出码当 `ctx` 链接成功的判据 — 退出 0 时命令仍可能不在 PATH 上，或 PATH 上排在前面的是别人的同名命令。
- 判不出归属就 `npm link --force` — 会悄悄顶掉使用者自己的同名 `ctx` 命令。
- 判归属时解引用全局目录下的符号链接 — 目标项目可能已被删或改名（这正是 EEXIST 的成因之一），解引用失败会把自己留下的链接误判成"不是本体系的"；只读链接字符串。
- 对已装的 codegraph 盲目 `npm install -g` — 它认得 bundle / npm / npx 三种装法，盲装会留下抢 PATH 的第二份；已装时 MUST 走它自己的 `upgrade`。
- 让外部子命令继承 stdin — codegraph 在 TTY 下会发问，安装器被挂住。
